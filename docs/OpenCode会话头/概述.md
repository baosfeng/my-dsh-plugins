# OpenCode 会话头（dsh-my-opencode-session-header）

> 模块文档：`docs/OpenCode会话头/` — 源码：`plugins/dsh-my-opencode-session-header/`

**dsh-my-opencode-session-header** 是 DSH **纯 server 插件**（issue #183，零运行时依赖）：让走 `opencode` / `opencode-go` 路由的推理请求自动携带 `x-opencode-session`（该会话的**稳定 id**），修复 OpenCode Go 托管推理网关（`https://opencode.ai/zen/go`）自 2026-09-05 起对缺失该头的请求返回 `400 MissingSessionID` 的问题。头值**按会话唯一**，同会话跨轮次 / 压缩 / 重试 / 重启不变；其它 provider 出站请求完全不变。

## 问题背景

网关要求每个推理请求带 `x-opencode-session`（稳定的 per-conversation id），否则 400。DSH 侧现状（已读源码确认，详见 [issue #183](https://github.com/baosfeng/my-dsh-plugins/issues/183)）：

- `@deepseek-ai/dsh-llm-pi-ai` 的 `requestHeaders()` 只合并 profile 静态 headers + attribution headers，`streamSimple` 只把 `options.sessionId` 透传给 pi-ai SDK；
- pi-ai 的 openai-completions 路径只发 `x-client-request-id` / `x-session-affinity` / `session_id`，**从不发** `x-opencode-session`；
- 官方适配器也不覆盖第三方 provider。

因此 DSH 默认模型走 `opencode-go`（openai-completions，无 `sessionAffinityFormat`）时**必然 400**。**纯配置不可行**——两条路都被堵死：

1. `dsh-llm-pi-ai` 的 `headers` 是静态字符串字典（无插值），无法填"当前会话 id"；
2. pi-ai 的 session 头名写死，DSH 把 `sessionAffinityFormat` / `sendSessionAffinityHeaders` 标为 withhold（写进 settings 直接报错）。

**已实测**（本机真实 key 直连网关）：无头 → `400 MissingSessionID`；`x-opencode-session: <uuid>` → `200 OK`；静态字符串值 → `200 OK`（网关不校验 UUID 形态）。

## 工作机制

唯一可用拦截点是 `llm/stream` waterfall + `globalThis.fetch` 补丁：

```
DSH agent loop
  └─ ctx.waterfall(ctx, 'llm/stream', options, () => adapterStream(...))
       options: { provider: 'opencode-go', sessionId: '<会话 id>', … }
       ↓ 插件 handler（同步函数，绝不 async）：`plugins/dsh-my-opencode-session-header/src/index.ts` `handleStream()`
       ① 同步取到内层流（next()）；
       ② 用 AsyncLocalStorage 存 { provider, 会话头值 }（`src/context.ts`）
       ③ 返回包装流：每次 next()/return() 都在 als.run(store, …) 内执行
          （pi-ai 的 Models.streamSimple() 是惰性的，真正的 HTTP 发生在消费流时）
       ↓ 消费流 → pi-ai → openai / anthropic SDK
   SDK 每次请求解析 globalThis.fetch
       ↓ 插件安装的单层 fetch 补丁（`src/fetch-patch.ts`）
       ④ 路由判定（AND）：provider ∈ 白名单 且 目标 host 命中
          任一不满足 / 无会话上下文 / 任何异常 → 原样调用原 fetch（零副作用）
```

要点：

- **不改 `options`**（可能被冻结），只包装流；handler 必须同步（async 会让 waterfall 返回 Promise，破坏下游 `yield*` 委托）。
- **会话头值确定性**：`src/session-value.ts` 纯函数（无状态无随机）——`valueMode: uuid` 提取会话 id 中的裸 UUID（无则回退原串），`raw` 用原始会话 id。
- **幂等**：请求里已有同名头时默认**不覆盖**（`src/headers.ts` 覆盖 `Headers` 实例 / 数组 / 普通对象三种形态，大小写不敏感），`override: true` 才覆盖；写入不就地修改调用方对象。
- **退化安全**：无 ALS 上下文或会话 id 为空时不注入（首次 warn 一次，之后静默）；内部任何异常被吞掉并降级为原行为，**绝不影响推理请求**。
- **卸载干净**：`disposer` 仅在"当前 `globalThis.fetch` 仍是我们装的那个"时还原；本层被压在下面（重复 apply / 乱序卸载）时从链上摘除自己，不误还原他人的 patch。
- 会话标题生成、压缩摘要等**辅助 LLM 调用**同样经过 `llm/stream`，也会带上同一会话的会话头。

## 业务场景映射

| 业务关键词                         | 入口                                                                                 | 说明                                                                                   |
| ---------------------------------- | ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------- |
| OpenCode Go 400 / MissingSessionID | `plugins/dsh-my-opencode-session-header/src/index.ts` `apply()`                      | 注册 `llm/stream` 监听 + 安装 fetch 补丁，命中即注入会话头                             |
| 会话头注入 / x-opencode-session    | `plugins/dsh-my-opencode-session-header/src/fetch-patch.ts` `planInjection()`        | provider 白名单 AND 主机命中（含子域）→ 注入；否则原样调用原 fetch                     |
| 会话上下文 / AsyncLocalStorage     | `plugins/dsh-my-opencode-session-header/src/context.ts` `wrapStreamWithContext()`    | 包装推理流，每次 `next()`/`return()` 在 ALS 上下文内执行（适配惰性发请求）             |
| 头值稳定性 / 会话唯一              | `plugins/dsh-my-opencode-session-header/src/session-value.ts` `sessionValueOf()`     | `uuid` 提取裸 UUID（无则回退原串）/ `raw` 原始会话 id，纯函数确定性                    |
| 已有头不覆盖 / 三形态归一化        | `plugins/dsh-my-opencode-session-header/src/headers.ts` `hasHeader()`/`withHeader()` | `Headers` 实例 / 数组 / 普通对象，大小写不敏感，不改动入参                             |
| 配置校验 / 非法值启动即失败        | `plugins/dsh-my-opencode-session-header/src/config.ts` `resolveConfig()`             | 空数组 / 非法 host / 非法头名 / 非法 valueMode 抛 `[opencode-session-header]` 前缀错误 |

## 配置项

| 配置项       | 默认值                        | 说明                                                                  |
| ------------ | ----------------------------- | --------------------------------------------------------------------- |
| `enabled`    | `true`                        | 总开关（`false` 不注册监听、不装 fetch 补丁）                         |
| `providers`  | `["opencode", "opencode-go"]` | provider 路由白名单（空数组 / 非法值启动即报错）                      |
| `hosts`      | `["opencode.ai"]`             | 目标主机白名单，自动含子域（`zen.opencode.ai` 命中 `opencode.ai`）    |
| `headerName` | `"x-opencode-session"`        | 注入的请求头名                                                        |
| `valueMode`  | `"uuid"`                      | `uuid` = 提取会话 id 中的裸 UUID（无则回退原串）；`raw` = 原始会话 id |
| `override`   | `false`                       | 已有同名头时是否覆盖                                                  |

配置示例（profile 的 `cordis.patch.yml`）：

```yaml
- id: opencode-session-header
  config:
    enabled: true
    providers: ['opencode', 'opencode-go']
    hosts: ['opencode.ai']
    valueMode: uuid
    # override: true   # 仅当确有需要覆盖已有同名头时才开启
```

## 安装与验证

安装（`link:` 本地路径方式见 [插件 README](../../plugins/dsh-my-opencode-session-header/README.md)）：

```bash
dsh plugin --profile web add dsh-my-opencode-session-header
```

> **包名说明**：本仓库插件包名为 `dsh-my-opencode-session-header`，与第三方包 `dsh-opencode-session-header`（npm 用户 `beihaizb`，仓库 `github.com/beihzb/dsh-opencode-session-header`，功能相似但**不同源**）明确区分；[issue #183](https://github.com/baosfeng/my-dsh-plugins/issues/183) 正文里的包名是改名前的旧名。

⚠️ **安装后必须完全重启 `dsh`（Web 服务）才生效**：插件在启动时注册 `llm/stream` 监听并安装 `globalThis.fetch` 补丁，仅刷新浏览器页面不生效。

**1. 启动日志（必须出现原文）**：

```
[opencode-session-header] active for providers [opencode, opencode-go] with valueMode uuid
```

没有这一行说明插件没挂载（检查 `dsh plugin list` / profile 的 `cordis.patch.yml`），或配置校验失败（非法配置启动时报 `[opencode-session-header] config.xxx …`）。

**2. 不依赖抓包的自证**：

1. 确认上一节启动日志出现；
2. 确认 `~/.dsh/settings.yaml` 里的**静态** `x-opencode-session` 已删除（见「已知限界」互斥一节）；
3. 新开一个走 opencode-go 路由的会话，随便发一条消息 → **正常回复、不再 `400 MissingSessionID`**；
4. 再开第二个会话发消息，同样正常 → 不同会话各自携带自己的会话 id（若两会话互相干扰/串上下文，说明仍在用静态头）。

**3. 带证据的确认（可选）**：HTTPS 下 `tcpdump` 看不到明文头，要看实际发出的值可用两条路——临时把 `llm-pi-ai.providers.opencode-go.baseURL` 指向本机记录器（README 提供 20 行 `node:http` 探针脚本），或让请求经 MITM 代理（mitmproxy / Charles）。判读标准：同会话多次请求值**完全相同**、换会话值**不同**、`valueMode: uuid` 时是裸 UUID。

## 已知限界

- 只拦截 `globalThis.fetch`：若某 provider 的 `transport` 走 websocket 或绕过 fetch 的原生客户端，本插件不注入（opencode-go 走 HTTPS fetch，不受影响）。
- 只在 `llm/stream` 上下文内注入：DSH 里其它（非推理）的 fetch 调用不会被加头。
- **与静态 `headers` 配置互斥**：若 `settings.yaml` 里给 opencode-go 配了写死的 `x-opencode-session`，静态值会一直在请求里出现，而本插件默认 `override: false` 不覆盖 → 插件等于没生效，且静态值是**所有会话共用的固定值**（网关会把不同会话折叠进同一亲和桶，提示词缓存命中率下降）。需要删除静态项，或改用 `override: true` 让插件接管。
- `valueMode: uuid` 在会话 id 不含 UUID 时回退为原始会话 id 字符串（仍确定性、会话间唯一）。
