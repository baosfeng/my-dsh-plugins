# OpenCode 会话头（dsh-my-opencode-session-header）

> 源码：`plugins/dsh-my-opencode-session-header/` · [插件 README](../../plugins/dsh-my-opencode-session-header/README.md) · [文档索引](../索引.md)

## 功能

让走 `opencode` / `opencode-go` 路由的推理请求自动携带 `x-opencode-session` 头（该会话的稳定 id），修复 OpenCode 托管推理网关对缺失该头的请求返回 `400 MissingSessionID`；头值按会话唯一，同会话跨轮次 / 压缩 / 重试 / 重启不变，其它 provider 的出站请求完全不受影响。

## 安装

```bash
dsh plugin --profile web add dsh-my-opencode-session-header
```

安装后**必须完整重启 `dsh` Web 服务**才生效（仅刷新浏览器无效），启动日志会打印生效的 provider 与取值模式。

## 关键配置

| 配置键       | 作用                                                                |
| ------------ | ------------------------------------------------------------------- |
| `enabled`    | 总开关，`false` 时不注册监听、不装 fetch 补丁                       |
| `providers`  | provider 路由白名单，默认含 `opencode` 与 `opencode-go`             |
| `hosts`      | 目标主机白名单，默认 `opencode.ai`，自动包含子域                    |
| `headerName` | 注入的请求头名                                                      |
| `valueMode`  | `uuid` 提取会话 id 中的裸 UUID（无则回退原串）/ `raw` 用原始会话 id |
| `override`   | 已有同名头时是否覆盖（默认不覆盖）                                  |

## 主要能力

- 拦截点为 LLM 流事件与单层 `globalThis.fetch` 补丁，判定条件是 provider 白名单与目标主机同时命中，任一不满足即原样调用原 fetch，零副作用；
- 已有同名头默认不覆盖，`Headers` 实例 / 数组 / 普通对象三种形态都做大小写不敏感处理，且不就地修改调用方对象；
- 无会话上下文或会话 id 为空时不注入，内部异常一律吞掉并降级为原行为，绝不影响推理请求；卸载时只还原自己安装的那层补丁；
- 头值由纯函数推导，确定性且会话之间互不干扰，会话标题生成等辅助 LLM 调用同样带上同一会话头。

## 限界

只拦截 `globalThis.fetch`，走 websocket 或绕过 fetch 的原生客户端不注入；若静态配置里写死了 `x-opencode-session`，默认不覆盖会让本插件等于没生效（且静态值被所有会话共用），需删除静态项或改 `override: true`。
