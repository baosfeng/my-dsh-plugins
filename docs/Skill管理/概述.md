# Skill 管理（dsh-my-skill-manager）

> ⚠️ **何时阅读：** 需要查看当前有哪些 skill（全局/项目）、或想按项目禁用某些 skill（省 token、避免干扰）时，或修改本插件代码前。

## 功能一句话

**分「全局 / 项目」查看全部 skill（名称 / 描述 / 来源 / 状态），在设置页一键启用/禁用——禁用的 skill 不再注入该项目会话（模型不可见、不可加载），配置随仓库版本化。**

## 解决的问题

DSH 的 skill 机制自动发现并注入所有 skill（项目 `.dsh/skills`、`.agents/skills`、用户级 `~/.dsh/skills`、`customSkillDirs` 等），模型侧统一以 `<available_skills>` 呈现，但用户侧有两个空白：

1. **看不到 skill 全貌**：有哪些 skill、来自全局还是项目、是否启用，没有管理界面可查；
2. **无法按项目控制**：skill 全部自动注入，项目之间无法隔离——项目 A 不需要的 skill 也会注入，浪费 token 且可能干扰。

本插件补上这两个空白（issue #23）。

## 工作机制

```
设置 → 插件 → Skill 管理（官方 slots 扩展点，纯官方依赖）
        ↓ GET /my-skill-manager/api/list?cwd=…
ctx.skills.list({ cwd }) 官方 catalog（host 层：runtime + 占位）
        + lib/diagnose.js 独立扫描目录（跟随符号链接，frontmatter 轻量解析）
        ↓ 项目视图（cwd 非空）只保留项目来源条目 / 项目 roots
        ↓ 合并：官方 catalog 优先；目录中 catalog 缺失的正常条目补充显示
          （标记「未收录」cataloged: false——host 层 skill-filesystem 被官方
          禁用时，filesystem skills 全部以未收录形式展示）
        ↓ diagnostics.missing：目录中 frontmatter 异常 / 符号链接异常的条目（名单 + 原因）
        ↓ GET /my-skill-manager/api/rescan?cwd=…（刷新按钮：control.invalidate() 后重扫）
        ↓ PUT /my-skill-manager/api/config（保存 + control.invalidate()）
<项目根>/.dsh/skills.enabled.json（项目配置，随仓库版本化）
$DSH_HOME/skills.enabled.json（全局配置）
        ↓ 禁用生效
ctx.skills 注册的 rank-0 占位 provider（全局层）：
  被禁用的 skill 名在合并目录中被「已禁用」占位覆盖
  （filesystem rank 100–500、runtime 250 均低于 rank 0 优先级）
  → 模型侧不可见；get() 返回 undefined（不可加载）
```

## 安装与使用

1. 安装插件：

   ```bash
   dsh plugin --profile web add dsh-my-skill-manager --trust-lockfile
   ```

2. 打开 DSH Web 设置 → 插件 → **Skill 管理**；
3. 默认「全局」视图切换任意 skill 的全局启用/禁用；顶部「全局 / 当前项目」分段控件切换视图（当前项目 tab 仅在检测到会话工作区时出现，项目根路径只读展示）——项目视图**只显示该项目的 skill**，可编辑该项目级配置（含在项目内禁用全局 skill）；
4. 新建 skill 后点右上角「刷新」立即可见（无需重启）；若列表下方出现「扫描诊断」警示条（可点击展开），说明有 skill 目录条目未被官方扫描器收录（如符号链接异常、frontmatter 缺失），按提示修复后刷新即可；
5. 修改即时生效（catalog 失效重算），无需重启。

## 边界与限制

- 禁用是**按名字**生效：同名的任何来源 skill（项目/用户/内置）都会被占位覆盖；
- 配置只维护 `disabled` 名单（`enabled` 白名单模式预留，暂未实现）；
- 项目配置以 `cwd` 向上找 `.git` 定位项目根；无 `.git` 时退回 `cwd` 自身；
- 项目视图只显示项目来源（`project-dsh`/`project-agents`）的 skill；全局 skill 只在全局视角查看；
- **host 层 `skill-filesystem` 被官方禁用**（dsh-web-app patch：presets own local discovery），`ctx.skills.list({ cwd })` 的 catalog 不含 filesystem skills——面板通过 `lib/diagnose.js` 独立扫描目录补充展示（标记「未收录」），因此列表与实际目录一致；「未收录」表示该 skill 不在官方 catalog（不注入会话），可能是 filesystem 发现未启用或扫描器跳过；
- 目录扫描只覆盖插件侧可确定的默认根目录（`$DSH_HOME/skills`、`~/.agents/skills`、项目 `.dsh/skills`、`.agents/skills`）；`customSkillDirs`/`bundledSkillDir` 是官方 filesystem provider 的配置，插件侧不可知，不纳入扫描（宁可漏报也不误报）；
- 面板为可选增强：`ctx.get('slots')` 缺省时静默跳过注册，server 端禁用能力不受影响（与「纯官方依赖」原则一致，不依赖 dsh-better-sidebar）。
