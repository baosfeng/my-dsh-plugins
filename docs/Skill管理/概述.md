# Skill 管理（dsh-my-skill-manager）

> 源码：`plugins/dsh-my-skill-manager/` · [插件 README](../../plugins/dsh-my-skill-manager/README.md) · [重设计原型](../原型重构/dsh-my-skill-manager.html) · [实现契约](../原型重构/impl-contract-skill-manager.md) · [文档索引](../索引.md)

## 功能

一页看清全部 skill（名称、描述、来源、路径、是否被收录、使用热度），在「设置 → 插件 → Skill 管理」里直接启停——全局开关对所有项目生效，本项目开关只影响当前项目；被禁用的 skill 不再注入该项目会话，模型不可见也不可加载。

主要能力：

- **全量目录**：官方 catalog 与目录扫描合并，未被收录的条目单独标记并说明不注入；
- **双作用域开关**：每个 skill 并排「全局 / 本项目」，状态徽标区分 生效 / 全局已禁用 / 本项目已禁用 / 未收录；
- **搜索与组织**：搜索（名称/描述/路径）、来源与状态筛选、只看未使用、四种排序、概览计数可点筛；
- **双视图**：卡片流（按来源分组）与紧凑表（可排序表头、多选）共享筛选状态；
- **详情**：路径复制、provider、调用能力（模型/用户可调用）、使用统计、SKILL.md 只读预览（前 15 行，可复制全文）；
- **批量启停**：选择模式 + 内联二次确认；
- **扫描诊断**：坏符号链接、缺 SKILL.md、frontmatter 异常等条目独立诊断台；
- **使用统计**：次数 / 最近使用 / 来源，持久化 `$DSH_HOME/skills.usage.json`。

## 安装

```bash
dsh plugin --profile web add dsh-my-skill-manager --trust-lockfile
```

## 配置

| 位置 | 作用 |
| --- | --- |
| 项目根下的 `.dsh/skills.enabled.json` | 项目级禁用名单（随仓库版本化） |
| 用户级 `$DSH_HOME/skills.enabled.json` | 全局禁用名单 |

只维护禁用名单（`enabled` 白名单模式预留未实现）。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/my-skill-manager/api/list?cwd=` | 全量 skill + 双禁用名单 + 诊断 + 使用统计 |
| GET | `/my-skill-manager/api/detail?name=&cwd=` | SKILL.md 只读正文（白名单根、≤256KB） |
| GET | `/my-skill-manager/api/rescan?cwd=` | 失效重算后返回列表 |
| GET | `/my-skill-manager/api/session?sessionId=` | 会话工作目录 |
| PUT | `/my-skill-manager/api/config` | 保存某作用域禁用名单 |

## 边界

- 禁用按名字生效：同名的任何来源 skill（项目 / 用户 / 内置）都会被占位覆盖；
- 项目配置以 cwd 向上找最近 `.git` 定位项目根，无 `.git` 时退回 cwd 自身；
- 详情只读扫描白名单根内的 `SKILL.md`（realpath 越界校验，超 256KB 截断）；
- 列表以目录扫描为主：宿主在 HTTP 侧只能看到 global 层的 skill catalog（文件系统 skill 在会话/作用域层），因此扫描发现且 frontmatter 正常的条目一律视为**可管理 skill**；「异常」只代表目录扫描失败（坏符号链接 / 缺 SKILL.md / frontmatter 异常等）；
- 只扫描插件侧可确定的默认根目录，宿主自定义 skill 目录不纳入（宁可漏报也不误报）；
- 禁用占位注册在全局层：宿主「最近层条目优先」语义下，若同名 skill 由 preset/scope 层提供，占位不覆盖（沿用既有行为，见下方待办）。
