# TS 示例插件（dsh-ts-example）

> 源码：`plugins/dsh-ts-example/` · [插件 README](../../plugins/dsh-ts-example/README.md) · [插件开发技能](../插件开发技能/概述.md) · [文档索引](../索引.md)

## 功能

仓库的 TypeScript 插件开发示例，演示新插件用 TS 开发的全流程：server 端 TS 源码经 tsc 编译、client 端 TS 源码构建时编译内联进模块加载器 bundle、CI 强制类型检查。**新 TS 插件照抄本插件结构即可**。

演示功能：问候语路由（支持中英文）、会话计数统计、侧边栏「TS 示例」页签（client 到 server 全链路）。

## 安装

```bash
dsh plugin --profile web add dsh-ts-example --trust-lockfile
```

## 关键约定

- **Server 端**：源码在 `src/`，由 `tsc -p tsconfig.json` 编译为 ESM 产物到 `lib/`；相对导入必须写 `.js` 扩展名；运行时类型用本地 `types.d.ts` 手写最小契约，不装宿主类型包；
- **Client 端**：源码 `src/client/index.ts` 必须单文件，编译成 CommonJS 后注入模板占位符生成 `lib/client.js`；内联后 `require` 只认识宿主注入的模块（如 react），因此不能有运行时相对导入，多文件请改用 esbuild 等打包器；
- **产物必须提交**：CI 只做语法检查与测试、不跑构建，改动 TS 源码后需重新构建再提交；
- **类型检查**：根配置 strict + noEmit 覆盖全仓 TS，本地与 CI 都跑类型检查——模块不存在、类型不匹配等错误在发版前就被拦下。
