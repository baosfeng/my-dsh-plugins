# md 渲染（dsh-md-render）

> 源码：`plugins/dsh-md-render/` · [插件 README](../../plugins/dsh-md-render/README.md) · [文档索引](../索引.md)

## 功能

对话里的**围栏代码块全部由本插件自己的渲染器产出**（不再调用宿主官方 `MarkdownText` / `CodeBlock`），官方节点结构一个字节都不改（只追加自有容器 + 自有 CSS 在接管视图下隐藏官方子树）：

- **自研 markdown 渲染**：`text` / `plaintext` / `txt` / `md` / `markdown` 围栏块、**确证无语言**的围栏块、`pre[data-context-text]` 上下文注入正文（子 agent 回传消息 / AGENTS.md）、公共 API `MarkdownView` —— 解析层用 **marked**（GFM 表格 / 列表 / 标题 / 链接 / 行内代码 / 代码块），产出真实标签 + 自有 class，每块带独立「查看原文」；
- **自研代码块渲染**：`js` / `ts` / `json` / `bash` / `python` … —— banner 显示**真实语言名**（不是官方那个本地化标签「代码块」）+ 复制 + 自动换行 + **highlight.js** 高亮（hljs 令牌树 → 自有 vdom span，没有任何 innerHTML）；
- **mermaid 图表卡片**：`mermaid` / `mmd` 围栏块 → 图表卡片（预览 / 代码切换、导出 PNG / SVG、浮窗 + 缩放平移）；
- **「渲染为…」三态切换**（图表 / Markdown / 源码）对所有围栏块可用，覆盖值按内容哈希记入 `sessionStorage`；
- **整段复制**、**统一 MarkdownView**、**表格容错**（GFM 不认的两种分隔行写法先规范化）、**思考块默认展开**、**设置面板**。

**解析层与高亮层走 assets 懒加载**（与 mermaid 引擎同一模式）：`marked`（47 KB）与 `highlight.js`（129 KB）由 host 半静态托管于 `/md-render/assets`，client 首次真正需要时才 fetch + 注入 `<script>`，**不进 `lib/client.js`** —— 用户口径「打包体积不用控，只控启动速度」；就绪通知触发一次重扫补渲染。

## 安装

```bash
dsh plugin --profile web add dsh-md-render --trust-lockfile
```

> 升级到本版本后**必须重启 `dsh web`**：host 半的资源白名单在启动时固定，老 host 会把两个新 assets URL 判成 404（此时插件真降级回官方形态，不报错）。

## 关键配置

设置 → 插件 → 渲染 页签可视化编辑，保存即生效、重启不丢；以下开关默认全部开启：`copyButton`（整段复制）、`textFenceMarkdown`（**围栏块渲染总开关**，关掉即全部交回宿主官方渲染）、`contextMarkdown`（上下文注入块渲染）。

> 原自实现渲染的开关（`syntaxHighlight` / `mathStructures` / `tableSort` / `codeTheme` 等 12 项）仍不存在（能力由自研渲染器提供，无开关）；patch 文件里的旧键保留无害。合并带来的包名 / 路由 / 配置键迁移见 [插件 README 的「破坏性变更与迁移」](../../plugins/dsh-md-render/README.md#破坏性变更与迁移)。

## 已知限制

- 围栏语言识别**不读 React fiber 私有属性**：DOM 契约（`code.language-*` / banner infostring）零请求优先；宿主 banner 只给本地化标签「代码块」时回落到 client 事件流索引与 host 半的有界语言索引（`GET /md-render/api/langs`，按块内容哈希，进程内、不落盘）；
- **全都拿不到语言**时仍按**代码视图**接管，但语言位留空（不写「代码块」、不猜语言、也不误判成 markdown）；想按 markdown 读就用块内「渲染为… → Markdown」；
- 解析层 / 高亮层懒加载：首屏到接管之间有「一次同源请求」的窗口（期间保持宿主官方形态）；加载失败按会话缓存、不再重试；
- 平台 `react-dom/client` 不可用时真降级：`MarkdownView` 落 `<pre>`，注入点保持宿主原样；
- 单块超长（markdown 围栏 > 10 万字符、代码块 > 20 万字符、上下文块 > 20 万字符）保持宿主原样；数学公式不做；raw HTML 永远是字面文本。

## 合并进来的能力（原 dsh-think-zh-expand / dsh-mermaid-render）

> 两个插件已下线（issue #463），能力并入本插件。以下保留「怎么跑 / 防复发 / 指针」，历史信息已删除。

### 思考块默认展开

- 实现：DOM 层对官方折叠行派发一次真实 click（外观 100% 官方），选择器 [data-variant="think"] [data-disclosure-row][aria-expanded]；WeakSet 一次性动作（幂等、尊重用户手动折叠）。
- 契约守卫 + 静默降级：选择器失配（宿主升级改属性）→ 退回官方默认，不报错、不写 DOM。
- 性能护栏：只在新增节点内定位 think 容器（先 matches 短路，再在容器内查行），单批最多 200 行。
- 开关：设置 → 插件 → 渲染 → 「思考块」分组（thinking.defaultExpanded）。
- 中文思考指令不在这里注入 —— 由 dsh-my-memory 的「全局提示词」提供。

### mermaid 图表卡片

- 引擎：assets/mermaid-10.9.3.min.js（3.34 MB）由 host 半静态托管于 /md-render/assets，client 首次渲染时 fetch 并按需注入 <script>；**不内联**进 bundle（issue #185 的 4.48 MB base64 冗余教训）。
- 渲染：离屏容器（.dsh-md-render-offscreen 类，脱离文档流但仍在布局树内）承接 mermaid 失败时的「炸弹图」，成功只取 svg 字符串。
- 流式：宿主在整条消息上挂 data-streaming，DOM 里看不到围栏是否闭合 → 用 400ms 稳定窗口 + 连续 2 次观察判定；源码再变即自愈卸载重来。
- 失败降级：卡片显示错误原因 + 重试 + **原始源码**（绝不静默丢内容）。
- 开关：设置 → 插件 → 渲染 → 「Mermaid 图表」分组（mermaid.render / mermaid.injectPrompt）。

### 排障

- 代码块没有高亮 / text 围栏没按 markdown 渲染：先看 Network 里 `/md-render/assets/marked-18.1.0.umd.js` 与 `/md-render/assets/highlightjs-11.12.0.min.js` 是不是 200 —— 404 说明 host 半是旧版本（资源白名单在启动时固定），**重启 `dsh web`** 即可；插件此时是真降级（块停在官方形态，不报错）。
- 代码块 banner 语言位是空的：说明该块的语言识别不出来（DOM 与两级索引都没答案）—— 属于设计内的「绝不编造语言名」，可用块内「渲染为…」手动指定。
- 卡片不出现：确认 mermaid.render 打开、块语言标记是 mermaid / mmd、会话滚动容器仍在（[data-conversation-scroll]）。
- 注入说明未生效：mermaid.injectPrompt 是否被显式设为 false。
