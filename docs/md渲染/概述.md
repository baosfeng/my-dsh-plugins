# md 渲染（dsh-md-render）模块概述

> 源码：`plugins/dsh-md-render/` · 需求清单：[需求清单](需求清单.md)

## 背景与问题

非思考模式（模型不输出 reasoning，仅 text 块）下，模型输出的 markdown 表格没有被渲染成表格，而是以纯文本/原始 markdown 语法展示。

原因分析（代码调研）：

- `dsh-think-zh-expand` 以 priority -1 替换了内置 `assistant-step` 渲染器，text 块与 reasoning 块都走轻量 `MarkdownView`（`plugins/dsh-think-zh-expand/src/client/index.ts`）；
- `tryTable` 检测严格：表头行必须以 `|` 开头和结尾（`/^\s*\|.*\|\s*$/`），分隔行必须含 `-`；模型输出的不标准表格（无首尾管道符、分隔行变体）检测失败 → 回退为纯文本段落；
- 内置渲染器（`MarkdownText`）支持表格（`md-table-wide` 宽表格样式），但被 think-zh-expand 替换后不生效。

## 方案（issue 方案 A：新建渲染插件）

新建 client-only 插件 `dsh-md-render`，分两层：

### 1. 统一 MarkdownView（issue #31 渲染职责迁移）

- think-zh-expand 的 MarkdownView 渲染逻辑（`mdInline` / `tryFence` / `tryTable` 等）整体迁至本插件 `lib/parts/markdown.part.js`，输出结构保持迁移前约定（`div.tzx-md` / `p.tzx-p` / `table.tzx-table` / `div.md-code-block`）；
- 新增**公式渲染**（自实现零依赖）：行内 `$...$` → `span.dsh-md-render-math`（货币 `$5` / 变量 `a$b` / 块级 `$$` 保护），块级 `$$...$$` → `div.dsh-md-render-math-block`；
- **代码块容器** `div.md-code-block`（含 `pre.tzx-pre` > `code.language-*`）由本插件产出，dsh-mermaid-render 无需改动即可扫描；
- `exports.MarkdownView` 供 think-zh-expand 跨插件 require（其 `dsh.client.external` 声明依赖本插件）；渲染器注册仍由 think-zh-expand 负责（保留思考展开职责），本插件不注册渲染器。

### 2. DOM 层表格增强（issue #30）

1. **扫描**：MutationObserver 扫描 `[data-conversation-scroll]` 内的 `div.tzx-md`（MarkdownView 输出）与 `div.md-table-wide`（内置 MarkdownText 的宽表格容器）容器；
2. **检测**：对容器内以纯文本段落（`p.tzx-p`）形式存在的表格文本，用增强规则解析（见下）；
3. **渲染**：将段落替换为 `div.dsh-md-render-table-scroll > table.dsh-md-render-table`（thead/tbody/逐列对齐），单元格行内格式（`**bold**` / `` `code` `` / `*em*` / `[link]`）重新渲染；
4. **跳过**：已渲染的表格（`table.tzx-table` 等）不重复处理；流式中的容器（`[data-streaming]` 祖先）等内容稳定后再处理。

## 增强表格检测规则

| 规则        | 实现                                                   | 说明                                             |
| ----------- | ------------------------------------------------------ | ------------------------------------------------ |
| 表头/数据行 | `isTableLine`：含 `\|` 且 ≥2 列，且不是分隔行          | 允许无首尾管道符（`插件 \| 版本`）               |
| 分隔行      | `isSeparatorLine`：只含 `-` `:` `\|` 与空白，且含 `-`  | 支持 `--- \| ---`、`-\|-\|-`、`---`、`:---:      | ---:` 等变体 |
| 对齐标记    | `parseAlign`：`:---` 左、`:---:` 中、`---:` 右、其余左 | 逐列生效                                         |
| 段落内查找  | `parseTable`：在段落文本中查找「表格行 + 分隔行」组合  | 表格前/后的非表格文本（prefix/suffix）保留为段落 |

## 渲染与样式

- 结构：`div.dsh-md-render-table-scroll`（横向滚动容器）> `table.dsh-md-render-table` > `thead`/`tbody`；
- 样式：表头底色 + 加粗（`--dsw-alias-markdown-code-block`）、行分隔线（`--dsw-alias-border-l2/l3`）、字体（`--dsw-font-markdown-table-head/table`），深浅主题自适应；
- 宽表格：滚动容器 `overflow-x: auto`、`max-width: 100%`，宽表格不撑破消息气泡；
- 样式随 activation 注入、fiber teardown 卸载（HMR/禁用无残留）。

## 公式结构渲染（issue #82）

行内 `$...$` / 块级 `$$...$$` 公式内容经**轻量 LaTeX 子集解析器**（零依赖，R10，见 `lib/parts/math.part.js` + `math-symbols.part.js` + `math-render.part.js`）解析为语义化嵌套结构，CSS flex 排版（`styles.part.js`，走语义 token，深浅主题自适应）：

| 结构      | LaTeX 输入       | 输出结构                                                                  |
| --------- | ---------------- | ------------------------------------------------------------------------- |
| 分数      | `\frac{a}{b}`    | `span.dsh-md-render-frac`（`-num` / `-den` 上下 + 分数线）                |
| 根号      | `\sqrt{x}`       | `span.dsh-md-render-sqrt`（√ 符号 + `-body` 顶部根号线）                  |
| 上下标    | `x^2` / `x_i`    | `span.dsh-md-render-supsub`（`-base` + `-sup` / `-sub`）                  |
| 求和/积分 | `\sum_{i=1}^{n}` | `span.dsh-md-render-big`（`-symbol` ∑/∫ + `-limits` 上下限）              |
| 希腊字母  | `\alpha` 等      | Unicode 符号（α/β/…），常见符号命令（`\times` ×、`\cdot` ⋅ 等）同样转符号 |
| 文本命令  | `\text{if}` 等   | 参数组按普通文本内联                                                      |

- **解析器**：tokenize（`\命令` / 花括号组 / `^` `_` / 字符）+ 递归下降解析（frac/sqrt/supsub/big/seq 节点），支持嵌套（`\frac{\sqrt{x}}{y}`）；
- **回退策略（不误伤）**：结构命令参数不完整（`\frac{a}{b`、`\frac a b`、无厘头组）→ **全局解析失败 → 整个公式保持原文**（不渲染结构、不报错、不触发 R14 错误标记）；未知命令（`\foo`）保持原样文本；
- **开关门控（issue #84）**：`mathStructures` 关闭时 formula 结构解析不执行，公式保持原轻量行为（原文）；
- **R14 兼容**：货币 `$5` / 变量 `a$b` / 块级 `$$` 保护不变；异常公式（未闭合/空/空白开头）仍走错误标记。

## 代码块增强（issue #80）

`div.md-code-block` 由 MarkdownView 产出，结构保持；在其上做 **语法高亮 + 语言标签 + 行号**（零依赖，见 `lib/parts/highlight.part.js` tokenizer + `codeblock.part.js` 渲染）：

- **结构**：`div.md-code-block > div.dsh-md-render-code-head`（语言名 + 复制按钮，同排）`+ pre.tzx-pre > code.language-*`（token 高亮 / 行号）；
- **语法高亮**：tokenizer 为纯函数单遍扫描，按语言规则拆分 token 输出 `<span class="dsh-md-render-tok-*">`；覆盖 javascript/typescript/python/json/bash/markdown/yaml；未知语言回退纯文本；超长（>500 行）跳过高亮；
- **行号**：`code` 内按行输出 `div.dsh-md-render-code-line`，行号经 CSS counter `::before` 显示，**不进入 code/pre 文本内容**——mermaid 扫描（`pre.textContent`）与复制按钮（`code.textContent`）读取的原代码不受污染；
- **样式**：token 类走固定色板 + `prefers-color-scheme` 深浅两套，随 activation 注入/卸载；
- **开关**：行号默认开，`config.lineNumbers: false` 关闭（`apply(ctx)` 读取，`setRenderOptions` 可编程切换/测试）。

## 增强功能配置化（issue #84）

各增强功能独立配置开关（默认全部开启），设置页（设置 → 插件 → 渲染 页签，官方 slots 扩展点）可视化编辑，保存即生效、重启不丢：

| 开关              | 功能                         | 来源 |
| ----------------- | ---------------------------- | ---- |
| `copyButton`      | 代码块/整段一键复制按钮      | #74  |
| `syntaxHighlight` | 代码块语法高亮（token span） | #80  |
| `languageLabel`   | 代码块语言标签               | #80  |
| `lineNumbers`     | 代码块行号                   | #80  |
| `taskList`        | 任务列表 checkbox            | #81  |
| `strikethrough`   | 删除线                       | #81  |
| `image`           | 图片渲染                     | #81  |
| `nestedList`      | 嵌套列表（按缩进层级）       | #81  |
| `mathStructures`  | 行内/块级公式结构            | #82  |
| `tableSort`       | 表头排序                     | #83  |
| `tableFold`       | 长表格折叠                   | #83  |

- **配置来源**：`apply(ctx, config)`（server，`lib/index.js`）与 client `apply(ctx)`（`lib/parts/config.part.js` 的 `pickRenderOptions`）从 `ctx.config` 读取；缺省/非法值保持默认（不覆盖）。
- **设置页**（`lib/parts/settings.part.js`）：`slots.inject('settings.plugins.tab')` 注册「渲染」页签，展示全部开关；保存经 `PUT /md/api/config`（server `lib/routes.js`）写入 profile patch 文件（`- id: md-render` + `config:` 块，复用 dsh-shared 配置持久化），DSH watchUserPatches 热重载 → 保存即生效、重启不丢；保存成功后立即 `setRenderOptions` 应用（当前页面无需等待重载）。
- **渲染门控**：各 parts 在渲染时读取 `renderOptions`（模块级，`config.part.js`）——`syntaxHighlight: false` 时 tokenizer 不执行（无 token span）、`taskList: false` 时任务标记保持原文（无 checkbox）、`tableFold: false` 时长表格不折叠等。
- **测试**：`test/host-config.mjs`（配置 API + 持久化 + 模拟重启恢复 + 非法/围栏）+ `test/config-switches.mjs`（各开关关闭时功能不渲染断言）+ Gherkin 关闭开关场景 + 真实环境验证。

## 兼容性

| 场景                        | 行为                                                                                                                                   |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 与 dsh-think-zh-expand 协作 | think-zh-expand 跨插件 require 本插件 MarkdownView（`dsh.client.external`）；识别 `tzx-md` 容器；已渲染的 `table.tzx-table` 不重复处理 |
| 内置 MarkdownText           | 识别 `md-table-wide` 容器；已渲染表格不干扰                                                                                            |
| 思考模式（reasoning 块）    | 表格渲染不受影响（回归）                                                                                                               |
| 流式生成                    | 流式中的容器等内容稳定后再处理                                                                                                         |
| dsh-mermaid-render          | `div.md-code-block` 容器由本插件产出（结构保持），mermaid-render 无需改动                                                              |

## 宿主渲染缺口的插件侧接管（项目策略）

宿主 `ContextBody` 把上下文注入正文（**子 agent 回传消息走的就是这条路径**）渲染为纯文本 `<pre data-context-text="true">`，MarkdownView 容器不在其中，增强因此不介入。按项目决策「宿主渲染/能力缺口一律由本仓库插件侧接管处理，不依赖上游修改、不向上游提 issue」（见 [dsh-plugin-development 技能](../../skills/dsh-plugin-development/SKILL.md)），issue #196 由本插件在 DOM 层接管：先确证宿主契约 → 内容签名幂等标记 → 契约不匹配时静默退让原文 → MutationObserver 应对 React 重渲染 → 超长内容跳过（实现见 [插件 README](../../plugins/dsh-md-render/README.md)）。轨迹视图（issue #205，宿主 `@deepseek-ai/dsh-client-ui-trajectory` 的 `MarkdownFragment → MarkdownText`）属同源第二路径，按同一模式覆盖。
