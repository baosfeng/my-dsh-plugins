## 易碎点

- **公式结构（issue #82）**：公式内容解析与渲染在 `math.part.js`（解析器）+ `math-symbols.part.js`（命令表）+ `math-render.part.js`（React 渲染）——三者与 `client.src.js` / `scripts/build.mjs` 的占位符顺序（SYMBOLS → MATH → MATH_RENDER → SYNTAX）必须一致；行内（`syntax.part.js` `mathSpanOrText`）与块级（`markdown.part.js` `mathBlockEl`）共用 `parseMath` / `mathNodesToReact`；回退契约：`parseMath` 返回 `{ failed }`，failed 时公式保持原文（不渲染结构、不报错）；`mathStructures` 关闭时结构解析不执行（原文），与 #84 配置体系一致——改动解析/渲染逻辑必须同步更新 `test/math-structure.mjs` 与 Gherkin 场景并保持全绿。
- **构建产物**：`lib/client.js` 是构建产物（parts 拼接），修改 `client.src.js` 或 `lib/parts/` 后必须 `npm run build` 并提交产物；CI 不执行构建。
- **检测规则**：表格检测规则（`isTableLine` / `isSeparatorLine` / `parseTable`）是核心逻辑，改动必须同步更新 `test/table-detect.mjs` 并保持全绿。
- **输出结构兼容（issue #31）**：MarkdownView 输出类名（`div.tzx-md` / `p.tzx-p` / `table.tzx-table` / `div.md-code-block`）是跨插件契约——dsh-md-render 的 scanner 扫描 `p.tzx-p`、dsh-mermaid-render 扫描 `div.md-code-block`、think-zh-expand 的测试断言这些结构；改动类名必须同步更新三个插件的测试。
- **复制按钮结构（issue #74 / #146）**：`div.md-code-block` / `div.tzx-md` 内渲染 `button.dsh-md-render-copy` 子元素——mermaid-render 扫描 `div.md-code-block` 用 `querySelector('code')` 不受影响；think-zh-expand 测试展开函数组件会收集按钮文本「复制」，其断言不受影响；改动按钮类名/文案需同步更新三个插件测试。issue #80 曾将代码块按钮移至头部（`div.dsh-md-render-code-head` 内与语言标签同排）；issue #146 起位置可配置：默认 `bottom-right`（按钮为 `md-code-block` 直接子元素，CSS `.md-code-block>.dsh-md-render-copy{position:absolute;right:8px;bottom:8px}`），`header` 位置保持头部布局（`.dsh-md-render-code-head>.dsh-md-render-copy{margin-left:auto}`）——两条 CSS 规则互斥共存（按钮只会在其中一处），改动定位规则需同步更新 `test/copy-button.mjs` 与 Gherkin 位置场景。
- **代码主题（issue #146）**：主题色板定义在 `styles.part.js`（`.md-code-block[data-theme]` 默认 bright + 4 套具名主题 + `prefers-color-scheme:dark` 暗色变体），经 `codeblock.part.js` 渲染的 `data-theme` 属性选择；**每个主题必须同时定义背景色 `--dsh-md-render-code-bg` 与自洽前景色 `--dsh-md-render-code-fg`（及 token 色），`.tzx-pre` 的 `color` 用 `var(--dsh-md-render-code-fg, var(--dsw-alias-label-primary))`——文字色不得再纯继承宿主 `.tzx-md`**（否则系统暗色 + 宿主浅色时背景反转为深色而文字仍为黑，代码不可见，见 `test/codeblock-theme-css.mjs`）；合法 id 列表在 server 端 `SELECT_KEYS.codeTheme` / client 端 `config.part.js` `CODE_THEMES` / `settings.part.js` `CODE_THEME_OPTIONS` 三处一致（`test/config-switches.mjs` 有跨端一致性断言）；主题只作用于实际高亮的代码块（无 `data-theme` 时 `.tzx-pre` 背景/边框走 DSH 语义 token fallback）；新增/改名主题需三处同步 + 色板落 `styles.part.js`。
- **代码块增强结构（issue #80）**：`div.md-code-block` 内新增头部 `div.dsh-md-render-code-head`（语言名 + 复制按钮）与 `code` 内 `div.dsh-md-render-code-line` 行号 div（CSS counter 伪元素，不进入文本内容）——tokenizer（`test/tokenizer.mjs`）与渲染（`test/codeblock-render.mjs`）是核心逻辑；mermaid 扫描 `pre.textContent` / 复制按钮读 `code.textContent`，行号用伪元素不污染，改动不得引入行号到文本节点；新增/改动 parts 需在 `client.src.js` 与 `scripts/build.mjs` 同步占位符。
- **跨插件导出**：`exports.MarkdownView` 是 think-zh-expand 的跨 bundle require 契约（`dsh.client.external`），删除/改名会破坏 think-zh-expand 的 client 端 materialize。
- **表格交互（issue #83）**：排序/折叠状态存 scroll 容器 dataset（`sortCol` / `sortDir` / `totalRows`），事件委托绑定在 scroll 容器 click 上——改动渲染结构（th/折叠按钮/折叠行 class）必须同步更新 `test/table-interact-render.mjs` 与 Gherkin 场景；折叠行用 class + CSS 隐藏（`tr[hidden]` 会被作者样式覆盖，不可用）。
- **配置化（issue #84 / #146）**：增强开关与选择项状态（`renderOptions`）定义在 `config.part.js`（`setRenderOptions` / `pickRenderOptions`），其余 parts 渲染时读取——开关名（11 个）在 server 端（`lib/index.js` `SWITCH_KEYS` / `lib/routes.js` `SWITCH_KEYS`）与 client 端（`config.part.js` `DEFAULT_RENDER_OPTIONS` / `settings.part.js` `SETTINGS_SWITCHES`）三处必须同名一致；选择项（`copyButtonPosition` / `codeTheme`）合法值在 server 端 `SELECT_KEYS` 与 client 端 `COPY_BUTTON_POSITIONS` / `CODE_THEMES` 一致（跨端一致性断言在 `test/config-switches.mjs`）；新增开关/选择项需三处同步 + 测试断言；patch 写入行 id 为 `md-render`（与 `cordis.patch.yml` 一致，改名会破坏持久化恢复）；server 端新模块（`lib/routes.js`）纳入覆盖率门禁（`vitest.config.mjs` include + 阈值）。
