# Mermaid 渲染（dsh-mermaid-render）

## 概述

DSH 对话 Mermaid 图表渲染插件（client 渲染 + host 提示词注入）：把对话消息里的 `mermaid` / `mmd` 代码块自动渲染成**图表卡片**（预览 / 代码切换）。**mermaid 引擎在构建时内联进 client bundle（base64），零 CDN 依赖、完全离线可用**——规避了第三方插件依赖 jsdelivr CDN 在部分网络环境不可达导致图表空白的问题。

## 零炸弹图与「闭合即渲染」（issue #195）

**「炸弹图」** = mermaid 引擎渲染失败时**自己**往页面插入的错误图形（`div#d<id>` 里一张 `svg`，含 `.error-icon` / `.error-text`，文案 `Syntax error in text` + `mermaid version x.y.z`）。用户要求这种图**绝不能出现**。

**引擎实测结论（决定方案）**：

| 事实                                       | 证据                                                                                                                                                      |
| ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| vendored 引擎是 **mermaid 10.9.3**         | 错误图形文案里的版本号 + bundle 内 `"10.9.3"` 字面量                                                                                                      |
| 该版本**不支持** `suppressErrorRendering`  | bundle 内检索不到该标识符；真实浏览器实测：传 `suppressErrorRendering: true` 后 `getConfig()` 能读到 `true`（配置被静默接收）**但失败仍往容器插错误图形** |
| 传`container` 时错误图形只落在**该容器内** | 探针页四组对照：`plain`/`suppress` 落在 `body`（`div#d…`）；`offscreen` 落在传入容器内，容器移除即彻底消失                                                |
| 成功路径只依赖返回的 `svg` 字符串          | 离屏容器渲染成功后容器内无残留（临时元素被引擎自己清掉）                                                                                                  |

因此方案是**离屏渲染**（确定性最强）：`renderSvg` 先建一个 `position:absolute;left:-99999px`（仍在布局树内，保证引擎量得到尺寸）的容器 → `engine.render(id, source, container)` → 无论成败都移除容器；成功只把返回的 `svg` 字符串注入卡片。失败统一进卡片错误横幅（**错误原因 + 原始源码 + 重试按钮**），`重试` 会同时清掉引擎加载缓存。

**闭合判定**：宿主在**整条 assistant 消息**上挂 `data-streaming`（证据：`@deepseek-ai/dsh-client-ui-chat/lib/client.js` 里 `"data-streaming": streaming || void 0`，消息结束才移除），DOM 里看不到「结束围栏是否已出现」。插件侧因此用**内容稳定**判定：块文本在 `STREAM_SETTLE_MS`（400ms，实测流式更新间隔约 240ms 之上）内不变 + 连续两次观察一致 → 才挂载；源码在挂载后继续变化 → **自愈卸载**（恢复原始块、重新等待），所以误判不会留下残缺卡片。非流式块（历史消息、流式已结束）仍**零延迟**挂载。
