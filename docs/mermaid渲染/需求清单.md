# dsh-mermaid-render 需求清单

> ⚠️ **每次开发本插件的新功能或修复前，必须逐条对照本清单**：新改动不得破坏任何一条既有需求；涉及「离线渲染 / 引擎内联」的需求变更后必须跑回归验证（见 [构建与测试](../开发指南/构建与测试.md#需求回归强制要求)）。

## 回归检查（每次改动后）

- [ ] `npm test`（client 渲染路径）通过
- [ ] 构建产物 `lib/client.js` 语法检查通过（`node --check`）
- [ ] 引擎 e2e 验证（playwright 注入渲染出 SVG）通过
- [ ] 与 dsh-think-zh-expand / dsh-md-render 共存时 mermaid 正常渲染（手动；md-code-block 容器由 dsh-md-render 提供，issue #31 迁移后结构保持）
- [ ] 系统提示词注入（issue #194）：`test/prompt-injection.mjs` + Gherkin 2 场景通过（关键行 / ≤500 字符 / 开关关闭不注入）
- [ ] 流式与兜底（issue #195）：`test/client-stream-bomb.mjs` + Gherkin 4 场景通过（零炸弹图 / 闭合即渲染 / 增长中不渲染 / 自愈卸载 / 不回归）
- [ ] 真实环境：隔离实例里用户**不提 "mermaid"** 时模型主动输出 mermaid 代码块并渲染出图（截图留证）
- [ ] 构建门禁（issue #185）：`test/build-inject.mjs` 通过（模板无占位符字面量 / 产物单份引擎 / 常量取值非空）
- [ ] 无副作用：插件禁用/卸载后无残留样式、无残留卡片

## 易碎点

- **引擎内联**：`lib/client.js` 是构建产物（base64 内联 3.3MB 引擎），修改 `client.src.js` 后必须 `npm run build` 并提交产物；CI 不执行构建。
- **占位符**：`client.src.js` 中 `__MERMAID_UMD_B64__` 是唯一注入点，注释中不得出现同名占位符（会被 `replaceAll` 误替换）；构建已改为 `spliceExactlyOnce` 精确一处替换（#185）。
- **注入文案**：`src/prompt.ts` 的 `PROMPT_TEXT` 有 500 字符上限，且**不得包含 `{{变量}}`**（宿主 `renderPrompt` 对变量引用是严格的，未注册变量直接抛错）——改文案必须跑 `test/prompt-injection.mjs`。
- **section 名**：`dsh-mermaid-render` 必须全局唯一（宿主对同层同名 section 注册直接抛错）；改名/新增 section 前先查其它插件（`dsh-think-zh`、`dsh-my-memory` 等）。
- **流式稳定窗口（issue #195）**：`STREAM_SETTLE_MS`（400ms）与 `STREAM_MIN_OBSERVATIONS`（2）是「围栏闭合」的判定参数——真机实测流式更新间隔约 240ms，调小会把 token 间隔误判成闭合；第二道防线是自愈卸载（源码再变即拆卡片），两条一起才保证不出现残缺失败卡片。
- **引擎能力边界（issue #195）**：vendored mermaid **10.9.3 不支持 `suppressErrorRendering`**，传了不生效；零炸弹图完全依赖 `renderSvg` 的离屏容器。升级引擎后必须重跑 `test/client-stream-bomb.mjs` + 隔离实例真实浏览器验证（错误语法 + 引擎不可用两条路径）。
