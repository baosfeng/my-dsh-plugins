# dsh-task-reliability 需求清单

> 维护规则：任何功能开发或修改必须对照本清单做回归检查；新增功能必须在本清单补充条目并添加测试覆盖。
>
> 插件定位：保证 DSH 中的任务可靠执行完成 —— 模型超时/请求失败自动重试、任务未完成自动继续、思考重复检测干预、系统休眠后重启恢复、独立完成度校验 agent、自主决策模式（出行防中断）、远程触发接口。

## 易碎点

- **瀑布事件不可误伤**：`agent/request-error` 与 `tools/pre-execute` 是 waterfall；不接管时必须调用 `next()`；接管（retry/deny）时**不要**调用 next()，否则双重处理。
- **turn-stopping 防死循环**：steer 会让机器再跑一步；必须内置护栏（同内容哈希去重 + 每任务循环上限 + 全局速率限制 + `signal.aborted` 检查），否则插件 bug 会造成 agent 无限循环。
- **校验 agent 生命周期**：创建后必须持有 `AgentHandle` 并在插件卸载/校验完成时 `dispose()`；校验 agent 的会话是独立持久化的，必须清理，否则残留脏数据。
- **校验 agent 不得干扰主流程**：校验在会话完全结束后异步进行；校验期间主 agent 保持 idle；唤醒用 `followup`（新 turn）而非 steer（避免与主 agent 自己排队的 next-step 混在一起）。
- **重启恢复幂等**：resume 前检查 `resumeAt`；同一任务只恢复一次；resume 失败（会话缺失）必须跳过并标记，不能阻塞插件启动。
- **持久化原子性**：`$DSH_HOME/task-reliability.json` 用 tmp+rename 原子写；防抖合并高频更新；损坏文件回退空表。
- **思考重复检测开销**：只保留最近 N 段 reasoning 文本用于相似度计算，不得累积全量；检测逻辑不得阻塞流（chunk 透传优先）。
- **远程接口安全**：trigger 路由必须 loopback 信任围栏；配置 apiToken 后要求 token 头；错误 token 一律 403。
- **ask 超时不得误伤正常询问**：`tools/execute` 包装只对 `ask_user_question` 生效；用户回答后（next() resolve）不得触发超时逻辑；`askTimeoutMs=0` 必须完全透传；子代理会话不处理。
- **autopilot 缓冲不得误伤正常询问（issue #79）**：`tools/pre-execute` 默认放行（缓冲期），延迟决策在 `tools/execute` 完成；缓冲期内用户回答（next() resolve）不得触发自动决策；`autopilotGraceMs=0` 才走 pre-execute 立即 deny 旧路径；autopilot 超时返回空回答（不假装用户选了推荐项），由模型自行决策。
- **看门狗唤醒温和失败**：唤醒失败（会话暂时不可用）不标记任务 failed，留给下次轮询重试；唤醒后必须刷新 `updatedAt`，否则每个检查周期都会重复唤醒。
- **看门狗与重启恢复区分**：看门狗唤醒用「系统唤醒恢复」文本（非「系统重启恢复」），且不依赖 `resumeAt` 幂等（重启恢复专用）；两者共用 live/resume 取回逻辑。
- **/task 命令注册判空降级**：`commands` 服务为可选增强，`ctx.get('commands')` 判空（宿主未提供时插件其余能力照常）；注册必须包 `ctx.effect`（disposer 被 fiber 持有），否则 HMR/禁用后残留注册。
- **/task continue 与看门狗共用唤醒逻辑**：复用 `wakeStalledTask`（无 `resumeAt` 幂等限制，任何时候可唤醒）；唤醒后刷新 `updatedAt` 避免看门狗重复唤醒；唤醒失败不标记任务 failed。
- **多维度循环检测不得误伤正常行为**：工具序列循环用「工具名 + 参数摘要」比对（不同参数不判循环），且排除交互式 `ask_user_question`（重复询问由 ask 超时自动决策 + 待确认去重处理）；只读工具（`toolLoopReadonlyTools`，snapshot/eval/read 等无副作用工具）的连续调用不纳入序列检测——轮询类重复读取是「有进展的重复读取」，与「无进展的死循环」不同（issue #153）；无进展检测只针对「既无助手结论文本也无工具执行」的空转（有产出即重置计数）；`repeatSimThreshold` 默认 0.8（避免过松误报）；检测参数阈值/轮数/每会话上限均可配置。
- **循环打断一次性消费 + 回合绑定**：`pendingBreak` 只在「刚检测到循环」时注入打断指令后置空，避免后续回合反复注入同一打断；且 pendingBreak 绑定命中回合（`pendingBreakTurn`，turn-stopping 开头推进 `turnSeq`），消费时校验属于刚结束的回合——命中回合因速率限制等未消费的残留跨回合自动失效清理，无工具调用回合不注入（issue #153）；每会话上限 `repeatMaxPerSession` 达成后置 `gaveUp` 不再干预。
- **工具循环中断与延续**：`tools/execute` 命中工具循环即抛 `TOOL_LOOP` 中断（复用 `REASONING_LOOP` 中断→turn-stopping 打断→自动继续的链路）；`llm/stream` 包装保持同步函数（waterfall 不 await 返回值），否则 `yield*` 委托消费会抛 `not async iterable`。
- **救场防打扰（issue #147）**：救场只针对「截断/错误 + 输出不完整」；aborted 永不自动继续（尊重用户意图）；每会话次数上限 `rescueMaxPerSession` + 冷却 `rescueCooldownMs` 防「截断→继续→再截断」死循环；输出完整（截断撞自然结尾）不救场；无任务无 todo 文本信号弱不自动救场；`rescueOnTruncation` 关闭后完全不干预。
- **error 救场时机（issue #147）**：error 不触发 turn-stopping（agent-loop 直接抛错），只能由 `agent/error` 标记 + `agent/status` idle 消费（followup 唤醒新回合）；标记一次性消费（用一次删一次），无新 error 的 idle 不重复救场；error 救场同样受上限/冷却约束。
- **救场与既有能力不冲突（issue #147）**：有活动任务走既有 continueTask（优先级不变，不回归）；循环打断（repeatBreak）优先于救场（避免指令混杂）；verify 模式有任务走校验流程，救场只覆盖无任务分支；子代理会话不救场。
