- [ ] 功能 5：LLM 不可用时标题回退核心机制（fallback 截断标题），会话不阻塞
- [ ] 功能 6：核心生成的非结构化标题最终被结构化标题覆盖；用户手动重命名不被覆盖
- [ ] 无副作用：插件禁用/卸载后无残留监听器（`ctx.effect` 持有 disposer、state 清理）

## 易碎点

- **provider 唯一性**：核心 bundle 已注册唯一标题 provider（`session-title-first-prompt-llm`），本插件**不得**调用 `sessionTitle.register()`（会抛 already registered），只能直接 `session.append('session/title', ...)` 覆盖。
- **竞态兜底**：核心 fallback（user/message 后立即 defer）与核心 provider（request/header 后启动 LLM）都可能先于/后于本插件生成标题；监听 `session/title` 事件 + per-session 去重（`source.provider === 'dsh-session-title-gen'` 跳过）保证最终结构化标题生效且无循环。
- **不阻塞会话**：生成必须异步 fire-and-forget（事件监听器不 await 生成），任何失败静默回退，绝不阻塞 `session/event` 事件流。
- **尊重用户标题**：`source.kind === 'user'`（用户手动重命名）一律跳过，不覆盖。
- **过滤插件注入**：`user/message` 的 `source.kind === 'plugin'`（runtime-context 快照等非用户输入）不触发。
- **LLM 路由**：provider/model 缺省时从 `session.requestHeader()?.config` 取；两者必须成对（配置覆盖也成对），否则抛错回退。
