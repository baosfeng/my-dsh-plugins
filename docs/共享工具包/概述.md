# 共享工具包（dsh-shared）

> 源码: `plugins/dsh-shared/`（issue #45：多插件间复制粘贴的公共实现抽取合并；issue #198：资源护栏收口 + 默认安全）

## 概述

`dsh-shared` 是仓库的 **server 端共享工具包**：把多插件间复制粘贴的公共实现抽取为单一来源，依赖方在 `dependencies` 声明 `dsh-shared`（issue #72：dsh-shared 是自家工具库而非宿主提供的运行时，用 dependencies 语义——npm 随插件安装自动安装，用户无需手动装；依赖先发版，见 `scripts/release.mjs` 跨插件依赖校验）。

资源护栏统一收口在这里（issue #198，用户诉求「精简到 share 插件，统一包装好」）：**默认安全**（不传参也有护栏）+ **有界容器**（淘汰语义 + 淘汰计数）+ **写入调度**（防抖/最小间隔/串行/drain）+ **降级看门狗**（采样→阈值→连续确认→降级/恢复），各插件不再各写一套或裸奔。

## 原语适用边界与反例（先读再选）

### 持久化三选一

| 数据形态                                 | 该用                                       | 为什么                                                                   | 反例（错误用法 → 后果）                                                                                               |
| ---------------------------------------- | ------------------------------------------ | ------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| 事件流（高频追加、每条独立、总量增长）   | `jsonlAppender`                            | 落盘字节 ≈ 事件本体字节（写放大 ≤1.6），compact 保证文件有界             | ❌ 用 `atomicWriteJson` 每条事件全量重写 → 写放大 = 状态大小/事件大小（数百~数千倍，9/2 事故：300GB 磁盘 / CPU 423%） |
| 状态快照（低频全量、整体替换、数据汇总） | `createWriteScheduler` + `atomicWriteJson` | 调度器保证节奏（防抖 + 最小间隔 + 串行），护栏兜底（1s/1MB），drain 可等 | ❌ 裸 `setTimeout` 防抖 + 手写 dirtyChain（各插件重复、易漏节流、测试只能 sleep 猜）；❌ 状态无字节上限               |
| 配置 / 用户显式保存                      | `atomicWriteJson` + `force: true`          | 人工操作低频且要求「点了就生效」，节流无收益；字节上限仍生效             | ❌ 用户 1s 内连续保存被节流窗口静默拒绝 → 配置丢失（dsh-my-notify 曾如此）                                            |
| 计数器型（O(1) 更新、无需跨会话累积）    | 内存维护 + 低频快照（≥10s）                | 快照频率低，写量可控                                                     | ❌ 每次计数变化都落盘                                                                                                 |

### 内存有界

| 场景                                        | 该用                                          | 反例                                                                                                                                     |
| ------------------------------------------- | --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 字典/表要有上界（会话表、路径表、失败记录） | `boundedMap`（默认 LRU）/ `boundList`（FIFO） | ❌ 无上限 `Record`/`Map`/数组：随运行时长线性增长（my-context 的 bySession 此前无上限）；❌ 自己写 `push` + `splice`（淘汰条数不可观测） |
| 需要「最近 N 条明细」                       | `boundList`（FIFO 保留最新）                  | ❌ 用 `boundList` 存审计明细（淘汰即丢数据，应落 jsonl）                                                                                 |
| 数组上的「访问即置新」                      | 改用 `boundedMap`                             | ❌ 对数组做 LRU 移动（O(n)/次，热路径性能陷阱）                                                                                          |
| 统计需要全量历史                            | 先聚合再淘汰                                  | ❌ 淘汰原始明细后再算累计值（统计口径被静默改变）                                                                                        |

> 淘汰是「静默丢数据」语义：上限必须**显式**（默认值只是兜底），并在需求清单「资源影响」栏写清「上限 × 单条大小 = 内存上界」。

### 写入调度

| 场景                                 | 该用                                                                 | 反例                                                                                                                                         |
| ------------------------------------ | -------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 变更后异步落盘（不需要写成功才返回） | `scheduler.schedule()` + `await scheduler.drain()`（测试/就绪）      | ❌ 测试用固定 `sleep` 等落盘（CI 高负载下 flaky，见 [踩坑：固定 sleep 等异步落盘导致 CI flaky](../踩坑/固定sleep等异步落盘导致CI-flaky.md)） |
| 进程退出 / teardown                  | `await scheduler.flush()`                                            | ❌ 直接 `clearTimeout` 后不写（丢最后一次变更）                                                                                              |
| 事件流                               | `jsonlAppender`                                                      | ❌ 用调度器把高频事件合并成一次「全量写」（正是写放大事故模式）                                                                              |
| 参数一致性                           | 调度器 `minIntervalMs` ≥ 落盘护栏 `minIntervalMs`（默认都是 1000ms） | ❌ 调度间隔 40ms + 护栏窗口 1s → 护栏拦下正常节奏（走重排，多一次重试且有丢状态风险）                                                        |

### 降级看门狗（资源超限自动降级）

持续运行逻辑（持久化 / 轮询 / 后台任务）必须有降级路径——**只告警不动作等于等人手动介入**（#126 复盘缺口 3）。

| 场景                        | 该用                                                                            | 反例（错误用法 → 后果）                                                                                     |
| --------------------------- | ------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 写放大 / 文件超限要自动停写 | `createResourceGuard`（`collect` + `onDegrade`/`onRecover`）                    | ❌ 各插件抄一份 resource-monitor（口径漂移、回调时序各异）；❌ 采样源做重活（递归扫目录）→ 监控自身成为热点 |
| 采样源                      | `createProcessSampler({ file })`（CPU/RSS/文件字节/写入速率）                   | ❌ 采样里做 O(n) 遍历；❌ 采样间隔 <1s（监控自身开销被放大）                                                |
| 判定                        | `evaluateResourceAlerts` / `shouldEnterDegrade` / `shouldExitDegrade`（纯函数） | ❌ 把「告警」当「降级」（CPU/内存峰值属于正常大请求，误停落盘）；❌ 一次超限就降级（抖动，必须连续确认）    |
| 降级动作（影响从小到大）    | L1 提高节流 → L2 停止落盘（内存有界）→ L3 事件降采样                            | ❌ 降级期间内存无界（恢复时把内存打爆）；❌ 恢复后不做全量快照（降级窗口的数据永久缺失）                    |
| 三态回归测试                | 注入 `collect` + `now` 的确定性序列（正常→降级→恢复）                           | ❌ 只用真实 fs + 墙钟测降级（15s 采样窗口让测试要么慢要么 flaky）                                           |

消费方示例：`plugins/dsh-my-observability/src/resource-monitor.ts`（采样源与降级动作由插件提供，状态机 / 判定 / 历史全部来自 shared）。

## 默认安全护栏（issue #198）

`atomicWriteJson` 不传 `options` 时：`minIntervalMs = 1000`、`maxBytes = 1MB`。被节流/超限一律 **warn + 计数**（`atomicWriteStats()` 读 `writes/bytesWritten/throttled/rejected/failed`）+ 可选 `onBlocked` 回调，绝不静默跳过。放宽必须显式：

```js
import { atomicWriteJson, atomicWriteStats } from 'dsh-shared'

await atomicWriteJson(file, state, logger, '[my-plugin]') // 默认护栏
await atomicWriteJson(file, state, logger, '[my-plugin]', { maxBytes: 8 << 20 }) // 状态自身有界 → 显式提高上限
await atomicWriteJson(file, state, logger, '[my-plugin]', { force: true }) // 退出前冲刷（字节上限仍生效）
console.log(atomicWriteStats()) // 资源观测
```

调用方接入现状（issue #198 第一/二批）：

| 插件                 | 接入方式                                                                                                                                                  | 行为变化                                                                                               |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| dsh-my-context       | `boundedMap`（会话数上限 20，LRU）+ `boundList`（每会话明细上限）+ `createWriteScheduler`（防抖 500ms / 最小间隔 1s）+ `atomicWriteJson`（显式 8MB 上限） | 会话数从此有界；写次数约减半；`store.whenPersisted()` 取代 sleep                                       |
| dsh-my-skill-manager | `createWriteScheduler`（同上）                                                                                                                            | 写次数与变更数解耦；`drainUsage()` 确定性就绪信号                                                      |
| dsh-my-notify        | `atomicWriteJson` 保存路径 `force: true`                                                                                                                  | 连续保存不再被 1s 节流吞掉；字节上限默认 1MB 生效                                                      |
| dsh-file-activity    | #197 已改 `jsonlAppender`（本次不动）                                                                                                                     | —                                                                                                      |
| dsh-my-observability | **第三批**：`createResourceGuard` + `createProcessSampler` 替换插件私有 resource-monitor（判定/状态机/ring buffer 全部来自 shared）                       | 行为等价（触发点/连续性/回调时序逐项一致，见 PR 证据）；新增 `stats()`/`history()` 与可注入采样源/时钟 |
| dsh-task-reliability | **第三批**：任务注册表写路径异步化（`fs/promises` + 写串行链）；teardown 保留同步尾写保证落盘                                                             | 防抖落盘不再阻塞事件循环（10MB 状态：阻塞 17ms → 调用 0.06ms）；读路径仍同步（启动一次）               |
| dsh-my-guard         | **第三批**：告警快照落盘改用 `atomicWriteJson`（紧凑 JSON + 4MB 显式上限 + 拦截计数）                                                                     | 快照体积不再被 pretty 缩进放大；超限被护栏拦下并 warn（不再静默写巨文件）                              |
