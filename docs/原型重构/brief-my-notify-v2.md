# 00-brief-v2 · dsh-my-notify 通知面板从零重做

> 用户明确要求：**完全不参考之前的页面**（旧原型、v2 骨架都不看），只搬功能。
> 本文件 = 新信息架构的设计输入。功能事实源：README.md、src/types.d.ts、src/notify/{vars,defaults,card,config}.ts、src/routes.ts。

## 1. 用户的三个真实场景（决定信息架构，而非功能清单）

| 场景 | 用户此刻在想什么 | 界面要让他几秒内做到 |
|---|---|---|
| **S1 配文案**「通知太吵/太哑，改一句话」 | 「我只想改『会话结束』这条长什么样」 | 找到事件 → 改标题正文 → 立刻看到效果 |
| **S2 配渠道**「这条要推到飞书群，那条别推」 | 「哪个渠道订了哪些事件、挂了没有」 | 一眼看到渠道路由矩阵 → 改订阅 → 试发一条 |
| **S3 看效果/排障**「刚才为什么没收到」 | 「发了没？发到哪？失败原因？」 | 看到最近投递与失败（含原因）→ 重试 |

> 三次场景里只有 S1 是「编辑」，S2/S3 是「看与判断」。旧页面把三者全塞进一列长表单，是它的根本问题。

## 2. 功能清单（只搬这些，布局自定）

5 类事件 end/ask/approval/subagentEnd/remote · 每事件独立标题+正文 · 32 个 {{ns.var}} + 7 个旧别名 · 五形态预览（系统通知 / toast / 飞书卡片 / 企微 / 钉钉）· 飞书卡片设计器（配色 / 字段 / 按钮 / @）· 渠道 CRUD + 订阅事件 + 加签 · 失败记录 + 测试发送 · 呈现配置（系统通知 / toast 位置时长堆叠 / 音效音色试听音量 / 免打扰时段 / 去重窗口）· 高级（apiToken / webBaseUrl / 远程触发 / 配置导入导出）。

## 3. 三版必须在四个维度上分歧

| 维度 | A 通知中心 | B 工作台 | C 分步向导 |
|---|---|---|---|
| 入口 | 全屏浮层（铃铛/侧栏底部进入），不进设置页 | **主区接管**（会话区变成工作台） | 设置页一级分类「通知」内 |
| 编辑↔预览 | 三栏画布：时间轴 / 编辑 / 预览画布叠层 | 上下堆叠：编辑区 + 底部五形态预览带 | 单列正文 + 右下浮动预览窗 |
| 事件切换 | **时间轴卡片流**（历史与草稿混排） | 左侧竖向事件列表 | 顶部分段 + 卡片**行内展开** |
| 变量交互 | **命令式**：输入 `{`/`@` 弹出可搜索面板 | 右侧常驻变量树（分组 + 拖拽把手） | 底部抽屉变量 chip 插入 |
| 主张 | 通知先是发生过的事，然后才是配置 | 一次看清全部五种形态 | 按配的顺序走一遍，降低同时面对全部配置的负担 |

## 4. 本步只做骨架

灰阶 + 单强调色，不雕版式细节、不做全量动效；只为选定方向。

## 5. 宿主真实画布约束（硬约束，B 版落地后补）

- 插件只有两个席位：settings.plugins.tab（设置页页签，宿主弹层 1120×740，减左侧 220 分类导航后内容区约 860×700）与 sidebar.right.pane.tab（右侧栏，380 宽）。
