# 官方文档 · 插件开发接入速查

> 链接分支统一用 `master`：上游 `deepseek-ai/deepseek-harness` 的默认分支是 `master`，把路径里的分支段写成 `main` 会 404。

## 一、先选形态

| 形态 | 什么时候用 | 官方入口 |
| --- | --- | --- |
| 工具型 | 给模型加一个可调用能力 | [开发一个工具](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/develop/basic/tool.zh.md) · [工具编写参考](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/cookbook/adding-a-tool.zh.md) |
| 浏览器侧插件 | 侧边栏页签、设置卡片、工具/聊天自定义渲染（跑在 Web Client 里，注册到 keyed slot） | [设置卡片](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/cookbook/adding-a-settings-card.zh.md) · [机制映射表](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/cookbook/extension-cookbook.zh.md) |
| 纯 server | 只做事件订阅 / 服务提供方 / 远端 API，不出 UI | [插件与生命周期](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/develop/framework/index.zh.md) · [事件系统](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/develop/framework/events.zh.md) |
| 不确定放哪 | 判断「新行为归属哪个扩展点」 | [architecture](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.zh.md)（新行为的归属位置）+ [capability-seams](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/capability-seams.zh.md)（可替换能力 seam 一览） |

先窄后宽：单形态一个包就够，只有角色需要独立演进（定义 / 提供方 / 消费方分离）时才拆包。

## 二、最小可跑骨架（从 0 到被 dsh 加载）

```sh
mkdir -p scratch-plugin/src          # 1. 建目录（插件 = 导出 apply 的 TS 模块）
pnpm dsh web --patch ./scratch-plugin/cordis.yml   # 2. 带 overlay 启动，打开 http://127.0.0.1:3080
```

两个关键文件：

- `scratch-plugin/src/my-plugin.ts`：`export const name = 'hello-plugin'` + `export function apply(ctx) { console.log('loaded!') }`；要用宿主服务就加 `export const inject = ['tools']`（Cordis 会等依赖就绪才 apply）。
- `scratch-plugin/cordis.yml`：`- insert: [{ id: hello, name: '/绝对路径/scratch-plugin/src/my-plugin.ts' }]`。**插件路径必须绝对路径**，patch 文件只贡献配置、不改变 loader 的模块解析目录。

判据：启动终端打印 `[hello-plugin] plugin loaded!`。`Ctrl+C` 关闭时插件树最多 5 秒完成 dispose（`SIGINT` 退出码 130，`SIGTERM` 为 0）。

详见[第一个插件](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/develop/basic/index.zh.md)。

## 三、注册与挂载

注册动作（对照[机制映射表](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/cookbook/extension-cookbook.zh.md)找宿主扩展点）：

| 要做什么 | 注册点 |
| --- | --- |
| 加工具 | `ctx.tools.register(defineTool({...}))`，插件 `inject = ['tools']` |
| 对外提供服务 | `class X extends Service`，`super(ctx, 'myService')`，消费方 `inject = ['myService']` |
| 订阅/拦截 | `ctx.on('tools/result' \| 'session/event' \| 'agent/*', ...)`；waterfall 类监听器**必须调 `next()`**，不调即短路 |
| 挂子插件 / 自定义资源 | `ctx.plugin(child)` / `ctx.effect(() => cleanup)` |

配置项：导出 `Config` 类型 + **同名 Schemastery schema**，默认值写在 schema 里；凡是不同部署可能取不同值的参数都必须做成配置字段（判据：能否在 `cordis.yml` 里改而不动代码）。不要导出普通对象当 `Config`，它不满足 Standard Schema 接口，会在加载时报错。

挂载两条路：

- 临时/调试：`--patch ./x.cordis.yml` overlay。
- 长期：`dsh plugin --profile demo add ./hello-plugin`，然后 `dsh --profile demo --dump-config` 确认出现该层（应看到 `# == dsh-hello-plugin`）；`remove` 会同时删依赖与层。

层序（后应用者胜，且 patch **整键替换**目标的 `config`，不深合并）：各 bundle patch（按 `dsh.profile.bundles` 顺序）→ profile 的 `cordis.patch.yml` → `$DSH_HOME/cordis.patch.yml` → 各 `--patch` overlay。推论：覆盖别人的行必须重述该行需要的每个键。

`cordis.yml` 里只有插件 `config` 与条目 `disabled` 支持 `!!js`（绝不写 `!js`）；按环境选条目请用 overlay，别在插件代码里写分支。

详见[插件配置](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/develop/basic/config.zh.md)、[服务与依赖](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/develop/framework/service.zh.md)、[CLI 参考](https://github.com/deepseek-ai/deepseek-harness/blob/master/apps/cli/reference/README.zh.md)。

## 四、热更新 / HMR 与重载

| 改了什么 | 怎么生效 |
| --- | --- |
| 插件源码（server 侧） | 加载 `@deepseek-ai/cordis-plugin-hmr` 时改文件即自动「卸载旧实例 → 加载新代码」；**前提是注册都走 `ctx.effect`/`ctx.on`** |
| `cordis.yml` 里某行的 `config` | 触发该插件热替换（旧实例卸载、注册随 effect 清理） |
| profile / home 的 `cordis.patch.yml` | `patchReload: live`（web 与自定义 profile 默认）监视并事务性重应用；`startup`（headless/sdk/sdk-minimal/acp）只应用一次 → **改配置必须重启** |
| 浏览器侧代码（client bundle） | 客户端 HMR 接收器始终挂载，但需同一检出里跑 `pnpm run dev:web` watcher 重建 bundle 才免刷新；否则重新构建 + 刷新页面 |
| 远端 API 的签名 / 码表 / namespace / 导出名 | 必须重跑 `pnpm run build:lib`，Client 才拿到新声明与 codec；只改实现体不用重建 |

- 手工注册（没经过 `ctx.effect`）不会被 reload 撤销 → 症状「改了代码老行为还在」。
- 工具注册后不要改 schema 或替换回调；要换实现就 dispose 所属 effect 再注册替代品。
- 必需服务消失时依赖方自动 dispose，服务恢复后自动重载 → 症状「插件突然不生效」先查提供方是否还挂载。

## 五、调试入口

- **确认插件真被加载**：`apply` 里的 `console.log` 会打到启动终端；再看配置树 `dsh web --dump-config` 或 `dsh --profile web --dump-default-config`（注释标注每行来自哪个文件、被哪些 overlay 改过；找不到目标的 patch 报 stderr）。`--dump-*` 不启动应用、不跑应用参数提供方。
- **加载不动**：`inject` 声明的服务没就绪 → Fiber 停在 PENDING；`apply` 抛异常 → FAILED（看终端错误栈）。两种都要顺藤查提供方是否在同一配置树里。
- **配置没生效**：先分清 profile 是 `live` 还是 `startup`，再确认改的是生效层（同名行被后面的层整键覆盖）。
- **patch 的 `name` 解析**：相对插件名以 patch 文件所在目录解析；`--patch` 的路径按调用目录解析。
- 日志级别开关与运行时日志目录在官方文档中没有权威说明，别照猜的路径找；需要时看[testing](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/testing.zh.md) 与[CLI 参考](https://github.com/deepseek-ai/deepseek-harness/blob/master/apps/cli/reference/README.zh.md)。

## 六、发布

- **两种 manifest 别搞混**：包里 `dsh.bundle.patch` → 组合包（回答「贡献什么」）；profile 里 `dsh.profile.bundles` → 启动组合（回答「由哪些包按什么顺序组成」）。没有 `dsh.bundle` 的包能装但只当普通依赖：`dsh plugin` 打警告、不激活任何层（症状：装上了没生效）。
- **组合包最小形态**：`package.json`（`type: module`、`files` 含入口与 `cordis.patch.yml`、`dsh.bundle.patch`）+ `cordis.patch.yml`（插件行按**包名**引用，不是相对源码路径）+ 入口模块。
- **安装**：`dsh plugin --profile <name> add <spec>` 在 profile 目录内转发给 pnpm（`add`/`remove`/`update`/`why` 都可用）；相对 spec 先锚定到调用目录。
- **从 git 装的坑**：pnpm 拉的是源码、不跑 `build`，TypeScript 包会因缺 `lib/` 而加载失败。作者必须提供**自包含**的 `prepare`；用户要在该 profile 的 `pnpm-workspace.yaml` 里 `allowBuilds: { <包名>: true }` 授权，然后重跑 `add`。该授权等于允许包代码在安装时于本机执行（不在 agent 沙箱内），只对可信源码授权并锁定 commit（`github:you/hello-plugin#<sha>`）。
- **不想让用户授权**：`npm publish`（发布前构建好 `lib/`）或 `pnpm pack` 出 tarball 后 `dsh plugin --profile demo add ./x-0.1.0.tgz`。
- **会话格式/持久化改动**：结构变更需要确认记录，`same-version` 与 `version-bump` 判定见[持久化变更](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/persistence-changes/README.zh.md)；升版本要走[adding-a-session-format-version](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/cookbook/adding-a-session-format-version.zh.md)。

详见[打包与安装插件](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/develop/basic/publish.zh.md)。
