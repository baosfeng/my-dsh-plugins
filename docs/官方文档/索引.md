## 二、知识图谱（查 API 与契约的首选）

```bash
CBM=~/.local/bin/codebase-memory-mcp
P=Users-bsfeng-IdeaProjects-deepseek-harness

$CBM cli search_graph --project $P --query "defineTool"     # 定位符号 → 限定名 + 文件:行
$CBM cli get_code_snippet --project $P --qualified-name "<上一步返回的 qn>"   # 读实现片段
$CBM cli trace_path --project $P --function-name "<完整 qn>" --direction outbound --depth 2   # 调用链
$CBM cli search_code --project $P --pattern "Loader 配置"   # 正文 / 中文检索
$CBM cli get_architecture --project $P --aspects all        # 架构概览
```

**三个实测实例**：

1. **符号定位**：`search_graph --query "defineTool"` → `packages/core/tools/src/schema.ts:545-617 Function`；再 `trace_path` 得 7 个 callees。
2. **补官方文档盲区**（有定义点、但没有子系统页的服务）：`ctx.webRuntime` 官方 docs 无对应页，服务提供点在参考源 `packages/bundle/web-app/src/index.ts:38` + `:231 ctx.provide(WEB_RUNTIME_SERVICE, runtime)`。这类"官方答不了"的项（见 [本仓库重点](本仓库重点.md) 第一节）只能靠图谱或读源码。
3. **契约由源码判定**：`grep -rn "turn-stopping" packages/core/agent-loop/src` → `agent.ts:317` 是 `dispatch.serial('agent/turn-stopping', …)`，**直接证明**它是 serial 事件、没有 `next()`。官方事件页只列事件名，不给 serial/parallel 契约——这类语义必须回源码。

> **图谱 0 结果 ≠ 不存在**：只看 `--query` 会**误判**——实测 `pluginInventory` / `documentPreviews` / `sidebarRightTabs` / `logger` 这些**真实存在**的服务名，`search_graph --query` 一律返回 0（BM25 按名字相关度打分，服务名往往不是符号名）。**四个通道全空**才判「不是宿主能力」：
>
> ① `search_graph --query "<名>"`　② `search_graph --name-pattern "<名>"`　③ 参考源查注册点 `grep -rn "provide('<名>'\|super(ctx, '<名>')" /Users/bsfeng/IdeaProjects/deepseek-harness/packages`　④ **本机运行包**里 grep `~/.npm-global/lib/node_modules/@deepseek-ai/dsh/`。
>
> 另外：索引按设计排除 `vendor/`（cordis 框架源码，查它只能 grep），`parse_partial` 文件还可能漏符号（`index_status` 可查）。实测 `ctx.bundler` 属四通道全空的那一类（见 [本仓库重点](本仓库重点.md) 第一节）。

> **重建索引**：官方参考源用 `node scripts/harness-ref.mjs --index`；**本仓库自身**的索引用 `npm run index:self` 重建、`npm run index:self --status` 查新鲜度——过期索引会把「没搜到」变成错误结论（实测曾落后 3 周 / 509 个提交、节点数只有 full 的 1/7）。

## 三、正文与中文检索：grep 参考源

图谱只覆盖符号与结构；**读文档正文、查中文、查 `vendor/`** 用 grep（100% 覆盖，最可靠）：

```bash
cd /Users/bsfeng/IdeaProjects/deepseek-harness

ls docs/subsystems                               # 子系统页清单（文件名即子系统名）
grep -rn "关键词" docs --include=*.zh.md         # 全库搜中文文档
grep -n "工具名\|配置键" docs/tool-catalog.zh.md docs/config-catalog.zh.md   # 生成式目录检索
grep -rn "ctx\.tools" packages --include=*.ts    # 查实现（比读文档更权威）
```

> `tool-catalog` / `config-catalog` / `persistence-catalog` / `module-graph` 是**生成物**：不要通读、不要手改、不要整篇复制进本仓库。
>
> 图谱的 `--semantic-query` 对**中文查询效果一般**（返回不相关），别依赖它。

## 四、引用官方文档时的两个坑

- **中文文档的锚点是中文 slug**：锚点由标题文本生成，往 `.zh.md` 上挂英文锚点（如 `#loader-configuration`）必然失效。要精确跳小节就链英文 `.md`，否则只链文件、不写锚点。
- 唯一例外：子系统页的生成区有显式锚点 `<a id="cordis-surface"></a>`，中文页同样可用 `#cordis-surface`。
