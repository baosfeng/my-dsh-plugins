# 插件调试排障速查（官方文档精编）

> ⚠️ **何时阅读：** 插件行为异常、且不想靠猜时。先按「一」钉住四个事实，再到「二」按症状取根因方向。
>
> 链接前缀均为 `https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/`（中文版 `.zh.md`）。

## 一、定位起手式：四个事实，缺一个就别往下猜

**0. 先钉住身份：哪个进程、哪个 origin、哪个源码树。** 官方事故复盘里最贵的一次错误，就是验收了另一个服务器而非当前 GUI。

- 当前 GUI 的规范 URL 由宿主发布，不要猜端口：shell 变量 `$DSH_WEB_URL`（与 `app:web-surface` 提示词区段同源）。
- 组合树与层序：`dsh --profile web --dump-config`（profile 组合包 → `cordis.patch.yml` → home → `--patch` overlay）；装插件只走 `dsh plugin --profile web add <包>`。
- 要改宿主行为/替换能力实现时，先定 seam 三角色（Service Definition / Provider / Consumer）再动手，别按名字猜服务：见 [capability-seams](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/capability-seams.zh.md) 与 [subsystems/README](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/README.zh.md)。

**1. 插件是否加载。** `dsh web` **先监听端口、后加载插件树**——端口能回 HTTP 不代表插件树活着。

- 启动日志 grep 致命串：`plugin tree failed to load`、`entry did not activate`、`without inject`、`cannot get property`、`in inactive context`、`missed the module table`、`window.__DSH_BOOT__ is missing or not an object`。
- 真实 Loader 路径冒烟：`packages/test-support/loader-smoke`（从 bin + `cordis.yml` 起隔离 cwd，附带捕获输出）。

**2. 进程是否活着。** 「端口有响应」≠「应用就绪」：裸 Vite 同样返回 200。

- 就绪需三条同时成立：端口有 HTTP 响应 + 日志出现正向就绪行 + 进程仍存活。
- 长驻进程一律用受管后台任务，**不要** shell `&`：任务身份、完成通知、结果收集与清理都会失效。

**3. 前端是否拿到模块。** 浏览器 console 是唯一现场。

- `window.__DSH_BOOT__` 缺失或非对象 ⇒ 页面没拿到宿主注入的启动图（白屏常态）；它只由完整宿主注入。
- 模块路由 `/plugins/??<包A>/client.js,<包B>/client.js&rev=<rev>`：404 = 未知/被改的资源列表、缺 revision 或**陈旧 revision**；405 = 方法不对。
- 插件进表条件：`package.json` 声明 `dsh.client`（`platform: 'web'`）且有 `exports["./client"]` 构建产物。

**4. 事件是否发出。** 先定事件域，再查对应载体。

- 三个事件域选一个：持久**会话事件**（`session/event`，落日志）/ 实时 **`agent/*`**（携带活跃 Agent）/ **能力事件**（`fs/*`、`tools/*`）。waterfall 监听器不调 `next()` 就断链；scoped 事件只投给 scope 匹配者。
- 持久事实查会话日志：`$DSH_HOME/sessions/<cwd 转义目录>/<sessionId>/session.jsonl[.zstd]`（v1 起为 `session.vN.jsonl`）。

## 三、事故复盘的通用判据（四条真实事故提炼）

- 单元测试全绿、100% 行覆盖，都不证明功能按交付方式可用——覆盖率只证明行被执行过。
- 手动 `ctx.plugin({ name, inject, apply })` 挂载绕过 Loader 的导出归一化与真实调用拓扑，两个 bug 因此同时逃逸。
- 必须至少有一个测试走真实入口路径：真实 Loader、真实 app/process、构建后的 `lib/`。
- 用跟踪结果推翻优雅理论：插桩 fiber 遍历、跑真实子进程，别停在「合理解释」上（同一错误串背后可以是两个独立 bug）。
- HTTP 200、构建成功、启动 manifest 是三个不同事实；验收要指定确切 origin，并从外部观察改动是否在该 origin 生效。
- 替代服务不能证明既有页面已变；长驻进程必须走受管任务生命周期，而不是 shell `&`。
- 语法上被接受的配置值不保证在该位置被求值：要记录并验证**哪些字段**被插值。
- 快照刷新是 fixture 的生产过程，不是正确性审查；`UNKNOWN_TOOL` 这类语义上不可能的结果必须独立断言。
- 进程归因要多证据合取（退出码门控 + 致命行 + 精确排除信息行），共享前缀不是协议。
- 适配器必须保留下层 seam 的结构化失败，不能用自身最接近的通用类别把它替换掉。
- 会自行跳过的真实内核/无密钥测试无法固定回归；平台相关行为需要确定性模拟 + 一条组装后的产品路径。

## 四、防御性写法（官方「来之不易的缺陷类别」精选）

- **正交结果独立上报**：`timedOut`、`signal`、`exitCode` 各自上报，别把一个标志嵌套在另一个标志的分支里。
- **公共约定两侧都遵守**：收到同一结果的多表示时，先在公共 API 边界规范化再返回，并在类型定义处写明约定。
- **异步状态不是同步状态**：`agent/status`、`whenIdle()` 不能当作某次 `followup()` 的结果；由自动化调用方显式定义区间，并处理「无需等待」分支。
- **dispose 必须达到完全停稳**：清理要等待子进程真正退出，并在终止前关闭监听器/通知注册表，让迟到完成事件保持静默。
- **分发器里隔离回调异常**：try/catch 包分发循环并记日志；一个抛错的订阅者不得 reject 该 promise，也不得饿死后续监听器。
- **不把环境变量或可预测路径暴露给不可信输出**：启动命令前清理 `*KEY*`/`*SECRET*`/`*TOKEN*`/`*PASSWORD*`；临时/spill 文件放 0700 私有目录，随机名 + `'wx'`/`0o600`。
- **链接形态路径用 unlink 删除**：先 `lstatSync().isSymbolicLink()` 判断再 `unlinkSync`；真实目录才用带 `recursive` 的 `rmSync`。

出处：[defensive-patterns](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/defensive-patterns.zh.md)。

## 五、写测试来定位

- 分层与命令：`pnpm run test`（包内 `tests/**`）/ `test:coverage`（`packages/*/*/src` 逐文件 100%，未覆盖行常是死代码）/ `test:e2e`（带密钥，缺 key 自动跳过）/ `test:expected`（无密钥组装 CLI·进程预期）/ `test:snapshot`（录制回放）/ `test:web`（Chromium，CI 强制 `DSH_SNAPSHOT=replay`）。
- 三条硬要求：**测试真实入口路径**（产品可见插件必须有非单元的真实组合测试）；**验证外部世界而非自我报告**（重新跑命令、重读文件，断言未修改文件逐字节一致）；**只 mock 开销高或不确定的边界**（LLM 适配器、网络、时钟），下游保持真实。
- e2e 自管资源：`afterEach` 里 dispose（失败/重试/超时也要释放）；共享 fixture 放普通 `tests/harness.ts`，绝不放进另一个 `*.e2e.ts`（导入会重复注册 `describe`）。
- 解析只到源码：vitest 一律经 `tsconfig.base.json` 的 `paths` 解析到 `src`，避免陈旧 `lib/` 造成第二份模块单例；构建产物只在显式 `lib` 模式与构建冒烟里用。
- 夹具在哪：包内 `tests/**`；profile 集成 `apps/cli/tests/profiles/`；录制会话 `snapshots/{session,sdk,acp,web}/`；仅 UI 预期 `apps/web/tests/expected/`；无录制预期 `tests/expected/` 与 `*.expected.e2e.ts`；共享快照规则 `packages/test-support/session-snapshot/`；真实 Loader/子进程夹具 `packages/test-support/loader-smoke/`；桥接 harness `packages/acp/acp/tests/harness.ts`（`makeBridgeHarness()`）。

出处：[testing](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/testing.zh.md)。
