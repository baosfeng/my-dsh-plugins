# 发版与打包流程

> ⚠️ **何时阅读：** 发版前必读（含批量发版与发版失败排查）。
> 目标：**一次发版 = 版本 bump + CHANGELOG + GitHub Release + npm 发布全部自动完成**。可自动化部分已沉淀到 `scripts/release.mjs` 与 `.github/workflows/`，本文只记录必须人工判断的规则与踩坑。

## 发版方式（二选一）

**方式 A：GitHub Actions（推荐）**——仓库 Actions → **Release (auto)** → Run workflow，填 `plugins`（一个或多个插件目录名，**逗号或空格分隔**）+ 选 `bump`（patch / minor / major）。输入先过白名单校验（允许值 = 仓库 `plugins/` 目录运行时读取，非法名 fail-fast 并列出允许值）。两个 run（Release (auto) + Release）全绿即完成。

**方式 B：本地命令**

```bash
node scripts/release.mjs <插件名> --bump patch --push   # bump + CHANGELOG + 同步文档 + tag + push
node scripts/release.mjs <插件名> --push                # 版本已手动改好时：只校验 + 测试 + 同步文档 + tag
node scripts/release.mjs a b c --bump patch --push      # 批量（共用同一 bump 类型）
node scripts/release.mjs a --bump patch                 # dry-run 预览（不提交）
node scripts/release.mjs a --bump patch --push --skip-real-verify --skip-reason "批量回归测试"
```

- `--push` 缺省为 dry-run；**跳过真实环境验证必须带 `--skip-reason`**（无理由 exit 1）。
- 批量：每个插件独立过完整门禁（一个失败不影响其他），成功后一次提交 + 逐个打 tag，再**逐个推 tag**（一次 push 只带一个 ref——一次推 N 个 tag 会被 GitHub 合并/丢弃 push 事件，实测零触发），推完逐个**确认触发**（没触发即报错 + 给补救命令，不再干等 post-release 超时），最后汇总失败插件与**失败门禁编号**。
- 并发只改顺序与耗时，**不改判定**：任一插件任一子门禁失败 → 该插件失败 → exit 1。`--concurrency N` 可覆盖（上界 8）。
- 用法错误 exit 2（无参数 / 非法名 / 非法 `--bump` / `--all-checks` 与 `--push` 冲突 / 缺 `--skip-reason`），环境错误 exit 1。

## 版本号规则（semver）

- **patch**：修复 / 内部重构（行为不变）；**minor**：新功能，以及 `0.x` 阶段的不兼容变更（如包名改名）；**major**：`>=1.0.0` 的不兼容变更。
- 每次发版必须更新 CHANGELOG（`--bump` 自动从 git log 生成段落，可事后补充详情）。
- 代码内硬编码的版本常量一并同步；**tag 版本必须与 `package.json` 版本一致**（workflow 强校验，比较的是不带 `v` 的裸版本号）。

## 门禁清单与判据

| 编号 | 门禁                  | 判据要点                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ---- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1a   | npm latest 防降级     | 新版本不得低于已发布的 npm latest                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| 1b   | peer 依赖             | `peerDependencies.cordis` 已声明且 major 与其他插件一致（npm 分发后缺失会导致安装失败）。**豁免**：`dsh.kind=preset` + 非空 `dsh.presetReason` 的 agent preset 资产包（不挂 profile、无 `cordis.patch.yml`）                                                                                                                                                                                                                                                                                                                                                       |
| 1c   | 跨插件依赖            | client/server 端 `require('dsh-*')` / `import` 的包必须在 `peerDependencies` 或 `dependencies` 声明；声明的仓库内 dsh-* 必须已发布 npm **且**已打 tag —— **依赖先发版、依赖方后发版**；npm view 404 直接阻断。扫描前先做轻量词法扫描剔除注释与字符串/模板/正则字面量里的示例 require                                                                                                                                                                                                                                                                               |
| 1c   | `dsh.client.external` | 每个 external 项必须在 dependencies 或 peerDependencies 声明；**仅在 peerDependencies** 时还必须同时在 `dsh.client.externalDegraded` 里声明降级路径（external 缺包时整条 client factory 抛错、插件 UI 全挂）。**不要求"移进 dependencies"**：`dsh plugin add` 只把 profile 直接 dependencies 里声明 `dsh.bundle.patch` 的包写进 profile bundles，插件自己的 dependency 只被铺到 `profile/node_modules`，不会激活 → 移进 deps 只是形式合规                                                                                                                          |
| 1d   | 包发布卫生            | ① `exports`（递归所有条件值）/ `main` / `types` / `dsh.bundle.patch` 指向的文件必须真实存在；② `dsh.*` 自洽（声明 `dsh.client` ⇒ `platform === 'web'` 且 `exports["./client"]` 存在，反之亦然；有 `cordis.patch.yml` ⇒ 必须声明 `dsh.bundle.patch`；有 `lib/client.js` ⇒ 必须有 `exports["./client"]` + `dsh.client`）；③ `npm pack --dry-run --json` 内容断言：README / CHANGELOG / LICENSE / package.json 与所有声明目标必须在包里，`test/` `src/` `coverage/` `reports/` `node_modules/` 不得在包里；④ README 引用的 assets 必须存在**且随包发布**。fail-closed |
| 3    | 测试                  | 插件 `npm test` 全绿                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| 3b   | 效果图                | README 引用的截图文件真实存在（`./assets/` 相对路径或 `https://unpkg.com/<包名>/assets/...`）。**无用户可见 UI 的插件**按 `package.json` 的 `dsh.ui=false` + 非空 `dsh.uiReason` 豁免（`dsh.kind=library` 沿用原豁免）                                                                                                                                                                                                                                                                                                                                             |
| 3c   | 真实环境验证          | `node scripts/verify-real-profile.mjs --addons plugins/<名> --clean-externals`，失败即阻断发版（详见下节）                                                                                                                                                                                                                                                                                                                                                                                                                                                         |

- `--all-checks`（仅 dry-run）：静态门禁全部跑完再统一报告失败项，避免 fail-fast 让后续门禁"从未执行"；`--push` 仍走首个失败即停。
- 门禁 1d 与 3b 互补：3b 只查"README 引用的文件在仓库里存不存在"，1d 查"文件存在但 `files` 白名单没带它"。**README 图在 npm / unpkg 上裂图 = `files` 白名单缺 `assets`**，修法是给 `files` 补 `"assets"`。
- 选型备忘：不引入 `publint`（只覆盖 ①，不认识 `dsh.*` 字段与 DSH 打包面，且在本仓库形态下恒定产生噪声）；①的判据已按它的实测行为等价实现。

## 3c 真实环境验证的精确语义（踩坑修法）

- **"就绪"必须三条件同时满足**：端口有 HTTP 响应 **+** 实例日志出现正向就绪行（`dsh web: http://127.0.0.1:<port>/?token=…`）**+** 进程仍存活。`dsh web` 先监听端口、后加载插件树，只看"端口回了 HTTP"会把"实例整个起不来"报成就绪。
- 全程扫描致命启动特征（`plugin tree failed to load` / `failed to apply|import loader entry` / `without inject` / `cannot get property` / `missed the module table` / `duplicate loader entry`），命中即 exit 1 并打印崩溃栈关键行 + 隔离实例日志路径。**崩溃证据在隔离 `DSH_HOME/dsh-web.log`**（实例 stdout/stderr 落盘）——排查时先读它，崩溃栈可能晚于脚本读日志才落盘。
- **端口占用 fail-closed**：启动前 `isPortInUse` 预检，端口被占直接报错，绝不把他人实例的响应当验证结果（否则会"0.2s 秒过"）。
- **缺包演练（`--clean-externals`）**：从 `--addons` 的 `dsh.client.external` 推导缺失集合，该集合既不复用真实 profile、也不做 addon 链接，**并同时从隔离 profile 配置（`dependencies` + `dsh.profile.bundles`）剔除**——只删 node_modules 会得到"配置列着却装不上"的不一致状态，boot 阶段 `cannot resolve profile bundle` 直接起不来。启动前 `checkOmittedAbsent` 校验"确实不可解析"。
- **清单留痕幂等**：`--checklist` 对已存在的目标清单**幂等合并**（人工「验证记录」段与已勾选 `[x]` 逐字节保留、头部时间/端口保持原值，换端口重跑零 diff），只刷新自动项；需要把本轮环境写进头部时加 `--refresh-header`。重跑（复验 / 换端口复现 / 排查 flaky）是正常操作，不该"一跑就丢证据"。
- **并发发版**：`verify-real-profile.mjs` 没有信号清理，中途强杀会残留实例与 `/tmp/dsh-verify-real-*`，因此并发门禁**必须 await 完**才退出；端口由调度层用 `findFreePorts` 预分配互不相同的值。
- 边界：client 侧渲染崩溃发生在浏览器运行时，server 日志未必留痕——这一项仍需浏览器步骤兜底（`verifying-dsh-plugins` skill）。

## 打包内容（npm pack）

- 发布内容 = `package.json` `files` 字段 + 默认项（README / CHANGELOG / LICENSE / package.json）；各插件 `files` 含 lib、assets、cordis.patch.yml 等。
- 预览：`cd plugins/<名> && npm pack --dry-run`（tarball 内容清单，防 secrets 泄露）。
- 判定口径是「**被已发布面引用才必须在包内**」，不是"不在 `files` 就报警"：构建期输入（`vendor/`）、`src/`/`test/`/`scripts/`、共享包的 splice 源都不被已发布面引用 → 只作为 info 列出。

## 发布通道

| 通道           | 触发                                                     | 说明                                                                                             |
| -------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| GitHub Release | tag 推送（`release.yml`，**一个 tag 一套 workflow**）    | 自动打包 tgz + CHANGELOG 段落作为 release notes；同 tag 有 `concurrency` 串行兜底                 |
| npm 官方       | tag 推送（`release.yml` 内）                             | 需仓库 `NPM_TOKEN` secret；未配置时仅警告跳过                                                    |
| 本地手动 npm   | `npm publish --userconfig "$NPMRC" --registry "$NPMREG"` | 见 npm-ops skill（token 管理 / registry 覆盖 / 2FA）                                              |

## 常见失败与修法

| 现象                          | 原因 / 处理                                                                              |
| ----------------------------- | ---------------------------------------------------------------------------------------- |
| `git tag` 已存在              | 该版本号发过版（tag 指向旧代码）→ bump 到新版本号；**不要 force 覆盖旧 tag**             |
| release workflow 版本校验失败 | tag 指向的提交里 `package.json` 版本 ≠ tag 版本 → 必须先提交 bump 再打 tag               |
| npm `ENEEDAUTH`               | 环境变量 `npm_config_registry`（镜像）覆盖配置 → 用 `--userconfig` + `--registry` 双参数 |
| npm `E403` 2FA                | 用 bypass 2FA 的 Granular Access Token；或 `--otp=<验证码>`（30 秒时效，多包易超时）     |
| npm `E409` staged version     | 版本已发布/部分发布 → `npm view <pkg> versions` 确认后 bump 再发                         |
| 插件名写错 / 用旧名发版       | Actions 入口白名单 fail-fast 报 `非法插件名`；本地脚本报 `plugins/<名字> does not exist` |
| 发版后文档不同步              | `node scripts/check-docs.mjs` 已强制（根 README 插件表 / docs 索引与模块 / 安装章节）    |
| 远端 tag 齐全但零 run | tag 被一次性批量推送（push 事件被合并/丢弃）→ `release.mjs` 改为**逐个推 + 逐个确认触发**；已推上去却没触发时按提示「删远端 tag → ≥5s → 重推」 |
| `Error saving asset` / `Error uploading` / 输出 HTML 错误页 | 两套 release workflow 并发抢建同一个 Release → 只保留 `release.yml` + 同 tag `concurrency` 串行；**先核对 Release/npm 交付物是否到位，再决定是否重发** |
