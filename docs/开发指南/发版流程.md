# 发版与打包流程

> 目标：**一次发版 = 版本 bump + CHANGELOG + GitHub Release + npm 发布全部自动完成**。
> 本文档是流程说明；可自动化部分已沉淀到 `scripts/release.mjs` 与 `.github/workflows/`（见下文"自动化覆盖"），文档只记录必须人工判断的规则与踩坑。

## 发版方式（二选一）

### 方式 A：GitHub Actions 自动发版（推荐）

1. 仓库 **Actions** → **Release (auto)** → **Run workflow**
2. 填写 `plugins`（一个或多个插件目录名，多个用**逗号或空格**分隔，如 `dsh-md-render,dsh-my-guard`）+ 选择 `bump`（下拉**单选**：patch / minor / major）
   - `plugins` 是**文本框**（`type: string`），不是下拉：GitHub Actions 的 `choice` 只渲染单选下拉、原生不支持 `multiple`，要一次发多个只能用文本分隔（issue #204）
   - 输入先过白名单校验（允许值 = 仓库 `plugins/` 目录，运行时读取，不硬编码清单）：写错/改过名的插件名直接 fail-fast 并列出全部允许值，不会带着错名字发版
3. 自动完成：
   - `release.mjs --bump`：版本 +1、从 `git log <prev-tag>..HEAD` 生成 CHANGELOG 段、提交
   - 同步根 README 插件表（AGENTS.md 版本行，如存在）
   - 打 tag `<插件>@v<新版本>` 并推送 → 触发 `release.yml`
   - `release.yml`：npm test 门禁 → 创建 GitHub Release（tgz 资产）→ **npm 自动发布**（读仓库 `NPM_TOKEN` secret）
4. 等 Actions 两个 run（Release (auto) + Release）全绿即完成

### 方式 B：本地手动（等价命令）

```bash
node scripts/release.mjs <插件名> --bump patch --push   # bump + CHANGELOG + 同步文档 + tag + push
# 或版本已手动改好时：
node scripts/release.mjs <插件名> --push                # 只校验 + 测试 + 同步文档 + tag
```

> `--bump` 可选 patch | minor | major；`--push` 缺省为 dry-run（只校验不提交）。release.mjs 会跑 npm test（门禁：测试全绿 + 截图引用有效 + 跨插件依赖校验 + 真实环境验证）。

### 批量发版（一次发多个插件）

支持一次发版多个插件，所有插件共享同一个 bump 类型：

#### GitHub Actions 批量发版

1. 仓库 **Actions** → **Release (auto)** → **Run workflow**
2. 在 `plugins` 输入框填多个插件目录名，**逗号或空格分隔**（`dsh-md-render dsh-my-guard` 与 `dsh-md-render,dsh-my-guard` 等价，换行/中文逗号也认），再选 `bump` 类型（下拉单选，所有插件共用）
   - **UI 能力边界**：`plugins` 是文本框（可填多个），`bump` 是单选下拉。GitHub Actions 原生不支持下拉多选（`type: choice` 无 `multiple`），所以批量只能走文本分隔（issue #204）
   - **输入校验**：非法/拼错的插件名 fail-fast——报 `非法插件名: <名字>` 并列出全部允许值（运行时 `ls plugins/`，与目录不可能漂移）；重复名字自动去重
3. 自动完成：
   - 每个插件独立校验门禁（一个失败不影响其他）
   - 所有成功插件一次提交 + 逐个打 tag + 推送
   - 失败报告汇总所有失败插件

#### 本地批量发版

```bash
# 批量发版多个插件（统一 bump 类型）
node scripts/release.mjs dsh-file-activity dsh-my-observability --bump patch --push

# dry-run 模式预览（不提交）
node scripts/release.mjs dsh-file-activity dsh-my-observability --bump patch

# 跳过真实环境验证（需提供理由）
node scripts/release.mjs dsh-file-activity dsh-my-observability --bump patch --push --skip-real-verify --skip-reason "批量回归测试"
```

#### 批量发版特性

- **独立校验**：每个插件独立执行完整门禁（版本检查、依赖校验、测试、截图校验等），一个插件失败不影响其他插件
- **统一提交**：所有成功插件的变更一次提交（避免多次 commit 污染 git 历史）
- **顺序打 tag**：逐个创建并推送 tag，避免 GitHub Actions 并发问题
- **失败报告**：脚本结束时汇总所有失败插件，方便定位问题
- **幂等重试**：已存在的 tag 会检查是否指向当前 HEAD，避免重复操作

## 版本号规则（semver）

- **patch**：修复 / 内部重构（行为不变）——拆分、文档元数据更新等
- **minor**：新功能；`0.x` 阶段的不兼容变更（如**包名改名** → 0.2.0）
- **major**：`>=1.0.0` 的不兼容变更
- 每次发版必须更新 CHANGELOG（`--bump` 自动从 git log 生成，可事后补充详情）
- 若代码内硬编码了版本常量，一并同步；tag 版本必须与 `package.json` 版本一致（workflow 强校验，不一致直接失败）

## 打包内容（npm pack）

- 发布内容 = `package.json` `files` 字段 + 默认项（README/CHANGELOG/LICENSE/package.json）
- 每个插件 `files` 已含：lib、assets（截图）、cordis.patch.yml、README、CHANGELOG、LICENSE
- 发版前门禁（release.mjs 自动校验）：
  - `peerDependencies.cordis` 已声明且 major 与其他插件一致（npm 分发后缺失会导致安装失败）
  - **跨插件依赖（issue #39 + #72）**：client/server 端 `require('dsh-*')` / `import` 的包必须在 `peerDependencies` 或 `dependencies` 声明（issue #72：扫描范围覆盖 server 端 import，声明检查覆盖 dependencies——dsh-shared 等自家工具库用 dependencies 由 npm 自动安装）；声明的仓库内 dsh-* 依赖必须已发布（npm）且已打 tag（`<目录>@v<版本>`）——**依赖先发版、依赖方后发版**（如 dsh-think-zh-expand 依赖 dsh-md-render，必须先发 dsh-md-render）；npm view 返回 404（从未发布）直接阻断，不再被「已打 tag」兜底放行；**解析边界（issue #203）**：扫描前先做轻量词法扫描剔除注释，注释里的示例 `require('dsh-x')` 不计入依赖，字符串/模板/正则字面量内部同样不解析（`const s = "require('dsh-x')"` 不算依赖），真实 `require` / `import ... from` 仍照常提取，检测面未收紧
  - **真实环境验证（issue #39，强制）**：发版前自动跑 `node scripts/verify-real-profile.mjs --addons plugins/<名>`（真实 DSH 实例 + 配置组合检查 + 日志错误扫描），失败即阻断发版；CI（GitHub Actions）无生产 profile 自动跳过，本地可用 `--skip-real-verify` 显式跳过（仅限无法起真实实例的场景，如批量回归）
  - README 效果截图引用有效（`./assets/` 相对路径 或 `https://unpkg.com/<包名>/assets/` 绝对 URL，文件必须真实存在）；**无用户可见 UI 的插件**按显式声明豁免（`package.json` 的 `dsh.ui=false` + 非空 `dsh.uiReason`；`dsh.kind=library` 的共享工具包沿用原豁免），豁免结果在发版输出与批量汇总中显式列出（issue #227）
  - **`--all-checks`（仅 dry-run，issue #227）**：静态门禁（peer / 跨插件依赖 / CHANGELOG / 测试 / 效果图）全部跑完再统一报告失败项——避免 fail-fast 让后续门禁「从未执行」而掩盖缺陷；`--push` 仍走首个失败即停的完整门禁
  - CHANGELOG 有当前版本段
- 预览：`cd plugins/<名> && npm pack --dry-run`（tarball 内容清单，防 secrets 泄露）

## 发布通道

| 通道           | 触发                                                     | 说明                                                    |
| -------------- | -------------------------------------------------------- | ------------------------------------------------------- |
| GitHub Release | tag 推送（release.yml）                                  | 自动打包 tgz + CHANGELOG 作为 release notes             |
| npm 官方       | tag 推送（release.yml 内）                               | 需仓库 `NPM_TOKEN` secret（已配置）；未配置时仅警告跳过 |
| 本地手动 npm   | `npm publish --userconfig "$NPMRC" --registry "$NPMREG"` | npm-ops skill 流程（token 管理 / registry 覆盖 / 2FA）  |

## 踩坑记录

| 现象                          | 原因 / 处理                                                                                                                                                                         |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `git tag` 已存在              | 该版本号发过版（tag 指向旧代码）→ bump 到新版本号；不要 force 覆盖旧 tag                                                                                                            |
| release workflow 版本校验失败 | tag 指向的提交里 package.json 版本 ≠ tag 版本 → 必须先提交 bump 再打 tag（`--bump --push` 已保证）                                                                                  |
| npm `ENEEDAUTH`               | 环境变量 `npm_config_registry`（镜像）覆盖配置 → 用 `--userconfig "$NPMRC" --registry "$NPMREG"` 双参数（npm-ops skill）                                                            |
| npm `E403` 2FA                | 用 bypass 2fa 的 Granular Access Token；或 `--otp=<验证码>`（30 秒时效，多包易超时）                                                                                                |
| npm `E409` staged version     | 版本已发布/部分发布 → `npm view <pkg> versions` 确认，bump 后再发                                                                                                                   |
| 发版后文档不同步              | CI 的 `check-docs.mjs` 已强制（根 README 插件表 / docs 索引与模块 / 安装章节）                                                                                                      |
| 插件名写错 / 用旧名发版       | Actions 入口：`Resolve + validate plugins` 步骤 fail-fast，报 `非法插件名: …` 并列出允许值（旧名如 `dsh-notify` 已改名，不在允许值内）；本地脚本：`✗ plugins/<名字> does not exist` |

## 自动化覆盖（防复发）

| 环节                                       | 机制                                                                                                                    |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| 版本 bump + CHANGELOG + 文档同步 + tag     | `scripts/release.mjs --bump`（本地与 Actions 共用）                                                                     |
| 跨插件依赖校验（声明 + 已发布 + 已打 tag） | `scripts/release.mjs` 步骤 1c（纯函数在 `scripts/lib/release-checks.mjs`，单测在 `scripts/test/`）                      |
| 真实环境验证强制                           | `scripts/release.mjs` 步骤 3c → `scripts/verify-real-profile.mjs --addons`（本地强制，CI 跳过）                         |
| 自动发版入口                               | `.github/workflows/release-auto.yml`（workflow_dispatch）                                                               |
| 发版插件名白名单校验                       | 同上 → `Resolve + validate plugins` 步骤（允许值运行时取自 `plugins/` 目录，非法名 fail-fast 列出允许值）               |
| workflow 输入语义与清单防漂移              | `scripts/test/release-checks.test.mjs`（直接执行 workflow 内校验脚本 + 断言输入类型/不插值；CI `npm run test:scripts`） |
| GitHub Release + npm 发布                  | `.github/workflows/release.yml`（tag 触发）                                                                             |
| 文档一致性强制                             | `.github/workflows/ci.yml` → `node scripts/check-docs.mjs`                                                              |
| 文档引用完整性强制                         | `.github/workflows/ci.yml` quality job → `npm run check:links`（链接/锚点/路径 token/npm script/skill 与插件名）        |
| 发版校验单测                               | `.github/workflows/ci.yml` quality job → `npm run test:scripts`                                                         |
| npm 凭据与发布操作                         | `~/Documents/skills/npm-ops`（SKILL.md + scripts/npmops.py）                                                            |
