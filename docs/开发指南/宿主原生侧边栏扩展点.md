# 宿主原生侧边栏扩展点 — 本仓库实测契约

> ⚠️ **何时阅读：** 新增页签 / 文件预览器 / 浮层 / 设置页时，或 e2e 出现「页签丢了」类假失败时。
> **官方语义不在这里查**——`SidebarRightTabDefinition` 字段、`register()` 签名、`documentPreviews` 契约等一律以**官方参考源**为权威（本机检出 `/Users/bsfeng/IdeaProjects/deepseek-harness`，直接 grep 其 docs 与 packages；检索通道见[官方文档索引](../官方文档/索引.md)）。**维护官方语义副本必然漂移**，本文只留三类：我们实际的调用形状、实测 DOM 契约、降级与验证要求。

本仓库已无任何插件依赖 `dsh-better-sidebar`（`npm ls dsh-better-sidebar` 无输出）；client 端一律经 **Cordis 服务名**取原生能力，**无需 require 任何 `@deepseek-ai/dsh-client-ui-*` 包**。

## 1. 我们的调用形状

- **页签两步式**：先注册 tab 类型，再注册两个 keyed 席位——正文 `sidebar.right.pane.tab`、标题 `sidebar.right.pane.tab.title`，**两处 key 都取 `definition.id`**；`inject` 声明 `['slots', 'sidebarRightTabs']`，两次注册各自放进 `ctx.effect`（唯一可抄的官方生产范本：`dsh-client-ui-sidebar-files`）。
- **icon 无原生对应**：`SidebarRightGuideEntry.icon` 只作用于 guide 页的入口胶囊，**页签 chip 没有 icon API**。可行做法：在 `.title` 席位组件里返回「图标 + 文本」（chip 实际结构 `[data-dockkit-tab] > [data-dockkit-tab-title] > [data-slot=sidebar.right.pane.tab.title] > 你的节点`）；`title(address)` thunk 返回 React 节点**不可靠**（它是 chip 的兜底文本）。
- **数字 order 无原生对应**：页签顺序 = `priority` 档 → 匹配模式长度 → 注册顺序；自定义数字顺序会失去意义，一般用默认档 `extension`。
- **预览器与 better-sidebar 的职责相反**：原生由 **document owner** 读字节（绑定 workspace 读接口），再经 `sidebar.right.tab.document` 席位把 `{ kind:'text', … } | { kind:'bytes', … }` 交给渲染器——**渲染器不 fetch、插件不选 viewer**；插件只注册「这些后缀也能开」。资源 tab 地址形如 `dsh-resource://file/session/<sessionId>/<path>`。
- **必须自己兜的例外**：插件记录的路径可能落在 workspace 之外（`/tmp`、`~/.dsh` 下的文件），宿主 `file` provider 的工作区围栏会拒绝——这类预览仍由插件自实现的浮窗承担。
- **浮窗选 `shell.overlay`，不选原生 `sidebarRight.float(tabId)`**：`float()` 只对**已存在**的 tab 生效，而点文件时要**新建**内容 tab；且预览对象是「任意记录过的路径」，不总是宿主的 `file` 资源地址。overlay 组件 root scope 常驻（与插件 fiber 同生命周期），显示与否由插件自己的 store 决定（`preview === null` 时返回 `null`），关闭动画与自动关闭语义由插件保持。注册形状 `{ name: 'shell.overlay', id: '<自有 id>' }`——新增 `id` 与宿主自带条目**并存**，不替换宿主 UI。
- **自动打开**：⚠️ **会话表面未挂载时调用打开动作会 throw**（`sidebarRight: no session surface is mounted`）——必须在 `ctx.effect` 内触发并监听会话挂载后重试；**失败必须可见**（见 §3），不能吞异常。
- **设置页**：注册 `settings.plugins.tab` 席位渲染设置页（先例：`dsh-my-memory` 的 client parts——`ctx.get('slots')` 动态取服务、零第三方依赖）；开关的**权威存储**是插件自己的配置表（server 端路由 + 持久化），**不依赖**宿主 `prefs.pluginSettings`；UI 用官方组件库（可用性以本机运行的包为准，见[官方 UI 组件库](官方UI组件库.md)）。

## 2. e2e DOM 断言契约（实测）

原生停靠体系真实使用的属性：`data-dockkit-surface` / `-drop-zones` / `-pane` / `-pane-active` / `-strip` / `-strip-tabs` / `-strip-fill` / `-strip-chrome` / `-split-button` / `-add-tab`。

- **页签**：断言 `[data-dockkit-tab="<plugin id>"]`（或该节点的文本）；`role="tab"` / `aria-selected` / `data-dockkit-tab-quiet` / `-active` 可选。
- **不要**用 `[data-dockkit-tab-title]` 当「我的页签出现了」的判据——它由宿主自己渲染、始终存在。
- **正文**：在 `[data-dockkit-pane]` 内找插件自己的 DOM 标记（插件保留自有类名 + `data-<插件>-*` 锚点）。
- **空 pane 不自动 seed**：初始载入时 `[data-dockkit-tab]` 计数为 0（宿主在展开后才 seed 默认页）——任何「页签存在」的断言前必须先点击 `[data-dockkit-add-tab]` 或触发一次展开，否则会得到「页签丢了」的假失败。
- **反例**：`[data-dsh-panel-host]` 是**左侧导航栏**的宿主标记，与右侧边栏无关；旧 e2e 探它（或 `[data-dsh-sidebar]`）会得到假阳性。

## 3. 降级语义（绝不允许静默失效）

| 失败场景                             | 要求的行为                                                                                                                                                                               |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 服务缺失（未 inject 成功）           | `inject` 声明式依赖会让宿主拒绝 mount 并报 `failed to apply ... without inject`；插件额外 `console.error` 一条带包名的可读原因                                                           |
| 注册调用 **throw**（id / kind 冲突） | try/catch 包住**每一次注册**，`console.error('[<包名>] <阶段> 注册失败: ' + message)`，并把失败写进 `document.documentElement.dataset.<插件>Degraded`（供 e2e 与用户排查），**不吞异常** |
| 页签未出现（服务在但渲染失败）       | 页签正文渲染显式错误面板（「扩展点不可用」+ 原因），而不是空面板                                                                                                                         |
| 浮窗取字节失败                       | 保留错误面板 + 自动关闭（现状语义不变）                                                                                                                                                  |
| 预览器注册成功但宿主读不到字节       | 宿主 owner 的 failure-line 显示原因，插件不再自己翻译 ENOENT                                                                                                                             |

## 4. 上线前验证

1. 单测覆盖新契约（`inject` 列表、两步式注册调用形状、`shell.overlay` 与设置席位注册、注册 throw 时的 console.error + degraded 标记）。
2. 覆盖率门禁：行 ≥85 / 分支 ≥75 / 函数 ≥80（阈值口径唯一出处见[构建与测试](构建与测试.md)）。
3. e2e 按 §2 契约重写（先制造展开意图，再断言 `data-dockkit-*`），并做隔离实例 + 真实浏览器实测。
4. `npm test` + `npm run verify` 全绿。
