# 文档规范（强制）

> **通用 leader 规则（派发 / 并行 / 验收 / 汇报）唯一权威 = 全局 `leader-ops` skill**——本仓库不复制、不另立；本文件只写本仓库专属落地。
> 文档四原则（只写怎么跑 / 防复发 / 指针，删历史，≤200 行，能并入就不新建）见全局 `leader-ops` skill §七，本文件不再复述。

> ⚠️ **何时阅读：** 动任何文档前必读；新增文档前必须过最后一节自查清单。

## 一、写入判据：出现即删的类别（速查）

写入内容限于「怎么跑 / 防复发 / 指针」三类（定义见全局 `leader-ops` skill §七）；本仓按下列类别逐条判删：

| 类别         | 例子                                                                       |
| ------------ | -------------------------------------------------------------------------- |
| 知识图谱可查 | 函数/类/文件清单、逐条 API 签名、目录树、调用链                            |
| 大模型已知   | 语言语法、node/npm/git 通用用法、React/TS 常识、通用工程常识               |
| 搜索可得     | 第三方库用法、协议规范原文、通用报错解释                                   |
| 重复         | 同一信息散落在 `docs/`、`skills/`、插件 README 多处 → 只留一处，其余改指针 |
| 历史         | 日期、issue 编号、复测记录、已完成项勾选、旧版本对照、复盘/完成报告        |
| 冗长         | 用代码段解释说明、多级小标题、背景铺陈、自我介绍式开头                     |

## 二、四类删除判据的本仓口径

四类删除判据（历史 / 常识 / 图谱可查 / 重复）的定义见全局 `leader-ops` skill §七，本文件不再复述；逐类速查见上一节。

**保留**：门禁依赖文件、流程知识（发版/验证/门禁**怎么跑**）、防复发教训（压缩成条目而非长文）、指针。

判不准是否「对未来有用」时——**保留**。判据：是否存在明确的「下次遇到 X 查这里」场景。

## 三、行数上限（强制）

- **单文件正文 ≤200 行**。超限必须**压缩**（删冗余/重复/历史）或**拆分**（按主题拆成多个 ≤200 行文件 + 索引指针）。
- 踩坑条目：单条 ≤6 行（症状 / 根因 / 修法 / 证据 各一行）；踩坑总表 ≤200 行。
- `AGENTS.md` ≤50 行（每次会话注入，多一行都浪费上下文）。
- 索引只放指针，不放正文。

## 四、历史信息的本仓口径

「不保留历史信息」见全局 `leader-ops` skill §七；本仓落地：

- 时效性版本信息只在 `package.json` 与插件 `CHANGELOG.md` 的**最新版本段**（旧版本条目删）；其余留痕交给 git 与 GitHub issue/PR。
- 要查历史用 git：`git log -- <路径>`。

## 五、目录与命名

- 文档放 `docs/`，文件名与目录名用中文；README / CHANGELOG / SKILL.md / LICENSE 保持英文名。
- 每篇必须有入链（至少被 [索引](../索引.md) 或其他文档引用一次），禁止孤立文档；新建前先问能否并入已有文档（见全局 `leader-ops` skill §七）。
- 插件 README 结构照 [README 模板](README模板.md)。

## 六、文档改动的门禁集

- 纯 `.md` 变更**不跑重型测试套件**（`npm run verify`、`npm run verify:fast`、插件测试都不跑）——测试与文档改动无因果关系；但 **`npm run check:links` 必须默认执行**（.md 改动最核心的检查：相对链接 / `#锚点` / 反引号路径是否真实存在；含空格的目标须用 `<>` 包裹，否则被空格截断；秒级）。**同属「默认执行、不可豁免」的还有两条文档门禁**（`scripts/verify-local.mjs` 里同为 `ciQuality: true`，CI quality job 与 `npm run verify` 都跑）：**`node scripts/check-docs.mjs`**（插件 ↔ 文档一致性：新插件未同步根 README 插件表 / `docs/索引.md` / `<模块>/概述.md` 即红，README 版本行与 `package.json` 不一致也红）与 **`node scripts/check-doc-api-drift.mjs`**（官方 API 面双向漂移：文档登记了代码里没有的 API、或代码在用而文档未登记，两者都红；兼查范例坐标 `plugins/<插件>/src/<文件>.ts:<行>` 是否真实）。三条都**不在豁免范围内**。
- 推送前只做**两条秒级 grep 自检**，推送用 `git push --no-verify`（跳过 pre-push hook）：
  1. **悬空引用**：对本分支删除的每个文档名，在 `*.md` `*.mjs` `*.ts` `*.js` `*.sh` `*.feature` `*.json` `*.yml` 里 grep 一遍，必须 0 命中（指向仍存在的文件不算）。注意 `git diff --name-only` 读中文路径必须加 `-c core.quotePath=false`，否则拿到的是转义串、grep 必然漏。
  2. **残缺链接**：对本次改动的 md 跑 `grep -rnE '\]\([^)]*$|\][^\(]*\)' <文件>`，必须 0 命中（`[path)` 这种缺左括号写法在 GitHub 上就是坏文本）——`check:links` 的 syntax 项已自动覆盖，这里是秒级快筛。
- 其余交给 CI；例外：删除或改名了**被测试/代码注释引用**的文档 → 手工清理注释里的裸路径（`links` 门禁看不见它们）。

## 七、行数度量口径（数字必须可比）

`git ls-files '*.md' | xargs wc -l` 在中文文件名下**不可靠**（xargs 按转义串拆分、会漏计数甚至报 No such file）。统一用：

```bash
git -c core.quotePath=false ls-files -z '*.md' | xargs -0 cat | wc -l   # 总量；换成 'docs/*.md' 等取分板块
```

同理 `git diff --name-only` / `git status` 读中文路径都要加 `-c core.quotePath=false`。

## 八、新增/修改文档前自查清单

- [ ] 内容属于「怎么跑 / 防复发 / 指针」三类之一？否则不写。
- [ ] 没有函数清单、目录树、逐条 API 罗列？
- [ ] 没有语法/工具通用用法讲解、没有代码段解释说明？
- [ ] 没有任何日期、issue/PR 编号、复测留痕、旧版本对照？
- [ ] 全仓无重复表述（同一信息只在此一处）？
- [ ] 正文 ≤200 行？
- [ ] 文件名中文、有 frontmatter（title / description）？
- [ ] 已加入 `docs/索引.md` 或其他文档入链，无孤立文档？
- [ ] 相对链接、`#锚点`、反引号路径、`npm run` 名、skill 名都真实存在（`npm run check:links` 绿）？
