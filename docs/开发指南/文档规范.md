# 文档规范

> ⚠️ **何时阅读：** 动文档前必读。

## 语言要求

所有用户文档必须使用中文编写。

## 目录与命名

- 所有文档统一放在 `docs/` 目录下
- 文档文件和目录名必须使用中文
- `AGENTS.md` 例外：位于项目根目录
- 例外：README、CHANGELOG、LICENSE、SKILL.md 保持英文文件名

## AGENTS.md 规范

AGENTS.md 是每次会话自动注入的 workspace instructions，**必须保持精简**（当前 35 行/~4KB，目标 ≤50 行）——注入即消耗上下文，只保留必须全局知道的内容：

1. **协作与项目管理原则**——所有 agent 必读的核心行为准则（leader 管理/分配优先/上下文管理/并行上限/续接原子 agent/严格验收/从小到大/外部能力吸纳）
2. **强制规则**——副作用操作 ask、测试必跑、命令超时、知识图谱、发版门禁
3. **入口**——docs/索引.md + 关键 skill 一句话指向

**不写入 AGENTS.md（可按需加载，放别处）：**

| 内容 | 放哪里 |
|---|---|
| 知识图谱使用规则 | codebase-memory skill（skill 自己知道） |
| 文档索引/体系树 | docs/索引.md |
| 插件介绍/功能模块表 | 各插件 docs/ 子目录 |
| 版本列表 | package.json（且每次 release 更新易过时） |
| 操作细节/流程 | 对应 skill 或 docs |

**新增内容前先问**：这个能被 skill/文档按需加载吗？能 → 不写入 AGENTS.md；必须全局知道 → 才写入，且精简措辞。

## 目录生成规则

- **基线固化**：首次全量扫描生成的目录结构即为基线，增量更新必须基于该基线
- **模块名固定映射**：英文包名 → 固定中文目录名映射表（如 `dsh-file-activity` → 文件活动追踪）
- **项目类型模板选择**：library（基础服务）
- **目录变更规则**：新增→新增文件，删除→移至未归档文档，重命名→保持旧目录名

## 子目录拆分规则

超过 3 个独立主题或单个文件超过 500 行时拆分，层级不超过 2 层。

## 文档结构与渐进式加载

索引即入口（`docs/索引.md`）、按需加载、有向无环图（DAG），禁止循环引用。

## 孤立文档禁令

每篇文档必须至少被索引或其他文档引用一次（有入链）。

## 计划和任务类临时文档清理

任务完成后立即删除，不得纳入正式文档体系。此类文档在文档体系中必须是孤立的，不得链接到正式文档。

## 代码示例规范

遵循语言编码规范、使用最新语法（Node ≥ 20：ESM、顶层 await）。

## 踩坑文档维护规范

记录门槛（编译错误/API 不兼容/持续失败测试）、格式精简（标题≤30字+状态+解决参考）、按功能域分组、淘汰归档。

## 源码路径索引（formatVersion ≥ 2）

- 文档中的核心类/文件必须标注精确 `src/路径`（如 `plugins/dsh-file-activity/lib/index.js`）
- 功能模块文档必须包含「业务场景映射」表格，业务关键词映射到入口与方法
- 禁止使用 `.../` 缩写路径
- 目标：AI agent 3 步内从"一个需求"定位到具体代码文件

## ✅ 操作前自查清单

创建、修改或删除文档前逐项确认：

- [ ] 文档文件名使用了中文
- [ ] 新增文档已在 docs/索引.md 或相关文档中添加引用链接
- [ ] 文档内容不构成孤立文档（至少有一条入链）
- [ ] 文档目录遵循了基线固化规则（不随意更改已有目录结构）
- [ ] 如果文档是计划/任务类临时文档，完成后已删除
- [ ] 遇到报错时已先查看 `docs/踩坑/` 对应功能域是否有类似记录
- [ ] 新遇到的值得记录的问题已写入踩坑记录
- [ ] 核心类/接口标注了精确源码路径，业务场景映射完整
