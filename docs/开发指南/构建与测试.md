# 构建与测试

> ⚠️ **何时阅读：** 构建 / 测试 / 提交前必读。

## 需求回归（强制要求）

改动前先确认对应需求（对应 GitHub issue 的验收标准原文），提交前**逐条回归**并留下证据；新增功能补测试与文档条目。完整生命周期见 `skills/development-lifecycle/`。

## 常用测试命令

```bash
cd plugins/<插件名> && npm test                # 冒烟测试（纯 Node，mock ctx / webServer / slots）
node --check plugins/<插件名>/lib/index.js      # 语法检查（client.js 同理）
for d in plugins/*/; do [ -f "$d/package.json" ] && (cd "$d" && npm test); done
```

- 测试放 `plugins/<name>/test/`，一个用例测一个行为，名字描述期望行为；覆盖边界（空 path、非法 sessionId、损坏状态文件、LRU 裁剪、重复访问去重）。
- 需要真实进程 / 浏览器的测试（`test/e2e-cdp.mjs`）本机手动跑，不进 CI。
- 覆盖率门槛 **行 ≥85% / 分支 ≥75%**（统计 `plugins/<name>/lib/`）。

## 本地一键校验（verify-local）

> 一条命令复现 CI 全部门禁（`.github/workflows/ci.yml`）。

```bash
npm run verify                    # 全量（等价 CI；pre-push 默认走这条）
npm run verify:fast               # 快速通道（显式：VERIFY_MODE=fast git push）
node scripts/verify-local.mjs --full | --fast --base origin/main
node scripts/verify-local.mjs --audit | --mutation        # 默认跳过的两项按需开启
node scripts/verify-local.mjs --only knip --only links    # 只跑单项（可重复）
node scripts/verify-local.mjs --list [--json]             # 检查项清单
node scripts/verify-local.mjs --plugin dsh-my-guard       # 单插件
npm run verify:ci-quality         # CI quality job 的执行体
npm run check:gate-parity         # 本地 ↔ CI 门禁覆盖一致性校验
```

- **失败语义**：任一检查失败 exit 1，但**继续跑完其余检查**并汇总全部失败项，方便一次修完。
- `--fast` 每次打印实际跑了什么（基准 ref、变更文件数、受影响插件清单、跳过项及原因）。
- pre-push 默认跑 CI 等价全量；失败阻止 push。`--fast` 是显式选择，且会逐条打印未跑项，不静默少跑。

### `--fast` 的范围裁剪规则

基准 `@{upstream}`，无 upstream 回退 `origin/main`（`git diff <base>...HEAD`，只看**已提交**内容）。

| 变更路径                                                          | 插件测试范围                                                      |
| ----------------------------------------------------------------- | ----------------------------------------------------------------- |
| `plugins/<name>/**`（低扇入）                                     | 只跑该插件 + 受影响闭包（package.json 依赖 + 源码 `import` 两路） |
| 高扇入共享库（闭包 > 一半插件，如 `dsh-shared`）                  | 安全退化 → 全部插件                                               |
| `docs/**`、`skills/**`、`*.md`、`.github/**`                      | 不跑插件测试，并跳过只针对源码的检查                              |
| `package-lock.json`、文档检查脚本（**仅修改**）                   | 不扩大范围；**删除**仍退化全量                                    |
| `package.json` 仅元数据字段（description/keywords…）              | 不扩大范围（dependencies/scripts/engines 等仍退化）               |
| 其它 `scripts/**`、根工具链文件（`knip.json`/`tsconfig.json` 等） | 安全退化 → 全部插件                                               |
| 无 upstream / `git diff` 失败 / `--base` 不可解析                 | 安全退化 → 全部插件，并输出原因                                   |

- **带证据才跳过**：`ts-size`（无 `.ts`/`.tsx` 变更）、`resource-smoke`（未触及 observability/shared）、`client-modules`（无客户端产物或插件 manifest 变更）、`client-size`（无发布面或基线变更）、`lint`（无 `.js`/`.mjs` 变更；有则只 lint 变更文件）、`format`（只 check 变更文件）。每条跳过都打印原因。
- **拿不到变更证据一律安全退化全量**（无 upstream / `git diff` 失败 / `--base` 不可解析 / 变更集为空）——不允许裁剪出「漏跑」。
- **恒跑项**（只并发、不裁剪）：typecheck、typecheck-plugins、test、test-scripts、knip、jscpd、depcruise、docs、links、gate-parity、client-size、pack-hygiene、artifacts、test-sleeps。
- **并发**：检查项 4 路、插件测试 6 路（实测上界，更高无收益且联网用例劣化）；`depcruise` 必须等插件测试跑完（否则扫到半截 `coverage/`）；怀疑 coverage 目录冲突时用 `VERIFY_CONCURRENCY=1`（另有 `VERIFY_CHECK_CONCURRENCY`）。
- **残余风险**：fast 可能漏检「测试断言了另一个未改动插件的行为」这类交叉形态，靠 CI 兜底；发版、改根工具链、改 `dsh-shared`、或对结果有疑问时跑 `npm run verify` 全量。

### 门禁覆盖一致性（唯一事实源）

- 每条门禁规则的「唯一权威执行点 + 理由 + 耗时」登记在 `scripts/lib/gate-registry.mjs`；运行时清单看 `node scripts/verify-local.mjs --list --json`，**文档不重复登记**。
- `npm run check:gate-parity` 对「登记表 ↔ `ci.yml` ↔ `verify-local`」双向比对，缺口逐条列出：本地有·CI 无 / 跑了没登记 / 注册未调用 / CI 有·本地无 / 命令漂移 / 范围漂移 / 白名单。
- **本地绿 ⇒ CI 绿**：本地无法执行的项必须登记进 `LOCAL_EXEMPTIONS`（含理由），`gate-parity` 拒绝「以慢为借口」，并反向校验「默认跳过却没登记」。当前唯一豁免项：`audit`（镜像源无 advisories 端点）。
- **`merge-ref`**：本地检查断言 `HEAD` 已包含本地已知的 `origin/main`，消除「CI 测合并结果、本地测自己分支」的偏差。
- **并发隔离**：检查项必须只读工作区；`test-scripts` / `artifacts` 各注入独立 `TMPDIR`（全局 `os.tmpdir()` 枚举会互相看见，必然假红）；`mutation` / `depcruise` 独占或后置。`artifacts` 的重建全部在仓库外一次性 HEAD 镜像内完成，工作区 hash/mtime/inode 不变。

## CI 阻断步骤 → 本地对应项

| CI job / step                           | 本地对应项                                                                                                                                                                | 本地默认                    |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------- |
| `quality`（聚合 `--ci-quality`）        | typecheck、typecheck-plugins、lint、ts-size、client-modules、client-size、pack-hygiene、format、test-scripts、depcruise、knip、jscpd、docs、links、gate-parity、artifacts | ✅ `npm run verify`         |
| `test`（Syntax check + 19 插件 matrix） | 逐插件 `node --check` + `npm test`                                                                                                                                        | ✅                          |
| `resource-smoke` / `mutation`           | 同名检查项                                                                                                                                                                | ✅（`--fast` 下按证据跳过） |
| `audit`                                 | 同名检查项                                                                                                                                                                | ⏭ 白名单（CI 专属环境）     |
| `coverage-finish`（Coveralls 上报）     | 无本地等价物                                                                                                                                                              | ⭕ 白名单（CI 专属上报）    |

> 白名单是**机器可校验的**：`gate-parity` 逐条校验豁免项在登记表存在、理由 ≥30 字、CI 侧真有执行点、类型属 `ci-env` / `ci-credential` / `matrix-os` / `reporting`，且理由里不得出现「慢 / 耗时」。

## 客户端产物体积预算

`node scripts/check-client-size.mjs` —— 产物体积决定用户下载量与加载时间，机器判定取代人工发现。

- **范围 = 完整发布面**：以各插件 `package.json` 的 `files` 字段为唯一权威（含 `lib/**` 与 `assets/**`），口径与 `npm pack --dry-run --json` 的 `unpackedSize` 一致。只查 `lib/client.js` 会漏掉 vendored 资源（如 mermaid 引擎）。
- **上限 = 基线 + max(64 KB, 基线 × 15%)**；两层检查：逐文件（未登记文件受 1 MB 默认上限）+ 每插件发布面合计。
- **fail-closed**：扫不到产物 / `package.json` 解析失败 / 缺 `files` 字段 / `files` 含 glob → 失败；基线缺失或损坏 → 工具错误 exit 2。绝不静默变绿。
- 基线在 `scripts/client-size-baseline.json`；体积增长确属合理时刷新 `node scripts/check-client-size.mjs --update-baseline` 并在 PR 说明原因。

## 依赖漏洞审计

> 改依赖（升级 / 新增 / 改 overrides）后 `npm audit` + `npm ci` 是必跑项，audit 必须走**官方 registry**。

```bash
npm run verify --audit                              # verify-local 的 audit 项已内置官方 registry + 禁止重写 + moderate 门槛
npm_config_registry=https://registry.npmjs.org \
  npm_config_replace_registry_host=never \
  npm audit --audit-level=moderate
```

- `npm audit` 依赖 registry 的 advisories 端点，npmmirror 等镜像未实现（`404 NOT_IMPLEMENTED`）→ 本地 audit 不可用。
- **`--registry` 会被重写回镜像**：`replace-registry-host` 默认值 `npmjs` 会把官方地址换成当前配置的 registry，必须同时设 `replace_registry_host=never`。
- **退出码分不清「没查成」与「没问题」**：镜像下 audit 也正常退出并打印提示，判定必须看输出里**是否真有结构化报告**。
- 门槛 `--audit-level=moderate`（moderate 及以上阻断）；失败排查见[踩坑记录](../踩坑/README.md)。

## 发布与提交

- 双通道发布：tag `<包名>@v<版本>` 推送 → GitHub Release 自动打包 + npm 自动发布；流程见 [发版流程](发版流程.md)。
- 代码 + 测试 + 文档**一次性提交**，提交信息遵循 conventional commits（见 [CONTRIBUTING.md](../../CONTRIBUTING.md)）。
