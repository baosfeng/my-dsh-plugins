# 版本号管理

> ⚠️ **何时阅读：** 改版本号 / 发版前必读。

各插件独立使用语义化版本 `主版本.次版本.修订号`。

| 变更级别 | 版本号变更 | 触发场景                                                             |
| -------- | ---------- | -------------------------------------------------------------------- |
| 小改动   | 修订号 +1  | Bug 修复、微小调整、内部重构（行为不变）                             |
| 中等改动 | 次版本 +1  | 新增功能、非破坏性变更；`0.x` 阶段的不兼容变更（如包名改名）也走这里 |
| 大改动   | 主版本 +1  | `>=1.0.0` 的破坏性变更、架构重构                                     |

## 操作流程

推荐一条命令完成（bump + CHANGELOG + 同步文档 + tag + push）：

```bash
node scripts/release.mjs <插件名> --bump patch --push    # --bump 可选 patch | minor | major
```

手动方式：跑通 `cd plugins/<名> && npm test` → 改 `plugins/<名>/package.json` 的 `version` → 在 `CHANGELOG.md` 顶部加对应 `## [x.y.z]` 段落（Keep a Changelog 格式）→ 提交 → `git tag <包名>@v<版本> && git push origin <包名>@v<版本>` → 同步根 README 的版本号与简介。

> 若代码内硬编码了版本常量，一并同步；**tag 版本必须与 `package.json` 版本一致**（workflow 强校验，不一致直接失败）。

## 操作前自查

- [ ] 变更级别判定正确，新版本号算对
- [ ] 全部测试通过（`cd plugins/<名> && npm test`）
- [ ] CHANGELOG 已加对应 `[x.y.z]` 段落
- [ ] tag 已打且与 `package.json` 版本一致；根 README 版本行已同步
