## 易碎点

- **渲染器替换的恢复性**：`assistant-step` 是 `shadows-shipped-ui` 级替换，卸载/禁用后必须恢复内置渲染，不允许残留。依赖 `ctx.effect` 持有注册 disposer。
- **section 命名冲突**：`systemPrompt.section` 同一层重复 name 会抛错；`dsh-think-zh` 为保留名，不得与第三方插件重复。
- **跨插件依赖（issue #31/#293）**：本插件 client 端 `require('dsh-md-render')`（`dsh.client.external` 声明，**首选渲染内核**）——`dsh plugin add` 不会自动安装/激活 external 指向的插件（只激活 profile 直接 dependencies 里声明 `dsh.bundle.patch` 的包；peerDependencies 在 `autoInstallPeers: false` 下永不安装），新装用户开箱即缺，因此必须有**真回退**：官方 `MarkdownText`（宿主 staticModules，零安装）→ `<pre>` 纯文本。**只 catch require 并把组件置 null 是假降级**，渲染期 `createElement(null)` 会抛 `Element type is invalid`（见 [踩坑](../踩坑/假降级-只catch-require不等于优雅降级.md)）。装了 dsh-md-render 时 `.tzx-md` 系列样式随它注入。该三级回退已在 `package.json` 的 `dsh.client.externalDegraded: ["dsh-md-render"]` 里**显式声明**（#294 发版门禁 1c：仅 peer 的 external 必须声明"缺失时有降级路径"）——注意此字段只被本仓库门禁读取，宿主只认 `platform`/`inject`/`external`/`immediately`，对运行时无副作用。
