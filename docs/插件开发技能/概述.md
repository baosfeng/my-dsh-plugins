# 插件开发技能（dsh-plugin-development）

## 概述

仓库内置的 DSH 插件开发技能，面向本仓库（my-dsh-plugins）中**新建、修改、调试或发布** DSH 插件的完整流程。仓库内插件均为 `plugins/<name>` 自包含 bundle，接入 `dsh-better-sidebar` 服务。

核心约定：

- **多插件目录**：每个插件是 `plugins/<name>/` 下的自包含 Cordis bundle（自己的 package.json + cordis.patch.yml + README + LICENSE + CHANGELOG），可独立安装、独立发布、独立拆仓。
- **三种插件形态**：工具型（`ctx.tools.register(defineTool(...))` 注册 agent 可调用函数）、侧边栏页签/预览器（消费 better-sidebar）、纯 server（事件/HTTP 路由）。
- **两端架构**：Server 端（`lib/index.js`，DSH Node 进程）+ Client 端（`lib/client.js`，浏览器）。
- **发布规则**：只发 GitHub Release（tag `<包名>@v<版本>`），不发 npm。

## 关键规范速览

- 包名 `dsh-<功能>`（无 scope），**目录名 = 包名**。
- client 注册的 tab/viewer id 统一 `包名:xxx` 前缀。
- 硬依赖才 `inject`；可选服务用 `ctx.get()` 判空降级。
- 所有副作用包在 `ctx.effect()` 中（返回 disposer），HMR/禁用无残留。
- 工具型插件：`inject: ['tools']` + `ctx.tools.register(defineTool({...}))`，schema 硬规则（属性级 `required: true`、对象显式 `additionalProperties: false`、`output` 必填、`execute` 非 `run`）。
- 术语统一：**Server 端 / Client 端**，禁止写 "Host 半"。
