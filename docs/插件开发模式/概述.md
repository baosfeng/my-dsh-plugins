# 插件开发模式（dsh-plugin-dev-mode）

> 源码：`plugins/dsh-plugin-dev-mode/` · [插件 README](../../plugins/dsh-plugin-dev-mode/README.md) · [文档索引](../索引.md)

## 功能

向 DSH 提供 agent preset「插件开发模式」（id `plugin-dev`）——启用 Cordis 工具集（`cordis_inspect_*` 运行时检查 + 动态插件生命周期 `define`/`run`/`stop`/`undefine`）的模式，专用于开发、调试和维护 DSH 插件与动态 Cordis 插件；与 shipped「创造模式」同为该工具集载体，但主动去掉了高 token 成本项（plan mode、委派工具、web 搜索）。

**载体形态**：`cordis.patch.yml` 里一行 `@deepseek-ai/dsh-agent-preset` 声明（Loader 行 id `preset-plugin-dev`），装载方式是把**包名**写进 profile 的 `dsh.profile.bundles`——不是运行时插件，也不再有 `$DSH_HOME/.agent-presets/` 目录资产。

## 安装

profile 的 `dependencies` 已指向本目录（`link:<仓库路径>/plugins/dsh-plugin-dev-mode`，见[安装与导入](../快速集成/安装与导入.md)）后，把**包名**追加进 `dsh.profile.bundles`——官方等价写法：

```text
plugin_manager { action: "set_bundle", target: "dsh-plugin-dev-mode", enabled: true }
```

手工等价做法：编辑 profile 的 `package.json`，给 `dsh.profile.bundles` 追加字符串 `"dsh-plugin-dev-mode"`（bundles 元素是**包名**，路径只出现在 `dependencies` 的 `link:` 值里）——**须在宿主停止时改**，运行中会被 `plugin_manager` 覆盖；依赖已就位时不必重跑安装、也不必动 lockfile。

装完在**新会话**里于 Web GUI 模式选择器切换到「插件开发模式」。要求宿主 DSH **≥ 0.1.7-rc.2**：声明行需要宿主提供 `@deepseek-ai/dsh-agent-preset` 与 `agent-preset-registry`，低于该版本不可用。

> ⚠️ **别用 `install_bundle`**：本仓库按 `link:` 布局开发，该 action 在 `link:` 下 `pnpm add <绝对目录>` 不改变依赖值 → 判定不到 `installed`，兜底只认裸包名（会把 link 换成 registry 版本）；`dsh plugin --profile <p> add <目录>` 同理，不追加 `dsh.profile.bundles`。

## 包含内容

- 声明行 `config`：`id`（`plugin-dev`）、`name`、`description`、`plugins` 列表（工具组合与身份指令），`order` 有意留空；
- 技能：`editing-cordis-compositions`、`cordis-plugin-development`、`cordis-composition-reference`，由 `skill-filesystem.customSkillDirs` 解析宿主自带的 `@deepseek-ai/dsh-agent-preset` 包提供（不随本包副本分发，永远与宿主版本一致）；
- 工具组合：shell、文件系统、后台任务、goal、compaction、技能、询问与 todo，外加 Cordis 工具集（inspect / define / run / stop / undefine）；
- 相对「创造模式」删除 plan mode、子代理与工作流、web 搜索三组高成本项，需要时切回标准模式即可。

## 注意

- inspect 注册表在 0.1.7 起由宿主一次性注册、各 preset 的 `tool-cordis` 行共同读取，所以本 preset 与「创造模式」**不再互斥**；
- 改动声明行后重启宿主重新装载（bundle 层栈在启动时读取）；已启动的会话保留其启动时的插件版本，行为变更请在**新会话**中验证；
- 卸载用 `plugin_manager` 的 `remove_bundle`。
