# 插件治理（dsh-my-guardian）

> 源码：`plugins/dsh-my-guardian/` · [插件 README](../../plugins/dsh-my-guardian/README.md) · [文档索引](../索引.md)

## 功能

新装 / 刚更新的插件先进候选区，由守护插件在 DSH 启动完成后逐个热挂载：成功自动转正，失败自动禁用并留痕，连续失败冻结；另对写进启动名册的插件做启动前静态预检，配套侧边栏诊断面板与一键安全模式。

## 安装

```bash
dsh plugin --profile web add dsh-my-guardian --trust-lockfile
```

再把 guardian 条目加到 profile patch 的 insert 列表**第一行**，并新建候选文件 `cordis.staged.json`（顶层数组，元素为 `{id, name, config}`）写入待观察插件；硬刷新浏览器后侧边栏出现「插件守护」页签。

## 主要能力

- **两段式加载**：核心启动区只留稳定插件，新插件验证通过后才进入常驻清单，把「坏插件拖垮整个 DSH」的概率降到最低；
- **启动名册静态预检**：对名册条目做包可解析 / peerDependencies 满足 / 无重复 id 三项静态检查，结果写入守护目录的启动问题报告（原子写、只记录只告警，绝不阻断启动）；
- **失败处置**：挂载失败记录失败类型、依赖缺失与安装建议；连续失败 3 次冻结，需人工解除；
- **安全模式**：一键跳过候选挂载并卸载已挂载的候选插件，用于启动排障；
- **自保**：`apply` 永不抛错、异步全路径 catch、状态文件损坏降级为空状态、仅用 Node 内置模块与 loader 公开 API；
- **恢复手段**：从 profile patch 删掉 guardian 条目即可退场——候选插件本就不在启动名册，无残留。

## 边界

提供的是加载时序与失败处置兜底，不是进程级资源隔离；正式启动区插件仍遵循 all-or-nothing，官方唯一自动豁免是条目 `disabled: true`，因此新插件请先放候选区验证。
