# dsh-my-guardian 需求清单（设计基准）

> ⚠️ **每次开发本插件的新功能或修复前，必须逐条对照本清单**：新改动不得破坏任何一条既有需求；涉及"失败隔离 / 重启恢复"的需求变更后必须跑回归验证。

## 0. 设计背景（为什么存在这个插件）

DSH（DeepSeek Harness）的 Cordis 插件加载是 **all-or-nothing**：

| 场景                           | 当前行为                                                 |
| ------------------------------ | -------------------------------------------------------- |
| 启动时插件 import 失败         | `assertEntriesLoaded` throw → 整个 `dsh web` 启动失败    |
| 启动时插件 apply 抛错          | fail-loud（`unhandledRejection` → 进程 `exit(1)`）       |
| 启动时插件 pending（依赖缺失） | `assertEntriesActivated` throw                           |
| 运行中 HMR 热更新失败          | ✅ 宽容：警告 + `hmr/config-update-failed`，事务回滚旧树 |

关键洞察：**运行时的动态挂载失败是宽容、可 catch、可回滚的**（`EntryTree.create()` reject 不污染 store；`EntryGroup.update()` 失败自动回滚）。只有**启动阶段**是致命的。因此本插件把"新装/刚更新的插件"一律推迟到启动完成之后动态挂载，绕开全有全无窗口。

业界参照：VS Code（Extension Host 独立进程 + 崩溃自动重启 + `--disable-extensions` + 懒激活）、IntelliJ（PluginClassLoader 隔离 + Dynamic Plugins 运行时装卸 + 损坏插件跳过）、systemd（`Restart=on-failure` + 失败超限标记 failed + 依赖分级启动）、OSGi（bundle 加载失败不影响容器）。

## 2. 诚实边界（写进文档，不越权承诺）

| 诉求                               | 插件层能做到   | 说明                                                                                                                     |
| ---------------------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 失败自动禁用 / 逐步加载 / 安全模式 | ✅             | 本插件                                                                                                                   |
| 进程级隔离                         | ❌ 需 DSH 框架 | server 插件同 Node 进程、client 同浏览器页面；真隔离需 worker_threads/子进程 + RPC（框架演进建议见概述「框架演进方向」） |
| 启动阶段坏插件不拖垮启动           | ❌ 需 DSH 框架 | fail-loud 是 `dsh-app-boot` 的 `assertEntriesActivated` 行为。缓解：核心区只放稳定插件，新插件一律走候选区               |

## 3. 用户明确确认过的设计决策（2026-08-23）

- 产出形态：**治理插件**（不动 DSH 核心）
- 候选区形态：**独立候选文件**（`cordis.staged.json`，非正式 patch 内标记）
- 失败处置：**自动禁用 + 记录 + 通知**（不停下等用户决定）
- 连续失败 3 次冻结，需手动解除
- 诊断面板：**复用 dsh-better-sidebar 侧边栏页签**（与 dsh-file-activity 一致）
