# 快速上手

## 1. 安装插件到 DSH

```sh
dsh plugin --profile web add link:<仓库路径>/plugins/<插件名>   # 本地 link（开发用）
dsh plugin --profile web add <插件名>                          # 从 npm 安装（已发布插件）
```

装完后**硬刷新浏览器**（Cmd/Ctrl+Shift+R）。更多方式见 [安装与导入](../快速集成/安装与导入.md)。

## 2. 使用文件活动页签

1. 侧边栏 `+` 菜单 → **文件活动**（会话首次自动打开）。
2. **最近访问**：LRU 记录（每会话最多 5 条），点击文件弹出浮窗预览（浮窗由插件自身 `/file-activity/file` 路由读字节渲染：代码高亮 / Markdown / 图片 / PDF / HTML，工作区外路径亦可）。
3. **文件统计**：读取/新增/修改次数按绝对路径组织成树形目录，文件夹可折叠；顶部图标提供刷新（重载）与清空（删除当前会话全部记录）。

## 3. 开发新插件

1. 先读 [插件开发技能](../插件开发技能/概述.md)（或 `skills/dsh-plugin-development/SKILL.md`），再在 `plugins/<新插件名>/` 建自包含插件包，并用 `dsh plugin --profile web add link:<绝对路径>/plugins/<新插件名>` 本地验证。
2. 更新根 README 插件表、`docs/索引.md`、模块概述与插件 README。

## 4. 发布插件

```sh
node scripts/release.mjs <插件名> --bump patch --push   # bump + CHANGELOG + 同步版本号 + 门禁 + 推送 tag
```

完整流程见 [发版流程](../开发指南/发版流程.md)；失败排查见 [踩坑目录](../踩坑/README.md)「发版版本校验失败与 dry-run 误 bump」。

> tag `<插件名>@v<版本>` 推送后由 workflow 自动创建 GitHub Release 并发布 npm（需仓库 `NPM_TOKEN`）；**tag 版本必须与 `package.json` 版本一致**（workflow 强校验，比较不带 `v` 的裸版本号）。
