# 快速上手

## 1. 安装插件到 DSH

前置：已安装 `dsh-better-sidebar`（v0.12+，推荐 v0.14）。

```sh
# 推荐：dsh plugin 安装（link 指向本仓库插件目录）
# 1) 克隆本仓库（任意目录）
git clone https://github.com/baosfeng/my-dsh-plugins.git
# 2) 以本地 link 方式安装（将 <仓库路径> 替换为上面的克隆目录）
dsh plugin --profile web add link:<仓库路径>/plugins/dsh-file-activity
```

装完后**硬刷新浏览器**（Cmd/Ctrl+Shift+R）。

> 编辑 profile 的 `cordis.patch.yml` 会在运行中通过 Cordis HMR 热挂载 server 端，无需重启 `dsh web`；client 端在页面刷新后生效。
> 更多安装方式（手动依赖 + patch）见 [安装与导入](../快速集成/安装与导入.md)。

## 2. 使用文件活动页签

1. 侧边栏 `+` 菜单 → **文件活动**（会话首次自动打开）。
2. **最近访问**：LRU 记录（每会话最多 5 条），点击文件弹出浮窗预览（复用侧边栏内置渲染：代码高亮 / Markdown / 图片 / PDF / HTML）。
3. **文件统计**：读取/新增/修改次数按绝对路径组织成树形目录，文件夹可折叠。
4. 顶部图标：刷新（重载）、清空（删除当前会话全部记录）。

## 3. 开发新插件

1. 先读 [插件开发技能](../插件开发技能/概述.md)（或 `skills/dsh-plugin-development/SKILL.md`）。
2. 在 `plugins/<新插件名>/` 创建自包含插件包（package.json + cordis.patch.yml + lib/ + README + CHANGELOG + LICENSE）。
3. 本地验证：`dsh plugin --profile web add link:<绝对路径>/plugins/<新插件名>`。
4. 更新根 README 插件列表与 `plugins/<新插件名>/README.md`。

## 4. 发布插件

> 完整发布流程见 [发版流程](../开发指南/发版流程.md) 与 [插件开发技能 - 发布](../插件开发技能/概述.md)；失败排查见 [踩坑：release 校验失败](../踩坑/github-release版本校验失败.md)。

```sh
# 发版（自动 bump 版本 + 生成 CHANGELOG + 同步版本号 + 校验门禁 + 推送 tag）
node scripts/release.mjs <插件名> --bump patch --push
```

> tag `<插件名>@v<版本>` 推送后由 workflow 自动创建 GitHub Release 并发布 npm（需仓库 `NPM_TOKEN` secrets）；tag 版本必须与 `package.json` 版本一致（workflow 强校验，比较的是**不带 v** 的裸版本号）。
