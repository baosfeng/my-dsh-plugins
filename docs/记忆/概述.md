# 记忆（dsh-my-memory）

> 源码：`plugins/dsh-my-memory/` · [插件 README](../../plugins/dsh-my-memory/README.md) · [文档索引](../索引.md)

## 功能

把用户偏好与项目约定持久化为全局 / 项目两级记忆：全局记忆在会话开始时注入系统提示词（agent 始终携带），设置页可视化面板管理（写操作必须用户确认），并提供 `memory_query` 只读查询与 `memory_save` 保存工具。

## 安装

```bash
dsh plugin --profile web add dsh-my-memory --trust-lockfile
```

## 关键配置

| 配置键             | 作用                                                                   |
| ------------------ | ---------------------------------------------------------------------- |
| `maxItems`         | 注入系统提示词的条数上限（默认 5，按相关性 + 时效性 + 置信度评分选取） |
| `maxDescLength`    | 单条注入长度上限（字符，按语义截断，不截断在句子中间）                 |
| `maxEntryLength`   | 建议的单条记忆长度上限（超出时面板提示精简，不拒绝保存）               |
| `proactivePropose` | 是否引导 agent 主动向用户提议保存记忆（默认关）                        |
| `maxPromptItems`   | 注入的全局提示词条数上限（默认 20，超出不注入 + warn）                 |
| `maxPromptLength`  | 单条提示词正文上限（字符，默认 1000，超出截断 + warn）                 |

## 主要能力

- **两级存储**：全局存 `$DSH_HOME/memory.json`；项目记忆按项目根路径哈希集中存 `$DSH_HOME/memory/projects/`，旧的项目内记忆文件首次访问时自动迁移；原子写 + 防抖 + 重启恢复；
- **注入**：只注入全局记忆，会话开始即生效，记忆变更后下一轮生效；
- **面板**：全局记忆 / 项目记忆 / 全局提示词三个 tab；条目概要 + 详情两级展示，带分类徽标、置信度、矛盾警示与演进历史；新增与编辑为多行自适应输入框，保存与删除走居中确认弹层；项目 tab 随当前会话项目根自动加载；
- **工具**：`memory_query` 只读查询（含项目记忆）；`memory_save` 每次调用都经确认门触发原生审批，绝不静默变更；
- **渐进合并**：同主题多次保存提升置信度、分歧标记矛盾、90 天未用降权（自动学习候选已移除）。

## Agent 记忆（issue #502，第四套体系）

**定位**：agent 自主维护的**跨会话记忆**——记住下次会话还用得上的信息与用户偏好。与上面三套（全局记忆 / 项目记忆 / 全局提示词）**完全隔离**：独立目录、独立工具、独立元数据、独立面板 tab。

**核心差异：正文零常驻，目录常驻。** 全局记忆是固定 top-5 注入，而 agent 记忆**不注入任何正文**——系统提示词里只有两段：恒定的规则说明 + 一张**一行一条的目录**（agent 自己写过的条目，order -80）。正文只在 agent 主动调用 `agent_memory_read` 时才进入上下文，不命中则一分 token 都不花。

**为什么目录必须常驻**：只按需读取有个死结——不读就不知道有什么，读了才知道。把「想起来去 list」压在模型自觉上靠不住（Claude Code 的解法也是索引常驻）。目录解决的是「看得见」，正文按需解决的是「付得起」：

| 层 | 内容 | 常驻 | 成本 |
| --- | --- | --- | --- |
| 目录 | `文件 · 这条讲什么`，一行一条 | ✅ | 硬上限 60 行 / 4 KB / 单行 32 字；排序固定为「user.md → feedback.md → 项目层」，超出按顺序截断并给「另有 N 条，用 read 查看」——绝不静默丢 |
| 正文 | 条目原文 | ❌ | 读哪份付哪份（单文件 ≤ 4 KB） |

目录是**系统按文件自动生成的**，不做相关性打分、不做筛选——它不是「系统替 agent 判断」，只是把 agent 自己的目录摆出来。内容恒定 → 前缀缓存可命中；写入/删除后重建一次，只失效一次。启动时同步装载一次（`prime()`），否则首轮组装会拿到空目录、agent 以为记忆库是空的。

**文件是存储，不是接口。** 正文是纯 markdown（不带日期、不带 id、不带 frontmatter）；元数据（创建时间 / 最后读取 / 读取次数 / 归档）单独存 `index.json`，**agent 读不到也写不到**。理由：时间戳与热度若可被 agent 篡改，遗忘机制就形同虚设。

```text
$DSH_HOME/agent-memory/
├── index.json              # 元数据（agent 不可见、不可写）
├── MEMORY.md               # 索引：一行一个文件 + 什么时候该读
├── user.md                 # 用户偏好
├── feedback.md             # 被纠正过的做法 + 正确做法
├── projects/<id>/         # <id> 是宿主按项目根算的 hash；agent 写 projects/current/
│   ├── decisions.md        # 决策 + 为什么
│   └── pitfalls.md         # 坑 + 怎么绕
└── archive/                # 冷记忆归档区（不列出；面板可见并可恢复）
```

**工具**（4 个，路径限定白名单内，逃逸结构上不可能）：`agent_memory_list` / `agent_memory_read` / `agent_memory_write` / `agent_memory_delete`。成功只返回 `ok`——不回显、不汇报、不占上下文。每个工具都按宿主契约声明 `output { schema, render }`（**宿主 `tools.register()` 强制要求，缺了直接抛 `TypeError` 注册不上**，见 `test/host-register-contract.mjs`）。

**项目作用域别名**：agent 写 `projects/current/…`，系统解析成当前项目的真实前缀——项目 id 是宿主算的 hash，agent 无从得知也不该背（盲测实测：4 个执行者里 3 个卡在这里，只能靠猜目录名，写错就落进「查无此项目」的黑洞）。`list` 返回真实路径，两种写法指向同一文件。

**list 的输出**：`文件 · 条目`，**一条记忆一行**。曾经的「一个文件一行 + 条数」等于让 agent 读文件名猜内容——它只能二选一：不读（猜错）或整份读（付 4 KB）；条目级才能「先扫一遍、只读命中的那一份」。`MEMORY.md` 不再自我描述（目录已由系统自动生成）。

**三道硬门禁**：尺寸红线（单文件 4 KB / 60 条 / 单条 100 字符，超限**报错**要求先整理）、敏感信息扫描（密钥 / token / 密码 / 私钥拒写）、并发写串行化。

**遗忘机制**：每次 agent 读取由系统自动累计 `readCount` 与 `lastReadAt`；超过 `archiveDays`（默认 180 天）未读即移入 `archive/`、不再列出、不进索引。**面板浏览不计入** readCount——人肉翻看不该让死记忆续命。

**归档可恢复**：归档后 **agent 仍读不到**（遗忘语义不变），但面板能读到正文并一键恢复（正文搬回原位 + 清归档标记）；GET 列表返回 `archived: true` 与正文；重新写入同名文件也会自动复活。归档不再是「凭空消失」。

**写入原则**硬编码在系统提示词里（agent 改不了）：一句话一条、只写通用的、不写能从代码推导的（项目层的具体命令 / 路径正是它的价值，不受此限）、决策必须带理由且理由不自行推测、先读再写不重复、不写日期、敏感信息零容忍、**宁缺毋滥（空文件是合法的）**。

**写到哪一层**（真实缺陷驱动，见 §分层写入判据的来历）：**默认项目层**，先定层再定文件——
- 换个项目就不成立 → `projects/current/…`：含仓库名、路径、脚本、命令、端口、IP、版本号，或某个项目的 UI 裁决与部署方式；
- 进全局要过**两问**（任一为否就写项目层）：
  1. 这是不是一种**通用能力**——换任何一个仓库，这句话仍然指导你做事？（方法、流程、工具偏好、交付格式、文档风格、环境约定、通用安全纪律）
  2. 它对**其他项目**有没有帮助——别的项目的人看了能不能直接用上？
- 自检「去掉当前项目名后这句话还成立吗」，拿不准也写项目层（污染全局比写错项目代价大）。

这两问不是凭空定的：用户真实的全局记忆全是这一类——「必须用知识图谱代替 grep」「写规则文档用正向表述」「多 agent 共享模拟器要串行」「隔夜长跑先防休眠」「改动收尾要清理失效产物」；而项目记忆全是具体事实——「部署在 192.168.x.x:8080」「镜像 tag 只发 X.Y.Z」「某页面保持 5/10/15 秒档位」。

**冲突处理同样交给 agent**（系统不做查重、不设矛盾状态、不阻断写入）：写入协议先**分清真假矛盾**——不同场景/不同对象的偏好能用限定语共存就别删（「前端用 pnpm，后端用 npm」）；真矛盾（同一对象、同一维度、互斥取值）写新的删旧的，演进有解释价值时写成「（原 X，现 Y）」一句，绝不留两条并存；**写满（超限报错）时先整理**（合并近义、删被取代、精简措辞）再写——尺寸红线报错即整理触发器。

**全局层写入护栏**（确定性规则，不是模型判断）：含项目专属标识（仓库内路径 `scripts/…` / `src/…`、IP、`localhost:端口`、当前仓库名）的条目写全局会被工具**直接拒绝**，并要求改写进 `projects/current/…`。误判的代价是 agent 改写一次，漏判的代价是全局污染——两者不对称，所以宁可严。

**文件分工的边界**（盲测暴露的歧义）：`user.md` = 用户要求 / 习惯（只收**跨项目通用**的「以后每次都要做」，只在本项目成立的归项目层）；`feedback.md` = **用户纠正过你的做法** + 正确做法——同一件事只写一处，是「我原来做错了」进 feedback，是「用户要的习惯」进 user。项目层的「纠正」写 `pitfalls.md`。`MEMORY.md` 保留但**不再参与目录与 list**（目录由系统按条目自动生成，无需手写索引）。

**分层写入判据的来历**：真实用户报告「某安卓仓库专用的调试脚本与 adb 用法被写进了全局 `user.md`」。根因不是 agent 读不懂层级，而是 `user.md` 的分工写着「以及『以后每次都要做』的动作」——这一句让「本项目以后每次都做 X」也合法落进全局层。修法：把它限定为「跨项目通用」，并把判据（换项目成不成立 / 拿不准写项目层）写进硬编码提示词。三个不知情执行者的盲测全部落对层。

**面板**：设置页第四个 tab「Agent 记忆」——文件视图（正文等宽展示、可直接编辑）+ **作用域徽标**（全局 / 项目，项目内容误写进全局层时一眼可见）+ 元数据可见（创建 / 最近读取 / 读取次数 / 归档标记）+ 行内操作走设计系统的 iconbtn（铅笔 / 垃圾桶，hover 显现）+ **删除二次确认**。这是「给用户了解原因」的唯一落点。

**按项目分组折叠**：条目按 `projects/<id>/` 分组（全局一份 + 每个项目一份），**默认展开全局与最近写入的项目**，其余折叠成「项目名 · N 条」——库里项目一多，平铺列表就变成几十张卡片的长卷。分组不装归档条目（归档区仍单独一栏，只读 + 恢复）。

**跨项目晋升建议**：同一事实被写进 ≥2 个项目层（判据与写入去重**共用** `duplicates.ts` 的字符级相似度，阈值 0.5，不做模型语义判断），面板顶部给一条「可晋升到全局」建议，点「晋升到 user.md」确认后：追加进 `user.md` + 从涉及的每个项目文件删掉该条。含项目专属标识（路径 / IP / 端口 / 仓库名）的条目会被**同一个 `globalScopeReject` 护栏**拒绝，拒绝原因直接显示在建议条上（按钮置灰），绝不静默失败；全局层超限 / 建议已过期同样把原因回给面板。

| 配置键 | 默认 | 作用 |
| ------ | ---- | ---- |
| `agentMemory.enabled` | `true` | 是否启用 agent 记忆 |
| `agentMemory.archiveDays` | `180` | 冷记忆归档阈值（天）；归档项面板可见并可恢复 |

## 全局提示词（与记忆隔离）

「全局提示词」是**必须始终生效的指令**，与记忆（「可能有用的事实，按相关度挑选」）语义相反，因此两者独立：独立文件 `$DSH_HOME/memory/prompts.json`、独立设置分区、独立端点 `/my-memory/api/prompts`。

| 维度 | 全局记忆 | 全局提示词 |
| ---- | -------- | ---------- |
| 检索 | 相关性 + 时效性 + 置信度评分取 top-N、逐条摘要截断 | 无检索：**全量按序**注入，不评分不截断 |
| 写入 | agent 工具 `memory_save` | **只有设置页可写**，agent 无写工具 |
| 注入 | section `dsh-my-memory`，order -95 | section `dsh-my-memory:prompts`，order -85 |

- 启停：`enabled:false` 即不注入；全部停用时 section 返回空串（宿主丢弃空 section，零成本）；排序用「上移 / 下移」写回 `order`。
- 生效：注入读内存态，保存后**下一轮组装即生效**，无需重启或重新注册。
- 迁移：`prompts.json` 不存在时写入内置种子 `builtin:think-zh`（中文思考指令，默认启用）；文件已存在不补种，用户删除后不复活。
- 上限：`maxPromptItems` / `maxPromptLength` 是安全阀，超出条目不注入、超长正文截断（都带 warn）。
