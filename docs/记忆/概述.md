# 记忆（dsh-my-memory）

> ⚠️ **何时阅读：** 想让 agent 记住你的长期偏好（回复语言、代码风格）或项目约定（技术栈、目录规范）时，或修改本插件代码前。

## 功能一句话

**全局/项目两级记忆持久化：全局记忆在会话开始时注入系统提示词（agent 始终携带），设置页可视化面板管理（新增/修改/删除均需自定义确认 UI 确认），`memory_query` 工具只读查询记忆详情，`memory_save` 工具经用户确认后保存记忆；记忆内容精简（issue #105）：保存引导浓缩为 1-2 句、面板概要/详情两级展示、注入按语义截断不截断句子中间；渐进式索引记忆（issue #78）：会话结束后自动提取记忆候选（`autoLearn` 开关，默认关）进入待确认列表，确认后写入——条目带分类/来源/置信度/更新时间/演进历史元数据，同主题多次出现提升置信度、矛盾标记待确认、长期未用降权，注入按相关性+时效性+置信度智能选择。**

## 解决的问题

DSH 的 agent 每次会话都从零开始：用户反复交代的偏好（「回复用中文」「代码注释写中文」）和项目约定（「本项目用 vitest」「不要动 docs/」）无法持久化，每次新会话都要重新说明。本插件补上这个空白（issue #38）：

1. **两级记忆**：全局记忆（跨项目，如用户偏好、常用习惯）+ 项目记忆（按项目 cwd 隔离，如项目约定、技术栈决策）；
2. **系统提示词注入**：会话开始时把全局记忆注入系统提示词，agent 始终携带用户关键偏好；
3. **可视化面板**：设置页查看/修改/删除记忆，写操作必须用户确认（自定义确认 UI：删除红色、保存绿色）；
4. **工具查询**：`memory_query` 只读工具让 agent 查询记忆详情；
5. **工具保存**（issue #107）：`memory_save` 工具让 agent 在**用户确认后**保存记忆（`tools/pre-execute` 确认门返回 `{ kind: 'ask' }` 触发 DSH 原生审批，绝不静默变更）；
6. **记忆内容精简**（issue #105）：保存时引导浓缩（输入框提示「建议 1-2 句话概括」+ 超 `maxEntryLength` 提示精简 + 确认面板概要预览）、面板**概要/详情两级展示**（列表显示首句概要、点击展开完整详情，存储保留完整 desc）、注入**按语义截断**（优先概要/首句，不截断在句子中间）——长条目不再整段铺开、解释性话语不稀释关键信息；
7. **渐进式索引记忆**（issue #78）：会话结束后从对话**自动提取记忆候选**（偏好/事实/项目/技术栈/工作流，`autoLearn` 默认关、`extractor` 默认 rule 规则提取器、llm 为预留占位），候选进入「待确认」列表，**用户确认后才写入**（记忆绝不静默变更）；条目带**结构化元数据**（分类/来源会话/置信度/更新时间/演进历史），同主题多次出现**置信度提升/内容更新**、内容分歧标记**矛盾待确认**、长期未用**降权**，会话开始注入按**相关性（当前会话上下文）+ 时效性 + 置信度**评分选择（替代简单 top-N）。

## 工作机制

```
设置 → 插件 → 记忆（官方 slots 扩展点，纯官方依赖）
        ↓ GET /my-memory/api/session?sessionId=…（解析当前会话 cwd，打开即加载当前项目记忆，issue #104）
        ↓ GET /my-memory/api/config（精简引导配置 maxEntryLength/maxDescLength，issue #105）
        ↓ GET /my-memory/api/memory?scope=global|project&cwd=…
        ↓ GET /my-memory/api/candidates（待确认候选列表，issue #78）
        ↓ POST /my-memory/api/memory（add/update/delete，必须携带 confirmed: true）
        ↓ POST /my-memory/api/candidates/confirm|dismiss（候选确认写入/拒弃，必须携带 confirmed: true，issue #78）
<项目根>/.dsh/memory.json — 项目记忆旧位置（issue #108 前；首次访问自动迁移到新位置后清理）
$DSH_HOME/memory/projects/<项目 id>.json — 项目记忆新位置（issue #108：集中 $DSH_HOME，按项目根路径 sha256 前 12 位分文件）
$DSH_HOME/memory.json（全局记忆）
$DSH_HOME/memory/candidates.json（待确认候选，issue #78——与正式记忆完全隔离，只含自动提取未确认项）
        ↓ 原子写（tmp+rename）+ 防抖（300ms 合并写盘）+ 启动 load() 恢复
        ↓ 记忆内容精简（issue #105，lib/memory-text.js：firstSentence / summarizeDesc /
          isOverEntryLimit——概要优先、不截断句子中间，#78 自动提取可复用）
        ↓ 自动提取（issue #78，autoLearn 默认关）
session/event（user/message，过滤插件注入）→ 只读收集本次会话用户消息（内存，按会话上限）
agent/status idle（仅顶层 agent）→ lib/extract.js 规则提取器（extractor: rule | llm 占位）
        → 候选进 $DSH_HOME/memory/candidates.json「待确认」区——绝不静默写入
        → 用户确认 → store.mergeAdd 渐进合并（同主题置信度+1/内容更新/矛盾标记）
        ↓ 结构化索引（issue #78，lib/memory-scoring.js）
条目元数据：category（偏好/事实/项目/技术栈/工作流）· source（会话 id+时间）·
  confidence（多次出现提升，上限 5）· updatedAt · relatedIds · history（演进）· status（矛盾）
旧数据兼容：withDefaults 回退默认值（category=fact / confidence=1 / 空 history）
同主题渐进合并 mergeCandidate · 长期未用降权 decayConfidence（默认 90 天）
        ↓ 系统提示词注入（issue #78 智能注入，替代简单 top-N）
ctx.systemPrompt.section({ name: 'dsh-my-memory', order: -95,
  text: (context) => 读取全局记忆缓存，decayConfidence 降权后
        按 score = 相关性(上下文关键词) + 时效性(exp 衰减) + 置信度(归一化)
        pickForInjection 选 maxItems 条，每条按语义截断 maxDescLength 字符})
  → 每次组装系统提示词时求值：会话开始即注入，记忆变更后下一轮即时生效
        ↓ 工具
ctx.tools.register(memory_query)（只读：全局/项目过滤 + 关键词过滤，
  项目 cwd 取会话工作目录 exec.agent.session.header.cwd）
ctx.tools.register(memory_save)（写：scope/desc 必填、cwd 可选，工具描述引导
  「浓缩为 1-2 句」；每次调用经 tools/pre-execute 确认门 → { kind: 'ask' } 触发
  DSH 原生审批，用户确认后才写入，绝不静默变更）
```

## 安装与使用

1. 安装插件：

   ```bash
   dsh plugin --profile web add dsh-my-memory --trust-lockfile
   ```

2. 打开 DSH Web 设置 → 插件 → **记忆**；
3. **全局记忆**区块：输入要记住的内容（输入框提示「建议 1-2 句话概括」，超过 `maxEntryLength`（默认 50 字）显示「内容过长，建议精简为 1-2 句」，确认面板显示概要预览）→ 绿色「新增」→ 绿色确认面板「确认保存」→ 写入 `$DSH_HOME/memory.json`（完整内容保留，列表只显示概要）；条目可「编辑」（绿色保存确认）或「删除」（红色确认面板 + 红色「确认删除」二次确认），点击概要右侧「展开」可查看完整详情；
4. **项目记忆**区块：**面板打开时自动加载当前会话项目的记忆**（issue #104，通过 `/my-memory/api/session` 解析当前会话工作目录，复用 `memory_query` 的会话 cwd 定位逻辑），显示项目记忆（蓝色 accent + 项目根徽标），操作同全局；无项目会话时项目区块显示「输入项目根路径加载项目记忆」的友好空状态提示。也可在顶部输入其他项目根路径 → 「加载」切换查看其他项目记忆；
5. **自动学习候选（issue #78）**：开启 `autoLearn` 后，会话结束自动从对话提取记忆候选，显示在面板底部「自动学习候选（待确认）」区块（带分类徽标 + 来源会话 + 时间）——点「确认写入」候选渐进合并进正式记忆（同主题自动提升置信度），点「拒弃」丢弃；候选绝不静默写入正式记忆（确认/拒弃都需用户显式动作）；
6. 新会话开始时，全局记忆自动注入系统提示词（agent 可见）；agent 可用 `memory_query` 工具查询记忆详情（含项目记忆），也可用 `memory_save` 工具在**用户确认后**保存记忆——发现值得记住的信息时可请 agent 保存（如「把「用 pnpm 装依赖」记到记忆里」）。

## 配置

插件配置（`cordis.yml` 中 `my-memory` 的 `config` 字段）：

```jsonc
{
  "maxItems": 5, // 注入系统提示词的全局记忆条数上限（默认 5；#78 起按相关性+时效性+置信度评分选 top-N）
  "maxDescLength": 200, // 单条记忆注入长度上限（字符，默认 200；语义截断优先概要/首句）
  "maxEntryLength": 50, // 建议单条记忆长度上限（字符，默认 50；超长时面板提示精简，issue #105）
  "autoLearn": false, // issue #78 自动学习开关：会话结束自动提取记忆候选进「待确认」区（默认关；开启后才提取，确认后才写入）
  "extractor": "rule", // issue #78 提取方式：rule（确定性规则提取器，默认）| llm（预留占位，接入 LLM 总结式提取）
  "proactivePropose": false, // issue #78 阶段预留：开启后 memory_save 工具描述引导 agent 主动向用户提议保存记忆（默认关，agent 按用户要求保存）
}
```

## 边界与限制

- 项目记忆以 `cwd` 向上找 `.git` 定位项目根；无 `.git` 时退回 `cwd` 自身；
- 项目记忆集中存 `$DSH_HOME/memory/projects/<项目 id>.json`（issue #108，项目 id = 项目根路径 sha256 前 12 位），项目目录不再产生 `.dsh/memory.json`；旧位置 `<项目根>/.dsh/memory.json` 的数据在首次访问该项目时自动迁移到新位置（成功后清理旧文件与空 `.dsh` 目录），已有记忆不丢失；dsh-my-skill-manager 的项目配置仍存项目目录，是否一并集中到 `$DSH_HOME` 另行评估（README 注明）
- 系统提示词只注入**全局**记忆（项目记忆按项目隔离，agent 需用 `memory_query` 查询）；
- `memory_save` 每次调用都经 `tools/pre-execute` 确认门触发 DSH 原生审批（`{ kind: 'ask' }`）——用户拒绝则不写入，记忆绝不静默变更；
- 注入受条数/长度上限约束，超出部分不注入（避免提示词膨胀），且**按语义截断优先概要/首句**，不截断在句子中间（issue #105）——注入的是概要而非整段解释性话语；
- 记忆内容精简（issue #105）是**引导与展示层**：存储始终保留完整 desc（不丢信息），面板/注入只在展示时计算概要（`maxEntryLength` 默认 50 为建议长度，不硬拒绝超长保存）；`memory_text` 纯函数（概要/首句/语义截断）为 #78 自动提取预留同一精简约束；
- **自动提取（issue #78）绝不静默变更**：`autoLearn` 默认关；开启后会话结束只把候选写进独立的 `$DSH_HOME/memory/candidates.json`（正式记忆文件只含用户确认过的条目），确认/拒弃需用户显式动作（API 强制 `confirmed: true`）；
- **自动提取为规则提取器**（`extractor: 'rule'`）：基于用户消息的偏好/事实/项目/技术栈/工作流句式模式匹配（确定性、可测；含「本项目」等关键词的候选建议 `scope=project`，需要会话 cwd 才标记项目并对按 cwd 写入对应项目记忆）；`extractor: 'llm'` 为预留占位（接入 LLM 总结式提取，当前不产生任何写入）；
- **渐进更新口径**：同主题判定 = 分类一致且归一化文本互为包含/子序列（措辞不同算同主题，如「回复使用中文」↔「回复必须使用中文」；语义分歧如中英文不算；跨明确分类不坍缩）；同主题合并置信度 +1（上限 5）、内容取最新、分歧时标记 `conflict-pending`；长期未用（默认 90 天）置信度 -1（下限 1）；注入评分 = 0.5×相关性（上下文关键词命中占比）+ 0.3×时效性（7 天半衰期 exp 衰减）+ 0.2×置信度归一化（`lib/memory-scoring.js` 可配置权重）；
- 面板为可选增强：`ctx.get('slots')` 缺省时静默跳过注册，server 端记忆能力不受影响（与「纯官方依赖」原则一致，不依赖 dsh-better-sidebar）。
