# 发版坑

## 症状关键词（可 grep）

- Release workflow 的版本校验步骤失败（Release 未创建、npm 未发布）
- `tag version '<x>' does not match plugins/<插件> package.json version '<y>'`
- `lsof -ti :3087` 仍有进程、`/tmp/dsh-verify-real-*` 目录残留（父进程提前退出留下的孤儿实例）
- 并行发版时多个插件日志出现同一个端口号、两个实例互相踢
- `! [rejected] main -> main (fetch first)`（改了 `url` 没改 `pushurl`，`--push` 仍往 GitHub 推）

## 根因

版本校验比的是 tag 里 `@v` 之后的**裸版本**与 tag 指向 commit 的 `package.json` 版本：任一侧带 `v` 则任何 tag 都失败；另一形态是手动 bump 后**没提交**，tag 指向的 commit 里仍是旧版本。并发改变的是**资源生命周期**：串行时天然成立的「某门禁失败就提前 return／kill」会让已启动的隔离实例变成孤儿（清理只在自身控制流里，没注册信号处理器）；各插件自探端口的探测—释放—启动窗口在并行时必然撞端口；git 推送时 `pushurl` 优先于 `url`。

## 修法

- 手动 bump 后先提交再发版（或用 `--bump` 让脚本自动 bump + 提交）；校验失败后删旧 tag 重打重推。
- 并发启动的门禁**必须在返回前全部 await 完，失败路径也不例外，绝不 kill 它们**；端口由调度层预分配互不相同的值再传给各插件。
- 发版后校验：确认 Release 已创建与 npm 版本已发布，任一超时未完成即 exit 1，不许静默失败。
- 做 `--push` 的本地集成验证前先自检 `git remote get-url --push origin` 必须回显 bare 仓库路径；改指向时 `url` 与 `pushurl` 两个都改，否则「本地验证」会变成真实外发动作。

## 活引用

- `.github/workflows/release.yml`（版本校验步骤）、`scripts/release.mjs`
- `scripts/lib/post-release.mjs`（发版后校验）
- `scripts/lib/release-checks.mjs`（端口预分配）、`scripts/test/release-ports.test.mjs`
- `scripts/verify-real-profile.mjs`（无信号清理，故父进程不得提前退出）
- `docs/开发指南/发版流程.md`（门禁与并发发版约定）、`skills/plugin-release/SKILL.md`
