# 安全告警修复引入资源上限退化

## 现象

`76f52ac`「修复 GitHub Code Scanning 安全漏洞 (43 个)」批量消除了 `js/file-system-race` 告警：把「`stat` 先检查再 `readFile`」改成「直接 `readFile`，读完再判大小」。**告警数归零，但正确性和资源上限同时被削弱**，且因为测试只断言"返回 null / 跳过"，全绿 CI 完全没有察觉。

3 个代码文件命中同一模式，第 3 处（`dsh-file-activity/src/media-route.ts`）被 #318 新增的产物一致性门禁翻出来，才牵出前两处。

**严重性按实测口径分级（不要夸大）**：

| 级别                     | 实例                                                                                          | 判据                                                                                                          |
| ------------------------ | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| **在途缺陷**（用户可见） | `media-route` 状态码被吞（#318）；`poison`/`check-links` 的**字节账**（中文/emoji 低估 3 倍） | 当前调用路径可达，且已有行为/上报数据被改写                                                                   |
| **纵深防御损失**         | `poison::readText` 的 `isFile()` 闸门、`check-links` 的读前大小闸门                           | 当前路径不可达（被上游 `dirent.isFile()` / `SKIP_PATH_RES` 挡住），但闸门被移除后一旦上游放宽就会变成在途缺陷 |

| 位置                                   | 退化                                                                                             | 后果                                                                                                                                                                                                                                                                                    |
| -------------------------------------- | ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dsh-file-activity/src/media-route.ts` | 空 `catch {}` 把 `EISDIR` / `EACCES` / `ENOENT` **全吞成 404**；`!info.isFile()` 消失            | 目录请求 400→**404**（目录明明存在，却说 "file not found"）；权限拒绝 403/500→**404**，诊断能力归零；且这是**已发布行为**被静默改写                                                                                                                                                     |
| `dsh-my-guard/src/poison.ts::readText` | ① `isFile()` 闸门丢失 ② `handle.bytes += info.size`（**字节**）→ `content.length`（UTF-16 码元） | ① 上限判定发生在读**完**之后（**纵深防御**：当前 `scanDir` 的 `dirent.isFile()` 过滤让 FIFO 到不了这里，实测直调 `readText` 才会挂起；`/dev/zero` 同理）；② 中文/emoji 源码字节账最多**低估 3 倍**（在途缺陷），`scannedBytes` 失真、预算被变相放宽（常量名就叫 `MAX_SCAN_FILE_BYTES`） |
| `scripts/check-links.mjs`              | ① `statSync(abs).size > MAX` 预先跳过 → **先整文件读进内存再判大小** ② 字节→字符                 | 任何 >1MB 且未被 `SKIP_PATH_RES` 排除的文件都会被整份读入内存再丢弃（旧代码根本不读）；中文文档的字节量最多被低估 3 倍，接近上限时漏跳                                                                                                                                                  |

## 根因

**「消除 stat→read 的 TOCTOU」被误等价成「删掉 stat」。**

`stat(path)` 和 `readFile(path)` 是**两次按路径解析**，中间目标可被替换 —— 这是 CodeQL 报的竞态，真实存在。但"检查"本身不是问题，**检查与读取用了两个不同的对象**才是问题。删掉检查只是让告警消失，把风险换成了没有闸门。

正解是让 stat 和 read **作用在同一个 fd 上**：

```ts
const fh = await open(path, 'r')
try {
  const info = await fh.stat() // 作用于 fd：与后续读天然同源，无竞态
  if (!info.isFile()) return null // 类型闸门保留
  if (info.size > MAX) return null // 字节闸门保留，且超大文件不会先被读入内存
  const buf = await fh.readFile()
} finally {
  await fh.close()
}
```

四条同时成立：**CodeQL 不再报竞态、类型闸门在、字节账准确、超大文件不读入内存** —— 不需要拿任何一条去换另一条。

配套要求：catch 不要写成空 `catch {}` 复用给所有 errno。`EISDIR`（是目录）、`EACCES`（没权限）、`ENOENT`（不存在）是三件不同的事，混成一个 404/null 之后，线上问题再也无法从状态码或日志里分辨。

## 为什么 CI 全绿

三处都**有测试**，测试**都通过**——因为断言只覆盖"成功路径 + 返回 null/跳过"，从不覆盖"为什么被拒"：

- `poison` 的测试只断言"不可读/超限返回 null"，没有断言 `handle.bytes` 的**单位**。
- `check-links` 的测试只断言超大文件"被跳过"，没有断言它**没被读进来**。
- `media-route` 的测试断言了目录 → 400，但因为 `src` 改了而 `lib`（产物）没重建，**跑的是旧产物**，红用例被产物陈旧掩盖（这正是 #318 产物门禁要防的）。

判据：**任何"先读后判"的检查都必须回答一句「读之前能不能先拒绝」**。如果答案是不能，说明漏了类型/大小闸门；如果有人为了过 CodeQL 把它改成不能，那是把门禁换成了告警数字。

## 规避

1. 处理 `js/file-system-race` 时，**禁止**用"删掉 stat / 读完再判"消警；一律用 `open` + fd `stat` + fd 读。
2. 新增"读文件"路径时，catch 不允许裸 `catch {}` 兜住全部 errno；至少区分"不存在 / 是目录 / 无权限"。
3. 涉及资源上限（字节/条数/时长）的字段，**测试必须断言单位**：构造 UTF-8 中文文件断言字节数而非字符数。
4. 因安全告警而改动的**行为契约**（状态码、上限语义）改动，必须单独成条并留痕——"顺手把断言改成新行为"等于把回归固化成契约。
5. 已发布插件的行为变更需**先同步 src 与产物**再判定，产物陈旧会让红用例指向错误的契约。
6. `open` 必须带 `O_NONBLOCK`：FIFO 在**没有写端时连 `open` 都会一直等**（不是等到 read 才等），只把检查挪到 fd 上仍会在 open 阶段挂死；`O_NONBLOCK` 对普通文件无副作用，类型判定依旧交给 fd `stat`。测试用 `Promise.race` + 硬超时钉住"立即返回"，否则 CI 会挂在那里而不是红。
