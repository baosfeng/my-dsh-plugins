# 宿主运行时陷阱

## 症状关键词（可 grep）

- `yield* (intermediate value) is not async iterable`（发消息即失败，`code: UNKNOWN`）
- `cannot get required service "<服务名>" in inactive context`（`dsh web` 启动 exit 1）
- `fatal load failure`（局部 `inject` 回调内抛错冒泡）
- `ctx.events._hooks`、`hook.ctx.fiber.name`（判定注册落在谁持有的 fiber 上的探针字段）
- `style[data-dsh-file-activity]` 在 `document.head` 里缺失 → 页签纯文字无样式（无报错）
- 监听器明明 `return` 了值，发送方却永远拿到 `undefined` → 聚合端点给每个插件编造"运行中"的假状态
- `N entries did not activate`、`pending (waiting for service: webRuntime)`（升 0.2.1 后插件整条不工作，无 fatal）

## 根因

loader 会回收 profile 插件自身的 fiber，挂在它上面的 `ctx.on`／`ctx.effect`（含路由注册）随之静默消失：事件 0 触发、路由 404、日志无报错；注册落在常驻 root fiber 上则不受影响。顶层 `inject` 在 ctx inactive 时解析即抛错（且发生在 `apply` 之前），局部 `inject` 回调可能晚到。`llm/stream` 的 waterfall 同步调用 `next()` 且不 await listener 返回值：async listener 把流包成 Promise，`for await` 消费方不报错而 `yield*` 委托方直接崩。

## 修法

- 监听／路由注册到常驻 root（`ctx.root ?? ctx`），监听带 `{ global: true }`，路由自持 disposer；用**以 root ctx 为键的 WeakMap** 去重（loader 会多次 apply 同一插件）。
- 静态样式不依赖任何服务：放 `apply` 最前无条件注入，每个 fiber 持自己的 `<style>`、disposer 只删自己的。
- 顶层 `inject` 写空数组，依赖改由 apply 内 `ctx.inject([...], cb)` 局部等待，**cb 内再包 try/catch + warn 降级**，绝不 fatal。
- `llm/stream` 的 listener 必须是**同步函数**（直接 `return wrap(next())`，禁 async）。
- 快速排除：查 `document.head` 里插件的 `<style>` 是否缺失、实例能否启动；单测 mock ctx 结构性复现不了这些坑，必须用隔离实例验「能启动 + 路由/UI 有响应」。

## 事件分发返回值：`emit` / `parallel` / `serial` 三种契约各不相同

**症状**：监听器明明 `return` 了值，发送方永远拿到 `undefined`。写成 `Promise.race([ctx.emit(...), timeout])` 时 race **立即**以 `undefined` 落定，`result ?? { running: true, … }` 这类兜底会**静默编造**假数据——真机表现是聚合端点给每个插件都报"运行中"、stats 全空，且没有任何报错。

**实测契约**（cordis 事件总线实现：参考源 `vendor/cordis/src/events.ts` 的 `isBailed` / `emit` / `parallel` / `serial` / `bail`；本机对应实现见本机运行包 `node_modules/@deepseek-ai/cordis/lib/index.js`）：

| 派发       | 对监听器返回值的处理                                              |
| ---------- | ----------------------------------------------------------------- |
| `emit`     | 同步派发，**不收集**（返回值直接丢弃）                            |
| `parallel` | await 全部监听器，但**只处理异常、不返回结果**（`Promise<void>`） |
| `serial`   | 顺序 await，**返回首个非 `null`/`false`/`undefined` 的返回值**    |
| `bail`     | **同步**派发（不 await 监听器），同样返回首个非 `null`/`false`/`undefined` 的返回值——async 监听器返回的 Promise 本身就被当成 bail 值 |

**修法**：要收集监听器返回值只能用 `serial`（`bail` 是同步派发，async 监听器会立刻以 Promise 落定），并配合**逐项查询 + 按名比对**——非匹配监听方一律 `return undefined`，因此一次 `serial` 恰好命中唯一那一条。**无匹配响应必须如实标记**（如 `no-response`），不得编造"运行中"；同理，服务清单取不到时保持"空列表 + 200"，不要退化成猜测。

**判据（探针实测输出，真实 cordis 事件总线）**：

```text
parallel(...)    => undefined
serial(match)    => {"ok":true,"value":{"plugin":"dsh-file-activity","running":true,"stats":{"files":7}}}
serial(no-match) => undefined
```

## 0.2.1 升级后插件 pending（`waiting for service: webRuntime`）

**症状**：隔离 profile 冷启动打印 `dsh: warning: 3 entries did not activate`，逐条为 `file-activity (dsh-file-activity): pending (waiting for service: webRuntime)`（my-memory / my-skill-manager 同）；无 fatal、端口照常监听，但插件的路由 404、页签与 API 全不工作。

**根因**：0.2.1 起 web profile **不再提供 webRuntime 服务**（0.2.0-rc.2 的参考源是 `packages/bundle/web-app/src/index.ts:38` + `:231 ctx.provide(WEB_RUNTIME_SERVICE, runtime)`，0.2.1-rc.1 已删、改为 `ctx.provide('webApp', …)`；官方[升级指南 v0.2.1-alpha.1](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/upgrade-guide/v0.2.1-alpha.1/web-listener-trust-config/guide.zh.md)）。插件顶层 `inject: ['webRuntime']` 或 `ctx.webRuntime.trustedHosts` 表达式在等一个永不挂载的服务——宿主只报 pending，不会报插件代码错。

**解法**：信任源改用 dsh-shared `createTrustFence(ctx)`（`webStartup.trustedHosts`（`--trusted-host`）+ `webServer.host`；旧宿主自动回退 webRuntime，插件**别再自己读 webRuntime**）；**移除顶层 inject 里的 webRuntime 硬依赖**（fence 每次请求现读，服务晚就绪也能拿到）；`types.d.ts` 最小契约同步改成 `webStartup` / `webServer`，`WebRuntimeService` 只留可选兜底。

**取证（隔离 profile 冷启动）**：

```bash
export DSH_HOME=/tmp/dsh-verify-021            # 独立 DSH_HOME，别污染生产 ~/.dsh
mkdir -p "$DSH_HOME/profiles" && cp -R ~/.dsh/profiles/web "$DSH_HOME/profiles/web"
dsh --profile web --port 3099 --no-open        # 冷启动；输出与 $DSH_HOME/dsh-web.log 同看
grep -E "did not activate|waiting for service" "$DSH_HOME/dsh-web.log"
```

判据：`did not activate` 行点名的服务名 = 插件仍在硬等的服务；`0` 条命中且日志只剩 `dsh web: http://127.0.0.1:<port>/?token=…` 才算恢复。
