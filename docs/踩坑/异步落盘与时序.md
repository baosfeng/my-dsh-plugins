# 异步落盘与时序

## 症状关键词（可 grep）

- `AssertionError: buffered alert merged with loaded state`、`Expected: 2, Received: 1`
- `'checking' !== 'done'`（业务异步流程还没跑到保存那一步，盘上仍是旧值）
- `write blocked N time(s) — dropping pending snapshot`（唯一线索，静默丢状态）
- `store.whenReady is not a function`（实现侧压根没有就绪信号）
- 断言前一行是 `settle(` 或 `sleep(`（墙钟依赖的签名）

## 根因

测试用固定 `setTimeout` 猜「异步加载 + 防抖落盘」已完成，结果取决于墙钟而非条件，CI 容器高负载下随机红。另一形态：`createWriteScheduler` 与 `atomicWriteJson` 同时开节流，调度器间隔短于快照原语窗口时每次非 force 写都被拒，重排耗尽即放弃且不报错，状态永不落盘。

## 修法

- 读之前等**确定性就绪信号**：实现侧补 `whenReady()`／`bootPromise`／`drainSaves()`，API 分派前 await；测试侧把固定等待换成 `waitFor(条件)`。
- 「就绪」= **所有会写盘的异步链**都完成，含 fire-and-forget 的启动预检与业务异步流程本身；漏一条等于没信号。
- 写入节奏只能有一个来源：用调度器就传 `minIntervalMs: 0`，否则节流职责归快照原语。
- **就绪信号必须名副其实**：只 drain 写链的 `whenPersisted()` 在加载未完成时写链为空、会**立即 resolve**——「有信号」比「没信号」更危险，调用方以为已安全。信号要同时覆盖加载与写链。
- **读路径不得静默跳过**：预算/校验类入口取不到状态时显式等待或记录，不能 `return next()` 悄悄放行——这类生产缺陷永远不会以 CI 红的形式暴露。
- 门禁：`scripts/check-test-sleeps.mjs` 要求**新增**固定 sleep 必须写 `// sleep-ok: <理由>`，存量冻结在基线（只许变少）——禁的是无理由 sleep，不是 sleep 本身。
- 快速判定：删掉全部 `sleep`／`settle` 再跑，变红的用例即依赖墙钟的清单；节奏契约回归 `cd plugins/dsh-shared && npx vitest run test/scheduler-throttle-conflict.mjs`。
- 同族近亲（issue #353）——**绝对耗时断言**与**框架默认超时**：
  - `elapsed < 5ms` / `Date.now() - start < N` 这类断言测的是**机器负载**，不是被测对象；多 agent 并行（local load 24~157）下必红、单跑必绿 ⇒ 本地红 CI 绿的假红。
  - 改法优先级：① 断言**行为/代码路径**（如"返回时目标文件尚未写出"证明 I/O 不在调用路径上；"无挂起写时 drain 不设定时器"证明快路径）② **比值**（输入 ×10 → 耗时 ≈×10 是线性，×100 是 O(n²)；负载被两侧约掉）③ **分布**（多次采样取分位数）。
  - 进程级 / 端到端用例（spawn node + git/commitlint/gitleaks、重建 client bundle）**必须给显式超时**；根 `vitest.config.mjs` 与 `scripts/test/vitest.config.mjs` 已把 `testTimeout` 提到 60s。
  - **放宽框架超时 ≠ 放宽判据**：前者是「允许慢」（停机保护），后者是「允许错」。禁止用「调大阈值」换绿——那只是把红推迟到下次负载更高时。
