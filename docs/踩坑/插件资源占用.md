# 插件资源占用

## 症状关键词（可 grep）

- 症状面：CPU 持续高位、RSS 涨到 GB 级、磁盘写入每小时数百 GB（长会话或多子 agent 后出现）
- `write throttled (minIntervalMs=`、`write rejected (`（护栏拒绝写入的告警）
- `COMPACT_LINES`（增量追加的 compact 阈值）
- `DEFAULT_RESOURCE_LIMITS`、`shouldEnterDegrade`（阈值口径与降级判定）
- `session_projcache.json`（DSH 核心同类写放大，插件不能假设运行时自带护栏）
- `resource-smoke`（资源回归门禁 job）

## 根因

高频事件监听（agent 状态、LLM 流 chunk、工具调用、文件操作）触发「防抖 + 全量 `JSON.stringify` 整个状态 + 原子替换写盘」。事件数万条后状态膨胀，单次写字节与序列化 CPU 随状态大小线性增长，写放大可达数百倍——功能正确、资源失控。

## 修法

- 事件流型**禁用快照原语**：走 jsonl 增量 append + 周期 compact；只有汇总统计型状态才用全量快照。
- 所有状态必须有上界：事件数与字典条目（FIFO／LRU 淘汰）+ 字节上限；护栏默认 `minIntervalMs` 1000ms、`maxBytes` 1MB，显式放宽即等于自证状态有界。
- 超限必须有动作而非只告警：用 dsh-shared 的资源护栏（连续确认进入／退出）做降级——停落盘但内存仍记录，恢复时全量快照；不要自己再写一个看门狗。
- 门禁与口径：`node scripts/resource-smoke.mjs` 断言写放大、内存有界、降级触发与恢复；五维预算按 `skills/resource-budget-review/SKILL.md` 逐维填数字（写放大倍数与内存上界不能省）。
