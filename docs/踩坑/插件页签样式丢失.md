# 插件页签偶发"纯文字无样式"

## 症状

侧边栏「文件活动」页签**偶发**变成无样式状态：图标退化为基础描边、彩色徽标（读/增/改）消失、按钮变纯文字、无背景无边框——像一份纯文本清单。刷新页面后恢复正常（"有的时候出现"）。

## 根因（2026-08-23 定位）

`lib/client.js` 的 `apply()` 里，样式注入 effect 被放在「服务判空早退」之后（当时是第三方侧边栏服务）：

```js
exports.apply = function apply(ctx) {
  const service = ctx.betterSidebar
  if (service === undefined) return   // ← 服务暂不可用就退出
  ...
  ctx.effect(() => { ...注入 <style>... }, 'dsh-file-activity: styles')  // ← 永远到不了
}
```

HMR 重建 / 服务重载的瞬间，新 fiber 的 `apply` 可能在服务暂不可用时执行 → 提前 return → **样式标签未注入**；而页签 DOM（旧渲染）仍在 → 纯文字。CSS 变量（`--dsw-alias-*`）本身没问题（检查确认可解析），缺的是插件注入的 `<style data-dsh-file-activity>`。

## 修复

样式是纯静态 CSS，不依赖任何服务——把样式注入 effect 移到 `apply` **最前面无条件执行**（早退之前），每个 fiber 持有自己的 `<style>` 元素、disposer 只删自己的，HMR 重建后至少保留一份。已提交（版本 0.4.2）。

## 解决参考

- 侧边栏页签/预览器插件：**样式注入不得依赖任何服务**（无论第三方侧边栏服务还是原生 `slots` / `sidebarRightTabs`），必须放 `apply` 最先无条件执行。issue #187 批 1 的 6 个插件迁移时均保持该顺序（样式 effect 在服务判空之前）。
- 通用检查：出现"纯文字"先查 `document.head` 里插件自己的 `<style>` 标签是否缺失（`document.querySelectorAll('style[data-...]')`），再查 CSS 变量在元素上是否可解析。
