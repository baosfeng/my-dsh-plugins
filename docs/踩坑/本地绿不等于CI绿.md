# 本地绿不等于 CI 绿（校验类工具的环境差异）

## 现象

新增的文档引用完整性门禁 `scripts/check-links.mjs` 本地 876 个文件全绿，**接入 CI 首次运行就红**：

```text
✗ 引用完整性检查失败（1 项）：
  docs/开发指南/NNNN.md:50  [path] .github/pull_request_template.md
  → 路径不存在（文件目录、祖先目录、仓库根均未命中）
```

而仓库里真实存在的文件名是 **`.github/PULL_REQUEST_TEMPLATE.md`（全大写）**——文档写的是小写。

同一个根因还同时打红了另一项：`npm run test:scripts` 里"用真实仓库自检"的那条单测（同一个 finding 让它断言失败）。**一项环境差异，两处红。**

## 四类环境差异（本例实测，按踩中顺序）

| 差异                      | 为什么本地过                                                            | 为什么 CI 红                              | 修法                                                         |
| ------------------------- | ----------------------------------------------------------------------- | ----------------------------------------- | ------------------------------------------------------------ |
| **文件系统大小写**        | macOS/APFS 默认不区分大小写，`existsSync('DOCS/x.md')` 返回 true        | Linux 区分大小写，同名不同大小写 = 不存在 | **逐段枚举真实目录项做精确名字比对**，不再依赖 `existsSync`  |
| **home 下的同名顶层目录** | 本机恰好存在 `~/scripts`，让相对路径 `scripts/…` 通过 home 兜底"假命中" | CI 的 HOME 是干净的，兜底不成立           | 把 home 兜底**限定为 `~/` 前缀**的写法                       |
| **全局资源目录存在性**    | 本机有 `~/Documents/skills`、`~/.dsh/skills`、`.reasonix/skills`        | CI 里都没有（只检出仓库）                 | 显式白名单登记外部资产 + **用空 home 跑真实仓库**做自检      |
| **Unicode 规范化**        | HFS+/APFS 可能把中文名 NFD 化，git 存 NFC                               | 同上，Linux 无此行为                      | 实测排除：抽查 200 个「git 名 vs readdir 名」精确比对 0 失败 |

## 仍未覆盖的残余（诚实列出）

- **Node 版本差异**（本地比 CI 新）：~~未覆盖~~ **已于 2026-09-11 消除**——CI 的 `node-version` 已由 22 升到 26，与开发者本地 v26.7.0 同主版本；本脚本只用 Node 20+ 的稳定 API，同主版本下不再有"本地新、CI 旧"的差异。诚实边界：CI 通道的 26 以该通道工作流的实际运行为准。
- **符号链接**：逐段枚举会跟进 symlink 指向的目标目录，若指向仓库外则本地可命中、CI 不可。当前仓库无此类 symlink。
- **git 不可用时的目录遍历回退**：会扫到未跟踪文件，与 CI 的 `git ls-files` 语义不同（只在"用 tarball 部署后跑门禁"时才会造成差异）。
- **`git add` 之前的文件**：本地不检查未跟踪文件（CI 上全是已跟踪），方向是**漏报而非误报**。

## 通用教训

1. **校验类工具的判定必须与宿主环境解耦**：凡是"这个路径存在吗"的问题，都不要直接交给宿主 FS 语义（`existsSync` 在 macOS 上对大小写是无条件宽容的）。要用**确定性规则**（枚举真实目录项、显式白名单）表达"什么算有效"，让本机与 CI 得到同一个答案。
2. **"本地绿"不能当作"CI 会绿"的证据**：把 CI 环境的关键差异（空 home、大小写敏感、无全局目录）**固化成自检用例**，而不是靠"我这儿跑过了"。
3. **失败方向很重要，但不等于可以不管**：本例方向是安全的（CI 拦住、不会漏），代价却是"本机永远测不出这类错误"，于是每次都要等 CI 跑一轮才发现——把反馈周期从秒级拖成分钟级，本身就是缺陷。
