# 生成器重写人工编辑的文件（清单留痕被抹掉）

> issue #329。**反模式**：一个"生成器"把**人工也在编辑**的文件当成自己的纯产物整文件重写 ——
> 人工写进去的东西在下次生成时静默消失。这里的具体形态是发版门禁证据被删。

## 现象

`node scripts/verify-real-profile.mjs --checklist verification/<插件>-<版本>.md` 会**整文件重写**目标清单。
已发布的 `verification/dsh-think-zh-expand-0.4.10.md` 在发布后被重跑一次，结果：

- 末尾整段「验证记录（真实环境证据）」**45 行被删除**（含缺包演练命令、隔离实例证据、
  真实模型会话结论、未覆盖项如实记录）；
- 头部「验证时间 / 端口」被改写（`3092` → `3087`）—— 对已发布版本是**纯假 diff**；
- 改动以**未提交状态**留在工作区，表现为普通 working-tree 改动。

实测复现（用改动前的生成逻辑对 0.4.10 跑一遍）：`diff` 显示 **43 行删除 + 2 行改写**。

## 为什么危险

1. **丢失发版门禁证据**：验证记录是 issue #67 功能级验证的留痕，删掉后无法追溯"当时怎么验的"
   （哪些项没验、环境限制是什么）。
2. **容易被误提交**：它看起来就是一份普通的文件改动，混在其他改动里会被顺手带上，把证据一起提交掉。
3. **惩罚正常操作**：重跑是**正常操作**（复验、换端口复现、排查 flaky），却被这个副作用惩罚 ——
   会让人不敢重跑（"一跑就丢证据"）。

**它已经真的造成了历史损失**：`git log -S'## 验证记录'` 显示 4 个 commit 删除过人工验证记录段，
其中 `4cfed8f`（commit message 就写着"验证清单自动重生成（3c 勾选保持）"）删掉 `dsh-my-remote-0.1.0`
的 35 行记录、`7a9e260`/`456ba85` 删掉 `dsh-my-skill-manager-0.1.7` 的 56 + 95 行记录。
这些内容只存在于 git 历史里，HEAD 上已经没有了。

## 根因

生成器假设"目标文件是我生成的，所以我可以重写它"，但**清单是脚本与人工共同拥有的文档**：

| 部分                                          | 真正的主人                               |
| --------------------------------------------- | ---------------------------------------- |
| `## 自动验证项` 段                            | 脚本                                     |
| 头部「验证时间 / 验证环境」的历史值           | 人工（它是**当时**那一次验证的环境记录） |
| `## 功能级验证项` 的勾选结论                  | 人工                                     |
| `## 功能级验证项` 之后的一切（`## 验证记录`） | 人工                                     |

旧实现只做了"保留功能级 `[x]`"（按文案合并）这一步，其余整文件覆盖 —— 于是人工段落被删、
头部被改写。

## 解决

`scripts/lib/verify-checklist.mjs` 把上面这张"谁拥有哪一段"的表显式建模（纯函数，可单测，
**不需要启动任何隔离实例**）：

1. 目标文件**不存在** → 按模板新建；
2. 目标文件**已存在** → **幂等合并**：
   - 头部（标题 / 验证时间 / 验证环境）**逐字节保留**（时间戳每次必然不同，任何"刷新"都必然
     产生假 diff；需要把本轮环境写进留痕时用 `--refresh-header` 显式开启）；
   - 自动验证项：本轮结果权威（`[ ]` → `[x]`），本轮新增项补入；上一轮有、本轮没有的项**保留不删**；
   - 功能级验证项：勾选状态逐字节保留，只补入模板新增项；
   - `## 功能级验证项` 之后的一切（人工段落）：**逐字节原样**；
3. 结构不可识别（缺锚点）→ **返回原文**（fail-closed：宁可不更新，也不丢人工记录）。

## 通用判据（下次写生成器时先问这四句）

1. **这个文件除了我，还有谁在写？** —— 有第二个人类作者，就不能整文件重写。
2. **重跑是否幂等？** —— 同一份输入（含"只换了环境参数"）连跑两次，`git diff` 必须为空。
   幂等是**可验收的硬判据**，不是"注意一下"。
3. **易变值（时间戳 / 端口 / pid / 随机 id）写在哪？** —— 写进"冻结区"（首次生成后不再改），
   或只在显式开关下刷新；否则每次运行都产生假 diff。
4. **识别不了既有格式时怎么办？** —— 必须 fail-closed（原样保留 + 明确告警），不许"猜着重写"。
