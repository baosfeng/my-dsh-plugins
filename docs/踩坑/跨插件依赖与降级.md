# 跨插件依赖与降级

## 症状关键词（可 grep）

- `Element type is invalid: expected a string … but got: null.`
- knip 报 `Unused dependencies`（client 端经 `inject` 使用的依赖被误报）
- reconcile 警告 `installed as a plain dependency, not a profile layer`
- 装完 A 但 `dsh.profile.bundles` 里没有 B → B 的服务 `inject` 缺失、client 崩溃

## 根因

`dsh plugin add` 会 pnpm 安装并 reconcile：把 `dependencies` 里**声明了 `dsh.bundle.patch`** 的包自动追加进 `dsh.profile.bundles` 层栈（级联安装 + 自动加载）；只写在 `peerDependencies` 不会自动装。假降级的根因是 `try/catch` 只让 `require` 不抛、把组件变量置成 null，渲染路径仍裸调 `createElement(MarkdownView, …)` → 崩溃从加载期挪到渲染期。

## 修法

- 跨插件依赖写进 `dependencies`（semver 范围要真覆盖兼容版本）；宿主运行时（cordis/react）留 `peerDependencies`；client 端经 `inject` 使用而非 import 的依赖，在 `knip.json` 的 `ignoreDependencies` 显式忽略；依赖先发版、依赖方后发版。
- 降级 = **真的换掉被渲染的组件**，且每级都能落到下一级：外部内核 → 宿主 `MarkdownText` → 消费方 `<pre>`。判定按 React 语义（`React.memo(...)` 返回 object，用 `typeof v === 'function'` 会把官方组件误判为缺失）；别自己重写三级链，直接用共享部件。
- 兜底组件自带完整契约：官方 `MarkdownText` 的 `labels` 无默认值，不传即 TypeError。
- 防复发：测试必须覆盖「缺包」本身（stub 的 `require` 对缺失包抛错、组件 stub 用真实 memo 形态），否则假降级一路绿到发版。
