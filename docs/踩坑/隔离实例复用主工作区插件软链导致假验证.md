# 隔离实例复用主工作区插件软链导致假验证

> **状态：已解决**（2026-09-12，issue #220）—— `--addons` 显式指定的插件强制重写为指向 addon 目录；实例启动前打印并校验 `realpath`，不一致即退出（fail-closed）。

## 现象（2026-09-12）

用 `node scripts/verify-real-profile.mjs --addons plugins/<插件>` 起隔离实例验证 fork/工作区里的改动时：

- 实例正常启动、健康检查 200、启动日志无 error、API 冒烟 200 —— **一切"看起来验证过了"**；
- 但实例实际加载的是**主工作区**的插件版本。手动 `rm` 隔离 profile 的 `node_modules/<插件>` 软链、重新指向 fork 后才生效。

**危害**：

- **假通过**：验证"跑过了"，但验的不是待验代码 → 未验证的修复可能被当成已验证并发布；
- **假失败**：反过来让 agent 认为"改动无效"，去改本来正确的代码（#220 发现者为此白跑数轮）。

## 根因

`scripts/verify-real-profile.mjs` 复刻生产 profile 到临时 `DSH_HOME` 时：

1. 复制 profile 目录（`filter` 跳过 node_modules）—— 该步没问题；
2. **重建 node_modules**：先把真实 profile 的 node_modules 条目**全量软链**进模拟目录（`for (const entry of readdirSync(realNode)) symlinkSync(...)`），再补 `--addons` 的软链；
3. 补 addon 的分支（旧实现）是：

   ```js
   // 生产 profile 已 link: 安装的插件（node_modules 已有同名条目，指向真实源码）
   // 直接复用，避免 EEXIST（发版校验对已安装插件跑 --addons 的常见场景）。
   const target = join(simNode, addon.split('/').pop())
   if (!existsSync(target)) symlinkSync(abs, target)
   ```

生产 profile 用 `link:` 安装本仓库插件（`~/.dsh/profiles/web/package.json` 里 `"dsh-my-memory": "link:/…/my-dsh-plugins/plugins/dsh-my-memory"`），所以同名条目**已经存在**且指向主工作区 → `existsSync` 为真 → **直接复用**，`--addons` 指向的 fork 路径被静默丢弃。

一句话：**显式声明的"待验代码"被"复用真实 profile"的优化顶替，且没有任何输出提示**——这就是它能潜伏数轮的原因。

## 修法（issue #220）

1. **显式优先**：`--addons` 指定的条目必须指向 addon 目录，覆盖真实 profile 的同名软链（`scripts/lib/verify-profile.mjs` 的 `planNodeModulesLinks` / `linkNodeModules`）；未被指定的条目照旧复用（保住 pnpm 依赖解析，未指定 addons 时行为零回归）；
2. **可见性 + fail-closed**：实例启动前打印每个 addon 的实际解析路径（`realpath`），与 addon 真实路径不一致 → 立即退出并列出 mismatch；
3. **防回归测试**：`scripts/test/verify-profile.test.mjs` 构造"软链指向错误路径"的输入，断言被修正（`replaced` 记录原目标）与检出（`checkAddonResolution().ok === false`）；
4. **比较一律用 realpath**：macOS 上 `/tmp` 是 `/private/tmp` 的软链，直接比字符串会把正确链接误判成错误、把错误链接误判成正确。

## 排查命令

```bash
# ① 隔离实例实际加载的是哪份代码（关键证据）
realpath /tmp/dsh-verify-real-3087/profiles/web/node_modules/<插件>
#   期望：待验工作区路径（如 /private/tmp/gh-fork-220/plugins/<插件>）
#   指向主工作区（/Users/<you>/IdeaProjects/my-dsh-plugins/...）→ 就是本坑

# ② 生产 profile 的 link: 安装记录（同名软链的来源）
node -e "console.log(require(process.env.HOME+'/.dsh/profiles/web/package.json').dependencies)"
ls -l ~/.dsh/profiles/web/node_modules/<插件>

# ③ 脚本自带的解析路径输出（修复后每次运行都会打印）
node scripts/verify-real-profile.mjs --addons plugins/<插件> --port 3087 --skip
```
