# 踩坑：隔离实例「静默少加载插件」（dshmarket 启停状态被一起复刻）

> issue #240。**假阴性陷阱**：验证环境自己把插件关掉了，看起来却像"插件坏了"。
> 两个 agent 都在这上面烧过大量排查时间（一度怀疑是迁移引入的 bug / 宿主 bug）。

## 症状

在隔离实例（`scripts/verify-real-profile.mjs` 复刻的 profile）里：

- 只有部分插件生效：**client bundle 不进 manifest**、**server API 404**；
- 插件本身代码没动、测试全绿、`package.json` 与 `cordis.patch.yml` 都正常；
- 重启实例、换端口、重装 addons 都无效。

**误判路径**：因为表现是"少了几个插件"，第一反应是插件注册失败 / 宿主 bug / 迁移引入的回归，
于是去读插件源码——而真正的原因在验证环境自己身上。

## 根因

dshmarket 插件（`dsh-plugin-dev-mode` 体系）把自己维护的**启停开关**写在 profile 目录里：

    <DSH_HOME>/profiles/<profile>/.dsh-market/state.json

形如：

```json
{
  "disabled": [
    "dsh-my-context",
    "dsh-task-reliability",
    "dsh-ts-example",
    "dsh-my-guardian",
    "dsh-my-observability",
    "dsh-session-title-gen"
  ],
  "groups": {},
  "groupOrder": [],
  "region": "china",
  "regionAuto": true
}
```

启动时 dshmarket 按这份名单**强制 off** 这些插件（日志 `.dsh-market/log.ndjson` 里能看到
`my-context -> off: fiber=false`）。

而 `verify-real-profile.mjs` 复刻生产 profile 时用 `cpSync` 把整个配置层一起复制 —— 包括
`.dsh-market/`。于是隔离实例**继承了生产环境的禁用名单**：生产里被手动关掉的插件，在验证环境里永远起不来。

> 本机实测（2026-09）：真实 profile 的 `state.json` 恰好禁用了 6 个插件，
> 与"隔离实例里 6 个插件加载不出来"完全对应。

## 判定步骤

```bash
# 1) 看生产 profile 的禁用名单（非空就是嫌疑）
cat ~/.dsh/profiles/<profile>/.dsh-market/state.json | head -c 300

# 2) 看隔离实例里是否被一起复制过去
ls -A /tmp/dsh-verify-*/profiles/<profile>/.dsh-market 2>/dev/null

# 3) 看启动日志里的强制关闭记录
grep -i 'fiber=false\|off:' ~/.dsh/profiles/<profile>/.dsh-market/log.ndjson | tail -20
```

**判据**：`.dsh-market/state.json` 的 `disabled` 非空 **且** 缺失的插件正好在这份名单里 → 就是这个坑，
不要再去查插件代码。

## 修法

**脚本已修（issue #240）**：`verify-real-profile.mjs` 复刻 profile 时在 `cpSync` 的 filter 里剥离
`PLUGIN_STATE_DIRS`（当前为 `.dsh-market`），**并明确打印**：

    已剥离插件自维护的启停状态：.dsh-market（否则生产的禁用名单会让隔离实例静默少加载插件）

> "必须打印"是这个修复的一半：静默正是这个坑潜伏数轮的原因。剥离本身没问题（验证环境本就该是干净的），
> 但**悄悄剥离**会让人以为"生产也是这么配置的"。

**手工等价做法**（脚本不可用时）：

```bash
rm -rf /tmp/dsh-verify-<x>/profiles/<profile>/.dsh-market
```

## 如何避免误判成插件 bug

| 现象                                | 先查什么                                                                                                                     |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 隔离实例里"少了几个插件"            | **先查 `.dsh-market/state.json` 的 disabled**，再查插件                                                                      |
| 插件 API 404 / client 不进 manifest | 先确认该插件在实例里是否被加载（日志 `fiber=false`）                                                                         |
| 改代码后行为没变化                  | 先确认隔离实例加载的是**待验代码**（见 [隔离实例复用主工作区插件软链导致假验证](隔离实例复用主工作区插件软链导致假验证.md)） |

一句话：**验证环境的"少加载"和插件的"坏掉"表现一样，但排查方向完全相反。**
