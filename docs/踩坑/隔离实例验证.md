# 隔离实例验证的假通过假失败

## 症状关键词（可 grep）

- `off: fiber=false`（`.dsh-market/log.ndjson` 里的强制关闭记录）
- 目标插件 server API `404`，client bundle 不进 HTML plugin manifest（`/plugins/??…` 里查不到 id）
- `choose folder with prompt "Select Workspace Directory"`（`osascript` 原生弹窗进程）
- `session/workspace-attach-failed`
- `已剥离插件自维护的启停状态：.dsh-market`

## 根因

复刻生产 profile 会把生产状态一起搬过去：node_modules 同名条目直接复用，`--addons` 指定的待验代码被主工作区版本顶替；`.dsh-market/state.json` 的 `disabled` 名单让目标插件被静默 off。另一类是缺前置：实例没有工作区时合成器禁用，点「选择工作区」命中宿主原生 macOS 目录对话框，浏览器自动化无法驱动 → agent 静默卡死（表现为「没进展」而非报错）。两种都不报错，排查方向却完全相反。

## 修法

- 起实例统一走 `node scripts/verify-real-profile.mjs --addons plugins/<插件> --workspace <目录>`：自动把 addon 软链重写为待验目录、剥离 dshmarket 状态、预置工作区落盘状态。
- 验前核一条命令：`realpath /tmp/dsh-verify-*/profiles/*/node_modules/<插件>` 必须指向待验工作区；指向主工作区则本次结论无效，别手工删软链绕过（绕过只救本次）。
- 判定分流：实例「少了几个插件」→ 先查 dshmarket 的 `disabled` 与 `-> off` 日志，**再**查插件代码；改代码后行为无变化 → 先做 A/B（软链指回主工作区）确认实例加载的是哪份代码。
- 派发验证 agent 的 prompt 必须写明工作区从哪来；收尾清理残留的原生弹窗进程。
