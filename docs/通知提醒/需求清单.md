## 易碎点

- **瀑布事件不可干扰**：`tools/pre-execute` 与 `approval/request` 是 waterfall 事件，监听器必须调用 `next()` 使流程继续；漏掉 `next()` 会导致工具/审批流程挂死。
- **子代理过滤**：`agent/status` 对所有 agent（含 subagent）派发，判定必须黑名单化——`session.header.origin === 'subagent'` / `header.delegationDepth > 0` / 运行时 `agent.options.subagentDepth > 0` / `header.parentSession`（派生父会话，workflow/ralph worker、fork 等有父会话但漏写前三个标记的形态）任一命中即子代理；header 缺失或结构不完整保守视为子代理，只通知明确无任何子代理标记的顶层会话。`subagentEnd: true` 后子代理完成也推送（标题带「子代理」前缀）。`subagentEnd` 过滤集中在下游 `emitNotice` 出口（issue #112），SSE 与 webhook 双通道一致，任何被识别为子代理的通知帧都无法绕过全局开关双通道轰炸。
- **SSE 长连接**：handler 不能 `response.end()`；客户端断开需监听 `close` 清理；需周期心跳防止空闲断连。
- **浏览器自动播放策略**：AudioContext 需用户首次交互后解锁（`resume`）；页面加载后可提前创建但保持 suspended，在首个 `pointerdown`/`keydown` 时恢复。
- **通知权限**：`Notification.requestPermission()` 应在用户可感知的时机（首次收到通知）发起，避免加载即弹权限弹窗。
