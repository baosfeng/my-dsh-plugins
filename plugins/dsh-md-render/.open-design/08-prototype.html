重试逻辑怎么设计？给我一份能直接跑的 TypeScript 实现。

先确认边界：重试只对幂等请求和网络错误生效，4xx 不重试；退避用 base × 2^n 并加抖动，避免同步风暴。

取消要贯穿到单次 fetch：外层 AbortController 与超时 controller 用 AbortSignal.any 合并。

实现方案

把重试、超时、取消拆成三个正交的部分，外层只负责编排。核心是 fetchWithRetry：每次尝试独立计时，失败后按退避策略等待，并在等待期间响应取消。 语义边界参考 RFC 9110 §15.5。

  • 可重试判定：网络错误、408、429、5xx；其余错误直接抛出。
  • 退避方式：指数退避 + 全抖动（Math.random()），上限 maxDelay。
  • 超时：单次尝试超时，不做整体超时，避免重试被总时长截断。
  1. 先判定请求是否幂等，非幂等只允许网络错误重试。
  2. 每次尝试用独立 AbortController 计时，超时抛 TimeoutError。
  3. 等待退避也接受取消信号，取消时立即拒绝、不再重试。
  • 补齐 408 / 429 的可重试判定
  • 重试等待期间响应取消
  • 退避加全抖动并限制上限
参数默认值上限说明
retries310最多重试次数，不含首次请求
baseDelay300ms8s退避基数，第 n 次等待 ≈ base × 2^n

容错口径：非标准分隔行（-- | --）会先规范化再解析，表格不会整块降级成纯文本。

嵌套引用降级为中性细线，不重复强调色。

可运行的实现

TS src/http/client.ts

import { fetchOnce, sleep } from './retry'

export async function fetchWithRetry(url, init = {}) {
  const { retries = 3, baseDelay = 300, maxDelay = 8000, timeout = 10000 } = options
  let attempt = 0
  while (true) {
    try {
      return await fetchOnce(url, init, timeout, signal)
    } catch (error) {
      // 只重试幂等请求与网络/超时类错误
      if (!isRetryable(error) || attempt >= retries) throw error
      const wait = Math.min(maxDelay, baseDelay * 2 ** attempt)
      await sleep(wait * Math.random(), signal)
      attempt += 1
    }
  }
}

Apple Native

macOS / iOS 原生：系统灰阶、SF 字体栈、8–10px 圆角、极细描边、克制阴影。

设计决策

  1. 层级不用「材质」表达，而用系统灰阶（layer-2 承托代码与图表），玻璃效果一律不出现。
  2. 描边降到 label 的 8–13% 透明度，接近 macOS 发丝线；阴影只保留 1px 级。
  3. 圆角收敛到 5 / 8 / 10 三档，控件 6px；标题字距 -0.015em，接近 SF Display。
  4. 引用区用中性浅底 + 22% 灰线，强调色只留给链接、语言胶囊与语法关键字。

Liquid Glass

Apple 26 液态玻璃：半透明材质 + backdrop-filter 模糊 + 高光内描边 + 柔和光晕。

设计决策

  1. 卡片材质用 62–66% 不透明度的代码底 + blur(22px) saturate(180%)，文字仍压在实色感更强的层上。
  2. 顶部 1px 内高光（label 12–18%）制造「浮起」的玻璃边，外部只有一层柔和投影。
  3. 圆角提升到 6 / 12 / 14，控件 6–7，接近 iOS 26 的连续圆角观感。
  4. 引用底改强调色 10%，比默认 14% 更低饱和，避免玻璃上出现色块。

Glassmorphism

重玻璃：大模糊、渐变底衬、明显半透明卡片层叠，视觉更张扬。

设计决策

  1. 材质 54–58% 不透明度（深色 54%）+ blur(34px) saturate(200%)，让页底渐变光斑成为构图的参与者。
  2. 阴影放大到 0 24px 60px（16%，深色 30%），卡片之间形成明显的层叠前后关系。
  3. 圆角全线上调（8 / 16 / 18），边框透明度 13–20%，玻璃轮廓更清楚。
  4. 强调色用量最高：引用底 16%、表头用 layer-1 34% 混色，视觉重心偏「展示」。

Editorial Paper

对照方向：暖白纸感、衬线标题、低饱和、强呼吸感（非 Apple 路线）。

设计决策

  1. 底色用 warn 色 4–6% 混入 layer-1，得到暖纸感而不引入任何新色值。
  2. 标题与正文切换衬线字体栈（New York / Songti SC），行距与段间距拉到 14px。
  3. 圆角压到 2 / 3 / 4，去掉阴影与模糊，靠留白与细线分区。
  4. 强调色与正文混色降低饱和度（62–70%），引用底改暖色 8%。
