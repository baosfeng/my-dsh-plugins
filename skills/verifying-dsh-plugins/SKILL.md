# 发版前功能级验证（verifying-dsh-plugins，人工自测）

启动成功 ≠ 功能可用。功能级项必须在隔离实例 + 真实浏览器 / 真实模型中由**人**走通。

> **本仓库不提供任何自动化 e2e / 真实浏览器测试脚本**（用户指令：全部由用户自己测）。
> 本 skill 只描述**人工步骤**。发版门禁 3c 不代跑验证，只校验「是否已显式声明完成人工自测」
> （未声明即阻断，绝不静默跳过；清单模板见 `verification/README.md`）。

## 何时必须做

| 场景                                                    | 要求                                                                                                                                                                            |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 发版（`node scripts/release.mjs <插件名>`，含 dry-run） | 3c 阻断未确认的发版：先按本 skill 人工自测并填清单，再 `--confirm-manual-tested` 重新发版                                                                                       |
| 修复"只在真实环境出现"的问题                            | 对照组复现 + 实验组证明修复，两者缺一不可                                                                                                                                       |
| UI / 交互 / 截图变更                                    | 真实浏览器走通 + 重新截图（release.mjs 3b 校验 README 引用的截图存在）。确无用户可见 UI 的插件按 `package.json` 的 `dsh.ui=false` + `dsh.uiReason` 显式豁免，并在发版输出中可见 |
| 插件联动 / 生命周期相关改动                             | 隔离实例（复用生产配置组合）+ 相邻插件共存验证                                                                                                                                  |

## 五个步骤（细节见 references/）

| 步骤 | 做什么                                                                                                                                                                    | 细节                                                                 |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 1    | **起隔离实例**：独立 `DSH_HOME` + 独立端口；**预置工作区**（没有工作区 = 合成器禁用，点选工作区会弹 macOS 原生对话框把 agent 卡死）；web（浏览器验证）或 headless（真实模型） | [references/isolation-instance.md](references/isolation-instance.md) |
| 2    | **真实模型 / 真实网关**：手工跑一次 headless 调用，需要时对照「无插件 / 有插件」两组                                                                                        | [references/verification-steps.md](references/verification-steps.md) |
| 3    | **浏览器验证**：用浏览器打开隔离端口，人工走通核心功能（不是"页面能打开"），需要时截图留档                                                                                  | 同上                                                                 |
| 4    | **收尾清理（强制）**：停实例 / 删隔离目录 / 复查无残留进程与原生对话框；**只动自己起的端口与目录**                                                                          | 同上                                                                 |
| 5    | **填清单 + 声明**：把结果写进 `verification/<插件>-<版本>.md`，发版时加 `--confirm-manual-tested`                                                                        | 同上                                                                 |

**三条最容易踩的**：① 绝不碰主实例（3080），验证全在隔离实例里做；② 先确认 `realpath` 指向的是待验工作区而非主工作区旧版（否则假通过/假失败）；③ 涉及 GUI 时不要把「需要人点原生对话框」的步骤留给无人值守的 agent。
