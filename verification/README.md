# 人工自测清单（模板）

> ⚠️ **何时阅读：** 发版前要人工自测时；或想知道 3c 门禁到底要什么。

真实环境 / 浏览器功能级验证**由用户本人手工完成**——仓库不保留任何自动化 e2e / 真实浏览器测试。
`scripts/release.mjs` 的 **3c 门禁**不代跑验证，只认显式确认标志：

| 情形             | 结果                                                                       |
| ---------------- | -------------------------------------------------------------------------- |
| 未自测就发版     | 被 3c 阻断（exit 1，打印清单路径 + 放行标志；**不会静默跳过**）             |
| 已自测后发版     | `node scripts/release.mjs <插件> --confirm-manual-tested [--push]`          |

## 清单模板

自测时把下面的模板复制成 `verification/<插件>-<版本>.md`（版本 = 本次发版目标版本；3c 阻断提示里会打印该路径）。
`--push` 时该文件若存在会随发版一起提交（留痕在 git）。

```markdown
# 发版前人工自测清单 — <插件>@<版本>

- 验证环境：DSH_HOME=… / 端口 … / 浏览器 …
- 待验插件处于启用态：是 / 否（带禁用位时插件被加载但不运行，页签不出现、API 404）

## 功能级验证项（逐条勾选）

- [ ] 核心功能在真实 GUI 里完整走通一次（真实数据、真实交互），不是只看页面能打开
- [ ] 易碎场景：重启实例后配置/数据回读一致；刷新浏览器后 client bundle 重载正常
- [ ] client UI：页签 / 预览器 / 设置页按预期渲染，浏览器 DevTools Console 无未捕获异常
- [ ] 插件间联动：复用生产配置组合，相邻插件共存、无注册冲突
- [ ] 真实模型 / 真实网关路径：需要真实出站请求的功能确实发出且被接受

## 未验证项与环境限制

（如实记录：无凭据、无 agent 事件、权限被拒等；没跑过的不要写成通过）
```
